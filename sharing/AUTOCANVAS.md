# 让模型自己连画布：为什么现在就能做，缺的是哪几行

这是这次分享里唯一一个**新东西**（前面那些都是在给现有实现记账）。它也是「为什么做成工作流」
最硬的答案：**工作流让 AI 生成的产物可以被机器验收。**

---

## 一句话

用户说一句「把这个视频转成笔记，顺手出一套题」，画布上自己出现一条连好的链路。
不是我们替他连，是模型连的；连完他还能改、能跑。

## 为什么这件事只有「做成工作流」才可能

1. **链路是数据，不是代码。** 模型不用会写程序，只要会填一张表：放哪些节点、谁连谁。
2. **更关键：这些节点的「料」是有类型的**（音轨 / 文稿 / 笔记块 / 文档）。
   所以模型连错了，**机器当场就能指出是哪条边错了**。这是「能自动重试」的前提——
   不然每个图都得跑一次才知道对不对，那个成本高得没法用。
3. 反过来看：如果产品是「贴链接、选模板、出摘要」，它里面根本没有「图」这个东西，
   模型无处下手，用户想要的加工顺序只能等我们排期。

## 实测：要让模型能连，图得满足 10 条约束，现在 8 条有人守

十条约束是从代码里列出来的（每条都对应一个真实存在或缺失的校验），不是猜的。

| 约束 | 违反的样子 | 谁在守 |
| --- | --- | --- |
| 字段取值合法 | 章节粒度写成 `"huge"` | 图校验 ✅ |
| 必填字段齐全 | 章节节点没填粒度 | 图校验 ✅ |
| 字段类型正确 | 章节上限写成字符串 `"20"` | 图校验 ✅ |
| 节点 id 不重复 | 两张卡同一个 id | 图校验 ✅ |
| 连线 id 不重复 | 两条线同一个 id | 图校验 ✅ |
| 连线不悬空 | 连到一个不存在的节点 | 图校验 ✅ |
| 端口必须存在 | 连到一个不存在的口 | 图校验 ✅ |
| 不能自连 | 节点连自己 | 图校验 ✅ |
| **端口类型要兼容** | 把「文稿」接到「笔记块」的口 | **只在鼠标上** ⚠️ |
| **不能成环** | 两个节点互相连 | **没人守** ❌ |

**8 / 10 已经有人守**，这是好消息：地基够硬，缺的是两条，不是重做。

### 第 9 条：只在鼠标上守

判断「这两条线能不能连」的那段代码（`canConnectSpecs`）全仓库**只有一个调用点**，
挂在画布的拖拽事件上（`FlowCanvas.vue:299`）。而契约包里那个本该做数据层判断的
`isValidConnection`（`graph.ts:379`）——**导出了，但从来没有任何地方调用它**。

所以：**你用手拖，它拦你；图从别的地方来（模型、文件、同步），没人拦。**

### 第 10 条：没人守，而且后果很重

我按真实节点类型搭了一张带环的图（文本 → 文本工具 → 素材挑选 → 接回文本工具）。
**三条边的类型全是合法的**，所以图校验一路放行：这张图能存进工程、能点运行。

然后运行会**空转不结束**。引擎算出来的执行顺序是「文本 → 素材挑选 → 文本工具」；
源节点跑完之后，剩下两个互为上游、都判为「还没就绪」，又谁都不算失败，
所以跳过逻辑也不会收它们。运行循环等不到可跑的节点，就一直在那儿转。

更糟的是：**一个工程只允许有一个运行在跑**。这次运行不结束，这个工程就再也发不起新运行了。

（这一条是按代码路径推的，我没有真跑引擎——见诚实清单。
顺便：你们现场手册里「不要演示把节点连成环」那条，现在知道原因了。）

## 补起来有多小

两处都补在**同一个地方**：图校验（`graphSchema`）。它是所有图唯一的必经之路——
**新建工程、保存工程、导入工程、发起运行，四条路都走它**（`projects.ts:175`、
`projects.ts:230`、`projects.ts:174`、`runs.ts:84`）。

所以**不需要为「模型生成」单开一条通道**：补好这一个关卡，所有来路的图一起被管住。

- **端口类型兼容**：那个校验函数里已经在解析两端端口了，自连判断就在旁边——
  加一行 `canConnectSpecs` 的事。
- **环检测**：一个三色 DFS，十来行（`tools/graph-guards.ts` 里那份可以直接用）。

补完之后，「模型连错了」就有了机器给的判词，而且**能指到具体哪条边、为什么不行**。
所以可以让模型带着这句判词重连一次——**这是「能自动重试」和「只能碰运气」的分界线。**

## 生成那一步大概长什么样

- 给模型两样东西：一句人话需求 + **端口目录**（16 种节点的名字、输入口、输出口、
  各自的「料」类型）。第三样现成的：**9 条内置链路，正好当示例**。
- 让模型只输出「放哪些节点、谁连谁」。**节点 id 别让它生成**，客户端按顺序补——
  这样「id 重复」和「悬空边」两类错直接消失。
- 输出先过图校验。不合法就带着判词回问一次（图校验的报错本来就是人话，
  比如「连线 e2 端口不存在」）。
- 合法了才落到画布上，用户接着改。

## 明天怎么讲

> 做成画布之后，这件事才可能：你跟我说一句话，我把链路连出来。
> 因为节点之间能不能连是有类型的，连错了机器当场知道——**AI 连出来的图是可以验的，
> 不是只能碰运气**。

**但现状要先说清**：现在缺两道校验，其中「成环」会让运行卡死。想真做，先补这两处。

这一条主动讲比被问出来强，而且它正好回答了「做成工作流到底换来什么」：
**换来的不是界面，是 AI 的产物可被机器验收。**

## 诚实清单

- **没跑过模型。** 那 10 条约束是我从代码里列的（每条对应一个真实校验或它的缺失），
  **不是从模型输出统计出来的**。所以「模型最容易犯哪一类错」我没有证据——
  我只知道哪一类现在没人拦。
- **成环的后果是按代码路径推的，没有真跑引擎。** 我读的是 `engine.ts:606-618` 的排序
  （只有 `visited`、没有「在栈上」标记的 DFS）和 `isReadyToRun` 的判定，结论是空转。
  **要坐实得真起一个带环的工程跑一次**，我没做。这一条在文档里是结论、在证据上是推断。
- 「加一行」「十来行」是读代码估的，**没实现**。
- **用户要不要这个功能，我没做调研。** 被质询时照 [DRILL.md](./DRILL.md) 答。
- 「四条路都走图校验」我是用调用点核的（`parseGraph` 的全部调用点）。**如果将来有新的写入
  入口不走它，这个「单一关卡」的说法就不成立了**——所以补之前值得再核一次。
- 实验脚本在 [tools/graph-guards.ts](./tools/graph-guards.ts)，自带前置断言
  （26 张内置链路必须全部合法、类型兼容、无环），跑法见 [README.md](./README.md)。
