# 现场手册（小会议室版）

一年一次，8-10 个前端同事，25 分钟，投影 + 一台开着 `pnpm dev` 的笔记本。
台下三个人在看手机，两个人真心想学，一个准备挑刺。

**只有三件事决定你讲不完：有没有画面、有没有一个记得住的数字、有没有一件他们明天能用的东西。**

配套：逐页脚本在 [SPEECH.md](./SPEECH.md)；被追问时的备料在 [QA.md](./QA.md) 与 [MODULES.md](./MODULES.md)（后面这两份**别投出来，自己看**）。
演示不需要道具：打开任意一个「有节点、有连线」的工程就够。

---

## 开场（60 秒）

动作：打开一个工程 → 画布上拖两个节点 → 连线 → 点运行 → 出结果。

说：

> 先花几分钟说清它是什么、跟现成的有什么不一样。
> 然后讲两类事——用户在界面上**跑的时候**、**读的时候**，分别会碰到什么。
> 这两类事，你们做任何"一屏放不下、又一直在变"的界面都可能碰到。

---

## 开场那 30 秒：先说清"我为什么做这个"（别省）

不介绍产品功能，但要**先把"这东西存在的理由"讲出来**，否则后面讲得再细，也会有人在心里问"这玩意儿干嘛的"。

> 我做它是因为一件很具体的事：我攒了几百个技术视频，看不完，但丢不掉。
> 市面上的工具我都试过，它们是"贴个链接、选个模板、出一份摘要"，模板是它给的，你改不了。
> 我想要的是把中间每一步都摊开：转写用什么、校对要不要、提炼用哪套提示词、要不要出思维导图，我自己连。
> 所以它是一张画布，不是一个网页应用。

这两句同时办掉了两件事：说明动机，顺便把"这跟已有的有什么不一样"提前答了一半。
展开版在下面「三个必答题」第一条。

## 第一段：它是什么，跟现成的差在哪（5 分钟，项目介绍）

准备：打开一个用内置模板建好、跑完过的工程。

主线一句话：**可编排的画布 × 音视频素材 × 产物是能带走的 Markdown——这个位置是空的。**

五页照 PPT 讲（P3 / P4 / P5 / P6 / P7）：

- **P3 一张画布，三个界面** — 项目介绍的正页。四条一句话带过：画布上放什么（B 站链接 / 本地音视频 / 已有文稿）、
  中间接什么（16 种节点）、不用从零连（9 条内置链路）、跑完看什么（结果页那几个标签）。
  **不要念数字清单**，停在底纹带那句上。
- **P4 它站在两类现成产品中间** — 本段最重要的一页。左边一类是 AI 音视频转笔记
  （BibiGPT / 通义听悟 / 飞书妙记 / Ai好记），右边一类是工作流编排（n8n / Dify / 扣子 / Flowise），我们在中间。
  收尾念底纹带：差别不在功能清单上，在**形态**（固定管线 vs 你自己连）与**数据**（别人的账号 vs 你自己的库）。
- **P5 这一类的技术底座** — **这是"资历信号"页，不是技术细节页，40 秒讲完**。四块各一句：
  前端与构建（Vue 3 组合式 + TS 5.9 + Vite 7）、画布与布局（Vue Flow 1.48 + ELK 0.12 进 Worker）、
  组件与渲染（Element Plus 配无样式原语、一份设计令牌、marked + DOMPurify、SSE）、
  服务端与数据（Hono 4 + Drizzle + SQLite，Zod 校验三包共用）。底纹带那句要念：
  没有一处是十年前那套写法。**不要展开任何一项**——"为什么用 Hono""为什么不上 WebSocket"留到问答；
  **也不要主动提 Tailwind**（装了零使用，在待移除清单里）。
- **P6 这些别人也做了，老实说** — **主动承认，这页决定后面所有问答的姿态**。三行承认
  （转写+摘要+章节+思维导图、导出与批量处理、条件分支/失败重试/定时触发），最后一行给真正站得住的三条。
- **P7 八个视频进同一条链路，我只要其中三段** — 段一里最像"设计"的一页，也是"可编排"最实用的一处：
  段身份只用素材自身的信息（`bvid:分P` / `file:id` / `node:来源`）、**不掺数组下标**；
  没配 = 全选、空数组 = 全排除（运行前会被拒绝）；下游要能说清"用了 8 段里的哪 3 段"。

**这一段不要讲**：`16 种节点只注册 1 个 nodeType`、`markRaw`、外壳 3028 行、正文分派几段——
这些是"我们的架构取舍"，屋里没有人在写同类产品，**无人在意**（被问到可以答，细节在 [MODULES.md](./MODULES.md)）。
如果被问「跟 BibiGPT 比谁强」，不要比功能清单，比形态与数据在哪——「已经有人做了的」那张表就写在投影上，不用遮。

## 第二段：跑的时候（7 分钟）

有演示。主线一句话：**推送是唯一会静默失效的通道，所以状态得自己会收口。**

四页照 PPT 讲（P8 / P9 / P10 / P11）：

- **P8 过场** — 用实测数字开场：**最长的一次跑 39 分钟**（8 个视频那条链路：转写 23.6 分钟、AI 校对 9.3 分钟、下载 2.4 分钟）。
  本机 114 次运行里有 **6 次**超过 10 分钟——这个数可以当场查库（`apps/server/data/scribe-flow.sqlite` 的 `runs.elapsed_ms`）。
  断线、切页面、刷新、服务重启都是常规情况，不是异常。
- **P9 进度动到一半就不动了——刷新回来还算数吗**（本段最有分量）— ① 用户看到的：进度停在某个节点不动，
  或者刷新之后整屏回到"什么都没跑过"；② 为什么会停：推送静默失效——断线、丢帧、服务重启它都不报错，
  只是不说话了；③ 怎么不撒谎：推送只当加速、状态以列表与详情为准，断线 2 秒重连 + 全局 5 秒对账；
  ④ 刷新回来怎么算：三条路径走同一套规则，规则是 3 个纯函数（45 行，带单测）。
  底纹带三条纪律要念：不覆盖当前结果、只认画布上还在的节点、**失败的运行里已完成的那几个照样算数**。
- **P10 被记成「你取消了」** — 两张卡片对照「已取消（人自己停的，不该再提醒）」与
  「已中断（服务掐断的，要提醒、还要让人看出不是自己停的）」。**真实案例要念**：
  `run_3b007bff` 里 4 个节点有 2 个已完成（2925 / 6558 字），2 个停在中途。
  收在底纹带：运行记录只写「名称 + 时间」——一列「成功 / 成功 / 已中断」里，成功每行重复等于没说。
- **P11 换一条运行，内容先消失再出现** — **全场最硬的一组数字，念出来**：533 次采样里阅读区消失 0 次、
  加载占位出现 0 次；请求只占 9 毫秒，其余全是渲染（所以"加个 loading"是错的解法）；
  解法是保留旧内容 + 压暗 + 忙碌提示延迟 180 毫秒。底纹带补同一个范式的复用：设置弹窗原来要等
  Obsidian 目录扫描 280–840 毫秒，而设置本身只要 4–22 毫秒。

## 第三段：读的时候（7 分钟）

有演示（切分段、切换运行不闪、粘分享文案建工程）。

主线一句话：**引擎给一份拼接产物，人却要按视频逐段读；AI 的产物坏了也得有降级。**

五页照 PPT 讲（P12 / P13 / P14 / P15 / P16）：

- **P12 过场** — 一张卡挂 8 个视频，读完要一段一段来。
- **P13 八个视频，读的时候得一段一段自己找** — ① 用户看到的：几万字里混着 8 个视频的内容，只能靠滚轮找；
  ② 分段哪来的：不是后端存的，是拿运行时记录的「每个输入一行」**反推**的，所以历史运行不用重跑也能切开读；
  ③ 标题怎么来的：沿链路向上游回溯最多 12 层取视频名；④ 导航形态：右侧常驻大纲 + `‹ 3/8 ›` +
  `↑↓ / jk / Home / End` 键盘，段数 > 12 才出现筛选框。底纹带点明"形态是查规范选的"（HIG 上限 5、M3 的 tab 语义）。
- **P14 我们曾经把练习题渲染成一张空表格** — ① 用户看到的：点开"练一练"是一张空的溯源表格，
  产品里其实有题，是渲染认错了类型；② 根因：按内容特征嗅探类型，没写互斥规则；
  ③ 现在怎么防：先排除练习题再判溯源；坏条目逐条丢弃但每条给原因；
  ④ 安全底线：Markdown 进 DOM 前统一过 DOMPurify（35 行单入口，四处共用）。
- **P15 想在输入框里选一段字，结果把节点拖跑了** — 两张卡片对照「画布要能拖」与「表单要能填」；
  解法一句话：拖拽句柄收敛到卡片头部一处、表单区域标 `nodrag`、卡片内滚轮不穿透。
  底纹带顺带一条：一按运行整张卡片就变灰锁住，用的是 getter 不是快照，所以不用刷新。
  **做过编辑器的人会在这里点头**——这是全场最容易产生"我也遇到过"的一页。
- **P16 粘过来的是 App 分享文案，不是链接** — 短，但**现场演示效果最好**：粘一段真实分享文案，
  看它直接抠出链接与标题。注意短链（`b23.tv`）也要认。

**这一段最容易被打断**：P12 讲大纲时、P14 讲拖拽时，都可能有人插话"我们也遇到过"。停一下让他说完——
那是这一段最好的效果。

## 一条必须知道的边界：素材挑选接在转写后面会静默失效（实测）

**现象**：把「选段加工」模板建出来的工程跑一遍，挑选节点上写着 **「放行 8/8 段」**，
八个视频全下载、全转写、全加工——而界面上完全看不出来。

**为什么**：引擎按**直接上游节点 id** 查挑选表（`engine.ts` 的 `passesPick`），
而前端写进去的键是**来源卡**的 id；中间隔了转写这一层，查表落空 →
`passesPick` 直接返回"全放行"。这条在 `docs/research/project-audit-2026-09-27.md` 的 A1 里写着，
当时的判断是「纯粹烧钱、烧时间的静默失效」，现在**实测复现了**。

**还有一层**：`source.bili` 的输出端口是 `audio`，而挑选节点的输入只收 `transcript / noteBlock / noteDoc`——
所以对**B 站来源**来说，挑选**根本没法"直连来源"**（只有 `source.text` 是 transcript 输出）。
也就是说"八个视频只要其中三段"这个能力，**目前对视频来源是不成立的**。

**现场怎么办（二选一，别含糊）**：

1. **不在台上演示它**，P7 那页照讲设计意图，被问到就照实说"这条现在对视频来源不成立，是已知缺陷"；
2. 或者先修再讲——审计里已经写了修法（把键统一到"身份链最上游来源"，并补一条"隔一个模块"的回归用例）。
   这是个不小的改动，**当天来不及就别硬上**。

**绝对不能干的事**：现场点开挑选、说"我只放行了三段"，然后跑起来。
八个视频全都会跑，数字一对就露。

## 收尾（60 秒）

三句话，让他们能带走（对应 P17）：

1. 「别人也有」不可怕——接不上的位置才是你的位置。
2. 用户说「卡住了 / 闪一下 / 没反应」，先别查网络：这三句里至少有两句是渲染与状态的问题。

> 这些决定后面都有一个"当时只能这样"。你们看到的问题我都知道，只是没排到。

## 三个必答题（被问到就照这个说）

### 一、这是个什么项目？市面上算什么类型的产品？

一句话：

> 它是个**把视频和文稿加工成笔记的节点式工作台**。你在画布上把「转写 → 校对 → 提炼」连起来，
> 点运行，出一份 Markdown 笔记。

对标的话，它站在两类产品的中间：

- **一类是 AI 音视频转笔记**：BibiGPT、通义听悟、飞书妙记、Ai好记。形态是「贴链接 → 选模板 → 出摘要」，管线固定。
- **一类是工作流编排**：n8n、Dify、扣子、Flowise。有画布，但做的是自动化与 AI 应用，不是笔记。
- 我在的是**这两类的交集**：可编排的画布 × 音视频素材 × 产物是能带走的 Markdown。

要主动承认的部分（不承认会被戳）：

> 单点功能我都能找到对应——转写、摘要、章节、思维导图、导出 Obsidian，别人都有，有些比我成熟。
> 差别在两个地方：**形态**（固定管线 vs 你自己连）和**数据在哪**（SaaS 订阅 vs 自托管、用你自己的密钥、落到你自己的笔记库）。

### 二、开发时遇到哪些困难，怎么解决的？

挑这三条讲，每条都是「现象 → 怎么定位 → 怎么解 → 数字」。**数字要念出来。**

**1. 长任务的状态会静默过期**

- 现象：一次运行跑十几分钟，用户中途会断网、切页面、刷新、重启服务。
- 怎么定位：SSE 断线、丢帧、重启**都不报错**，只是不说话了——这是最容易被"看起来正常"骗过去的一类问题。
- 怎么解：推送只当加速通道，状态以列表与详情为准。三条恢复路径走同一套规则，规则抽成 3 个纯函数
  （45 行，带单测）；全局 5 秒对账一次；局部重跑按时间倒序回填，**失败的运行里已完成的节点照样算数**。
- 数字：断线 **2 秒**重连、**5 秒**对账、最多往回翻 **200 条**运行。

**2. AI 的产物一定会坏，而坏法你猜不到**

- 现象：模型返回的 JSON 会截断、格式会漂移、引文可能是编的。我们遇到的最难看的一次是
  **把练习题渲染成了一张空的溯源表格**——产品里明明有题。
- 怎么定位：问题不在数据，在展示层按内容特征**嗅探类型**时没写互斥规则，练习题被当成溯源报告渲染了。
- 怎么解：嗅探规则要写互斥（先排除练习题、再判溯源）；坏条目逐条丢弃，但**每一条都要给出人话原因**，
  丢弃率本身当质量指标看；Markdown 进 DOM 前统一过一遍 DOMPurify（35 行单入口，四处共用）。
- 一条边界要主动说：生成期严格校验、展示期只做结构解析——同一份数据不被两套标准各否一次。
- 数字：消毒入口 **35 行**；展示层的结构解析只有 **26 行**，与生成期的校验分开。

**3. 八份素材拼成一份，读的时候又要切开**（这条最能体现设计）

- 现象：一张卡挂 8 个视频，8 份产物在引擎里被拼成一份，但阅读时要按视频逐段读。
- 怎么解：拿运行时记录的「每个输入一行」**反推**分段，所以历史运行不用重跑也能切开读；
  分段标题沿链路向上游回溯最多 **12 层**去取原始视频的名字。
- 数字：回溯上限 **12 层**；结果页大纲的筛选框在段数 **> 12** 时才出现。

### 三、这套框架是照搬别人的，还是怎么来的？

分三层说，别含糊：

1. **底层库是成熟方案，不是自研**：画布用 Vue Flow（MIT），组件库用 Element Plus。
   画布交互**照搬 n8n 的行为**——这是我自己定的硬规则：只复刻行为，不复制代码。
2. **编排能力是对着做的，不是凭空想的**：我读过 n8n、Dify、Flowise、扣子、Zapier、Airflow、Prefect、
   ComfyUI 等 20 个产品的文档，做了一张 14 维功能矩阵和差距分析，排出 4 个必补能力
   （条件分支、失败重试、文本工具、章节切分），然后一次性补齐——**这几个节点在代码里都能找到**。
   所以"为什么有这几个节点"是有出处的。
3. **真正自己设计的是「音视频 → 笔记」这段的语义**：批量素材的段身份、素材挑选（只放行其中几段）、
   按页/按段阅读、练一练（把文稿变成题 + 本地判分）。这些在调研里我没找到直接对应物。

如果被追问「那不就是拼装吗」：

> 拼装也是设计。难的是**组合起来之后的语义**——八段素材进一条链路、只放行三段、下游还能说清用了哪三段。
> 这一段没有现成框架能抄。

如果被问「为什么不用 n8n / Dify 自己搭一个」：

> 能搭，编排那一层它们比我的成熟。但音视频这一段得自己写——它不是"接一个 HTTP 节点"，
> 是一层平台能力：

- **B 站登录**：不是填个 token 就完事。要扫码登录 + 轮询状态、cookie 存在服务端、处理登录失效；
  还要能把收藏夹 / 合集 / 稍后再看 / 历史列出来给人挑，分 P 与选集得对得上号。
- **下载**：要带 Referer 与 UA，走 DASH 拣音轨（取码率最高那条）；下下来的东西要进媒体库，
  而不是散在磁盘上。
- **转码**：FFmpeg 提音轨、转成 ASR 要的格式；Windows 下还得绕开管道死锁这类平台坑。
- **ASR**：两套协议（自建 / OpenAI 兼容）、超时要能中断在途请求、逐段跑、失败重试，
  而且转写结果要回写到「每段一行」的输入记录里——**按段阅读就靠它**。
- **媒体库**：同一个视频不重复落盘、播放走 Range 流式（拖进度条能直接跳）、文件丢了能按引用重下。
- **按段阅读**：引擎把多段产物拼成一份，前端要能从运行时记录反推出"这一段是哪个视频"，
  而且**历史运行不用重跑也能切开读**。

> 所以我不是在别人的平台上接了十几个节点，是把这一段做成了开箱可用：
> 打开就是一个能扫码、能下载、能转写、能挑段、能按视频读的闭环。

补一句诚实的（被追问"那编排是不是抄的"时用）：**编排那一层我确实是对着它们的功能矩阵学的**——
条件分支、失败重试、文本工具、章节切分这四个能力就是那么排出来的，代码里都能查到。

## 被问"这跟 BibiGPT / 通义听悟 / 飞书妙记 有什么不一样"怎么答

先记住自己调研的结论（`docs/research/r1-desktop-research.md` 里写的）：
**差异化落在「画布可编排 + 逐节点产物可见 + 工程可保存复用」，不跟它们拼平台覆盖。**

30 秒版：

> 它们做的是固定流水线，你用它给的模板；我这里每一步都能换、能拆、能只重跑一段。
> 具体到最实用的一点：八个视频可以进同一条链路，但我能只放行其中三段继续往下加工。
> 还有一点是数据在哪：它用自己的账号、自己的密钥，产物直接落到自己的 Obsidian 里。

**别装成"这些都是我发明的"，会被当场戳穿。** 该承认的直接承认：

| 已经有人做了的 | 老实说 |
| --- | --- |
| 视频转写 + 摘要 + 章节 + 思维导图 | 对，BibiGPT、通义听悟、飞书妙记都有，而且比我成熟 |
| 导出 Markdown / Obsidian | 有，BibiGPT 支持 Notion/Obsidian/flomo |
| 多视频批量处理 | 有，BibiGPT 支持批量链接和合集归纳 |
| 条件分支、失败重试、文本工具、定时触发 | 这些是工作流产品的默认能力，n8n/Dify/Airflow 全都有 |

**真正站得住的差别，就三条**（说这三条就够）：

1. **可编排**：n8n/Dify 有画布但不是做笔记和视频的；视频笔记工具是固定管线。**两者接起来的这个位置是空的。**
2. **多素材在编排里保持身份**：八个视频走同一条链路，能只放行其中几段继续，且下游能解释"这次用了 8 段里的 3 段"。别的工具要么每个视频单独跑一遍，要么全并成一份。
3. **逐节点产物 + 历史运行可重新分段**：段是从运行时记录反推出来的，所以**旧运行不用重跑也能按视频切开读**。

## 还能从项目里挖的素材

下面这些没进投影，被问到、或者时间有富余时可以补：

- **运行中的画布是只读的**，而且判据用 getter 而不是快照——效果是运行一开始界面立刻变灰，不用刷新。讲出来 10 秒，大家会觉得巧。
- **撤销是整图快照**（不记命令），上限 50 步；两个副作用谁都躲不掉：逐字输入算不算一步、视角要不要进历史（我们进了，所以 Ctrl+Z 会把镜头一起弹回去）。顺带承认文本工具那处逐字直连提交做错了。
- **一键整理用 ELK 而不是 Dagre**：n8n 的 Tidy Up 与 Dify 的「整理节点」都用 Dagre，我们为了把排布搬进 Web Worker 付了 1,595,334 B（gzip 466,809 B）的懒加载体积；Dagre 小一个量级，我们没做 spike——被问"为什么不用 Dagre"就照这个答。
- **字符级 Diff 视图**（`components/DiffViewer.vue`，278 行）：先按行配对出"删/增"的 replace 行，再只高亮真正变化的字符。用的是 `diff-match-patch-es`，**不用 jsdiff 是因为它是 BSD-3，撞了本仓"只复用 MIT / Apache-2.0"的许可证红线**。
- **弹出的模态守卫要同时兼容两套组件库**（`lib/dropdown-modal.ts`，67 行）：不渲染遮罩，给 `<html>` 加类 + `pointer-events: none`，选择器同时覆盖 Element Plus 的 `.el-*-popper` 与 Reka UI 的 `[data-reka-*]`；还得用 `:not(.sf-node-result-preview)` 把悬停预览排除掉，否则画布上没法把鼠标移到下一个节点。
- **视频在页内播放走的是 Range 206 流式**（GB 级文件不进内存），文件丢了还能按引用重下；播放器是自研的 742 行（原生 video + 自研控件层、Pointer Capture 拖拽、缓冲条双轨、全屏控件 2600ms 自动隐藏）。有人问播放器就讲这个，能撑 3 分钟。
- **B 站选集拆成了"点行切换"和"勾选合并"两条轨道**。如果有人问多选怎么做，这是现成的答案。
- **空画布的覆盖有两道保险**：前端在"上次有节点、这次要存零个"时弹二次确认；服务端覆盖前留档 20 份，**而且不拒绝空画布**——理由是它判断不了那是用户真想清空还是界面出了毛病。这是"真发生过的事"，比讲条款有说服力。
- **自动保存有两个时序坑**：保存时把 `projectId` 存进闭包（否则切换工程途中定时器触发会写错工程）、切走前先 `flushPendingSave` 把防抖窗口里的改动补写掉。
- **运行结束提醒的两条细节**：判定抽成纯函数并有 4 条用例；提示音用 WebAudio 现场合成、不引入音频文件；通知按 runId 去重。
- **数据账本**：设置页按分区给出文件数与体积、按工程占用排行、五类可回收空间逐项清理。改前页面在 2.2 GB 里只展示了 383 KB。

**已经进投影的，别再当备用素材**：段标识不掺下标 → P6（讲得比这里细）；拖拽句柄与表单 → P14；粘贴分享文案 → P15；分段从运行时记录反推 → P12。
