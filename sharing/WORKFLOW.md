# 为什么做成工作流：加一个节点，值多少、付多少

这份备料回答一个问题：**「以后还要加节点」这个前提，到底证明了当初做成工作流是对的，还是暴露了它的代价。**

结论是两边都成立，而且都能用数字量出来——所以它比「我们喜欢画布」这种说法抗打。

所有数字标了来源：**实测**（跑了命令/脚本）、**结构量**（从代码里数出来的，会随改动漂）、
**精确计算**（纯数学，可校验）。数字怎么来的写在每节末尾，脚本在 [tools/node-economics.ts](./tools/node-economics.ts)。

---

## 一、结论三句（可以直接念）

1. **工作流把「加一种能力」和「运行时」解耦了。** 加一个节点，跑起来那一整套——调度、推送、
   断线恢复、撤销、结果存储、按段阅读——**一行都不用改**；它只要声明端口，就自动获得了
   插进任意已有链路的能力。实测：新增「知识巩固」那次，引擎的 14 个改动块**没有一块**落在调度上。
2. **代价和收益在同一个地方**：一张卡片要动 **23–26 个文件、1500–3100 行**，还要在
   **73 行手写枚举**里各补一笔，其中**没有守护的那几处漏了不报错**。但**这个贵是应该的**——
   它之所以贵，是因为它真的换掉了料的形状（音频变稿子、一份变好几章、稿子变一套题）。
3. **判据只有一条：料变不变。** 料不变、只是换个处理方式 → 走提示词块，1 个源码文件；
   料的样子变了、或者得出门拿/写东西 → **必须加卡片，没有别的办法**。
   **提示词改不了料的形状**——所以一个只会加提示词的产品，跟「贴链接、选模板、出摘要」
   没有本质区别：输入输出被定死，画布就成了装饰。
   **加卡片不是成本项，它是这个产品唯一真正长个子的方式。**
   要认的一条：8 张卡涨到 16 张只用了 15 天，**之后 18 天一张卡没加——也就是这 18 天
   产品的「料」没变过**，变的是看法和说法。这一条现场主动讲，比被问出来强。

## 二、值的那一半：十六次「料的变形」

**先说这张表**，它是「我们不是只会加提示词」的直接证据。一个节点的价值不看它多聪明，
看它有没有**换掉料的形状**；只换处理方式的，那本来就不该占一张卡。

| 节点 | 料怎么变 | 变形 / 只是做法 |
| --- | --- | --- |
| B站链接 / 本地文件 | 链接、文件 → 能转写的音轨（还要**出门下载**） | 变形 + 出门 |
| 文本 | 一段文字 → 一篇文稿 | 变形（来源） |
| 转写 | **音轨 → 文稿** | 变形 |
| 章节切分 | **一篇 → 好几章** | 变形 |
| 思维导图 | **文稿 → 一张导图** | 变形 |
| 知识巩固 | **文稿 → 一套题** | 变形 |
| AI 加工 | 文稿 → 笔记块 | 变形 |
| 合并 | 一堆笔记块 → 一份文档 | 变形 |
| 输出 | 文档 → 硬盘上的一个文件 | 变形（落盘） |
| Obsidian 笔记 | 文档 → 写进自己的笔记库（**出门写**） | 变形 + 出门 |
| 素材挑选 | 八段 → 只放行三段 | 变形（分流） |
| 条件分支 | 一份 → 分成两条路 | 变形（分流） |
| AI 校对 | 文稿 → 文稿，只是更干净 | **只是做法** |
| 文本工具 | 文稿 → 文稿，纯本地处理 | **只是做法** |
| 阴阳师攻略加工 | 文稿 → 笔记块，和「AI 加工」同形 | **只是做法（走错了）** |

**13 / 16 在改料的形状**，只有 3 个不变——而这 3 个里，
[你们自己的调研](../docs/research/node-vs-prompt-block-boundary.md)已经写明
「阴阳师攻略加工……**这是唯一放错的一个**」，它本该是「AI 加工」下拉里的一种做法。

**这就是「固定管线」和「画布」的分界**：固定管线的产品，这些变形只能由它自己排期，
一次给你一种；画布把这些变形做成积木，用户可以按自己的顺序拼——甚至拼出我们没预设的链路。
**所以「加节点」不是成本项，是这个产品唯一真正长个子的方式。**

### 2.1 运行时零改动（实测）

新增「知识巩固」节点那次提交：**26 个文件、3137 行新增**。其中 `engine.ts` 有 14 个改动块，
改的**全是「往手写枚举里补一笔」**，没有一处动机制：

| 改的是什么 | 性质 |
| --- | --- |
| `RETRYABLE_NODE_TYPES` 加一个成员 | 手写枚举 |
| `isRetryableError` 的文案黑名单加三个词 | 手写枚举 |
| 「一个输入一份结果」的判定链加一个 `\|\|` | 手写枚举 |
| 产物类型的判定加一个 `\|\|` | 手写枚举 |
| 卡片预览的排除名单加一个 `\|\|` | 手写枚举 |
| `runNode` 的 switch 合并进已有分支 | 手写枚举 |
| `runs.ts` 的 AI 密钥预检加一个 `\|\|` | 手写枚举 |

**核验**：`git show f6ac5d4 -- apps/server/src/lib/engine.ts | grep -E "^[+-].*(runLoop|拓扑|emit|broadcast|并发)"` 输出为空。

这条就是工作流范式的核心收益：**扩展点是声明，不是管线**。端口、执行分支、数据校验各自声明一次，
调度与推送不用知道多了一个谁。

### 2.2 「插在哪都行」是算得出来的，而且由端口声明决定（精确计算）

连线合不合法只看端口类型（4 种端口 + 一条单向偏序）：16×16 = **256 个有序对里合法 108 个（42.2%）**。
所以一个新节点「能待在哪些地方」，**开工前就能算出来**，不用等它写完再试。

口径：把 9 条内置链路按来源展开 = **26 张展开图**（「选段加工」只支持音视频，所以不是 27），
再按住它的每一段空隙数 = **116 个位置**（按「前驱 → 后继」去重，分支模板的共享前缀只算一次）。
两个口径的差别很重要：

- **① 能挂上去**：前驱的输出 → 新节点的输入可连。这是「拖一张卡过来、从某个节点拉一条线」。
- **② 能塞进去**：还要新节点的输出 → 原来那个后继的输入也认。这是「插进已有两段之间、不拆下游」。

| 节点 | ① 能挂上 | ② 能塞进去 | 覆盖链路 |
| --- | --- | --- | --- |
| 条件分支 / 素材挑选 / 文本工具 | 95 / 116（82%） | **95 / 116（82%）** | 9 / 9 |
| **知识巩固** | 95 / 116（82%） | **43 / 116（37%）** | 9 / 9 |
| 思维导图 | 95 / 116（82%） | 37 / 116（32%） | 9 / 9 |
| AI 校对 | 57 / 116（49%） | 57 / 116（49%） | 9 / 9 |
| AI 加工 / 章节切分 / 阴阳师攻略加工 | 57 / 116（49%） | **5 / 116（4%）** | 9 / 9 |
| 合并 | 31 / 116（27%） | 23 / 116（20%） | 8 / 9 |
| 转写 | 18 / 116（16%） | 0 | 9 / 9 |
| 输出 / Obsidian | 40 / 34 | 0（终点不能插中间） | — |
| 三种来源 | 0 | 0 | 0 / 9 |

**这张表里最值得讲的是 ① 和 ② 的差**：

- 声明了**多类型端口**的节点（条件分支、素材挑选、文本工具、知识巩固的输入侧），
  ① 一律 82%——它挂哪都行，因为输入口接受文稿/笔记块/文档三种。
- 而**单类型端口、产物又不是笔记块**的（AI 加工 / 章节切分 / 阴阳师攻略），
  ① 有 49% 但 ② 只剩 **4%**：在已经连好的链路上，它几乎没有「不动下游就能塞进去」的位置，
  因为它的产物是笔记块，而原来那个后继要的是文稿。

所以结论不是「节点越多组合越多」，而是：**一个节点的可组合性，在它声明端口那一刻就定下来了。**
想让它真的能插进别人的链路，就把输入口的 `accepts` 放开、把产物类型选成下游最常要的那种。
（最后一行的来源与终点类算出 0，是自检：来源没有输入口、终点没有输出口，本来就不该插在中间。）

**核验**：`node .../tsx .../cli.mjs sharing/tools/node-economics.ts`，第二段。
脚本里有前置断言：内置链路里每一段连线都必须符合端口规则，不符合直接抛错。

### 2.3 内置链路是数据，不是实现（结构量）

9 条内置链路 = 同一批 16 块积木的 9 份 `stages` 数组（`packages/shared/src/templates.ts`）。
同一份节点集合既当「积木」又当「流水线」卖：**加一个节点，模板里立刻多出可插入的位置；
改一条模板不动任何运行时代码。**

## 三、付的那一半：清单税

### 3.1 两边的账目（实测）

| | 加一张**卡片**（工序） | 加一种**做法**（提示词块） |
| --- | --- | --- |
| 文件 | **23–26 个**（知识巩固 26 / Obsidian 23 / 素材挑选 25） | **1 个源码文件**（`prompt.ts`）+ 测试 |
| 行 | **1500–3100 行** | +61 / +71 / +214 |
| 服务端 | 引擎、预检、门禁脚本都要动 | **零改动** |
| 用户 | 多学一个概念（且收不回来：旧工程里的卡片要一直能跑） | 下拉里多一项 |
| 画布 | 多一个位置（ComfyUI 社区管这叫 node bloat） | 不占位置 |

**核验**：`git show --numstat f6ac5d4 / 7ff6ff9 / 7208547`（加卡片三次）、
`7588f60 / e813f17 / b14eef6`（加做法三次）。

### 3.2 清单税已经咬过人——两次

**漏改不会报错**，这件事已经在仓库里发生过：

- **`flow.pick` 的卡片图标漏了一支。** 代码注释自己记着这段事故：那处曾经是 `switch`，
  漏配一个类型不会编译不过——「`flow.pick` 漏了一支没人发现，素材挑选卡的头部就没有图标，
  标题比别的卡少缩进 17px，整张卡看起来不像同一套组件」。（`ScribeNode.vue:486` 附近）
- **AI 密钥预检名单漏了三个节点。** `process.chapter` / `process.gameguide` / `process.obsidian`
  都不在预检里，缺密钥时表现为「运行能启动、中途才失败」，而不是启动就被拒。（`docs/nodes.md` §9.3）
- **同一个概念在仓库里有三份清单，成员各不相同**：引擎的逐项透传 5 个、契约包的
  `PER_INPUT_NODE_TYPES` 7 个、前端结果页的 `PER_INPUT_RESULT_TYPES` 4 个；
  其中一份的注释明确写着「**不能**复用另一份」。（`packages/shared/src/segment.ts:90`、
  `apps/web/src/utils/run-segments.ts:37`）

### 3.3 守护强度分级（这一节可以直接变成待办）

同样是「按节点类型列一遍」，保护强度分三档。**出过事的全在最下面一档**：

| 清单 | 守护 | 漏了会怎样 |
| --- | --- | --- |
| `NODE_TYPE_LABELS` / `NODE_CARD_WIDTH` / `NODE_PORTS` / `nodeDescriptions` / `TYPE_ICONS` | 写成 `Record<NodeType, …>` | **编译不过** |
| `NODE_TYPE_ORDER` | 测试里有穷尽断言 | 测试红 |
| `nodeDataByType`（Zod 判别联合） | 运行时校验 | 保存被拒（错误信息是一长串期望值） |
| **`runNode` 的 switch** | **`default: throw`，不是 `never`** | **编译过、运行到才炸** |
| `RETRYABLE_NODE_TYPES` | 测试只抽查一个成员 | 静默不重试 |
| 逐项透传 / 卡片预览排除 / AI 密钥预检 / `PER_INPUT_*` / `SECTION_TYPES` / `noInlineFormTypes` | **无** | **静默行为不一致** |

**结构量**：按节点类型硬比较的地方共 **73 行 / 91 处**，分布在 **12 个文件**；
最多的是 `engine.ts`（31 行）、结果页（16 行）。而契约文件 `graph.ts` 是 **0 行**——
它用 `Record<NodeType, …>` 声明，一处硬比较都没有。**这就是「该长什么样」的现成例子，只是没铺满。**

## 四、下次加节点时，怎么把这份优势真的兑现

**这一节是「怎么让加节点变便宜」，不是「怎么少加节点」。** 该加就得加——只有卡片能改料的形状。
要压的是那 73 行手写枚举带来的小心翼翼，不是加卡片这件事本身。

按证据排优先级：

1. **先声明端口，再看它能插哪。** 端口声明就是这张卡的可组合性预算：多类型输入口的节点两端都宽松
   （挂得上 82%、塞得进 82%），而单类型口 + 笔记块产物的节点挂得上 49%、**塞得进只剩 4%**。
   **开工前先把这张卡该接受什么、产出什么定下来，比写完再调便宜得多。**
2. **加卡片必须配一条内置链路。** 否则用户不知道它能插哪——现在 9 条链路里 8 条都以
   「AI 校对」开头，说明模板本身就是教学材料。
3. **把那 7 处枚举一次改齐，并且能提级的提级。** 能写成 `Record<NodeType, …>` 的就写（编译期拦下）；
   拦不住的（如 `runNode` 的 switch）至少加一条穷尽断言，或者把 `default` 换成 `never` 收口。
   **这一条是把「73 行手写枚举」从风险变成清单的唯一办法。**
4. **不属于「工序」的，一律走提示词块。** 判据见
   [docs/research/node-vs-prompt-block-boundary.md](../docs/research/node-vs-prompt-block-boundary.md)：
   **卡片是工序，提示词是做法**；料会变形、或得出门拿/写东西的，才是工序。

## 五、明天怎么讲（建议）

**不要为这个单独开一页。** 你们这一版定的选题标准是「每页的主角是用户身上发生的事」，
而「加一个节点要动 26 个文件」属于我们的架构取舍——屋里没有人在写同类产品，
上一版已经因为这类内容被撤过（MODULES.md 开头记着）。所以：

- **投影上只用一句**：P4 底纹带那句「差别在形态：固定管线还是你自己连」已经在这个位置上了；
  如果要在 P6「真正站得住的三条」里补一句，补**「音轨变稿子、一份变好几章、稿子变一套题——
  这些变形我做成积木，顺序你定；贴链接选模板那种产品一次只能给你一种」**。
  这是收益，不是架构；而且它一句话就把「只会加提示词」那个质疑堵住了。
- **被问到时照这个顺序答**（放 [ROOM.md](./ROOM.md) 的备料里）：
  1. 为什么不用 n8n / Dify 自己搭 → 已经有答法，接着补一句：「而且它的节点是通用节点，
     我这 16 个是长在『音视频进、Markdown 出』这条链上的，比如素材身份、按段阅读、
     转写这几件事，通用节点里没有。」
  2. **「你自己加了这么多节点，用户学得过来吗？」** → 三层答：
     ① 可以**收起**：设置页「展示范围」把用不到的节点收起来，而且**只影响新建**，
     旧工程里的节点照常跑（`packages/shared/src/visibility.ts` 的三条约定）；
     ② 常用路径已经**预连好了**：9 条内置链路，平均三四步；
     ③ 大部分新能力**不是新卡片**，是「AI 加工」下拉里多一种做法——16 个内置块，用户不用学新概念。
     **但答完这三条要把话收回来**：改料的形状的一定是新卡片，我们会加，只是**加得少而准**
     （16 个节点里 13 个都在改料的形状，只有 3 个只是换做法，其中 1 个我们自己承认走错了）。
     别说成「以后都靠提示词」——那句你上一轮已经自己指出是空的。
  3. **「以后想加功能怎么办？」** → 用第 2.2 节那组数：一个节点声明完端口，就知道自己
     在 9 条内置链路里能挂上 95 处、能直接塞进去 43 处，而运行时一行不用改。

## 六、诚实的部分

**这次现量的**（2026-09-29）：
- 连线判定 108/256、可插入位置那张表（26 张展开图 / 116 个位置 / 两个口径）—— 脚本算的，脚本里带前置断言
- 三次加卡片的文件数与行数、三次加做法的行数 —— `git show --numstat`
- 73 行 / 91 处 / 12 个文件、`runNode` 的 `default` 不是 `never` —— 脚本扫源码 + 人工看代码
- 「Zod 判别联合漏一个类型会怎样」—— 实跑了一次 `graphSchema.safeParse`，确认报
  `Invalid discriminator value` 并把 16 个合法值全列出来

**口径修过一次，这里记下来**：第一版的可插入位置数用「路径上任意一个上游拼得上就算」，
而且分支模板的共享前缀按分支重复计，得出的数偏高（AI 加工 46 而不是 5）。
现在改成**立即前驱 + 双向 + 按边去重**。**上一版那两个数（101 / 46）已经作废，不要再引用。**

**没有验证的**：
- **能挂上 ≠ 有用**。95 处「挂得上」是**类型上**挂得上，不代表每一处都讲得通
  （比如把「合并」挂在两个「AI 加工」之间是合法的，但你多半不想）。
  这两个数的作用是「比大小 + 定位瓶颈」，不是「有 95 种好用法」。
- **`run-segments.ts` 那份 4 个成员的清单里没有 `process.drill`**，而引擎那边把 drill 算作
  「一个输入一份结果」。看起来可能漏了，但两份注释都强调语义不同，
  而练一练的产物走的是「练一练」标签页、不走分段阅读——**判断不了是不是真漏了，需要单独核**。
- 「加一种做法只有 1 个源码文件」取自三次提交，里面还各带了一份根目录的 .md 说明，
  以及个别提交顺带改了冒烟脚本。**纯运行时改动是 1 个文件，这一点是准的。**
- 116 个位置是拿**内置链路**当样本算的，不是拿用户真实工程算的（本机没有跑过真实规模的工程统计）。
  真实工程大概率更长，位置数会更多，但**没量过**。

**量过但建议不要引用**：
- **「16 种节点能连出 3,472,103 条合法链路」**——脚本第三段会算出来，但**不要拿去讲**。
  它把「连串三个素材挑选」这类无意义连法也算进去了；同一个口径下拿掉一个节点会涨 570%，
  纯粹是因为多类型端口的节点能插在几乎任何位置。**这是上界，不是可用量。**
  讲可组合性就用 2.2 那张「可插入位置」表，它小、可核、每个数都能对到一条真实链路。

**数字会漂的**：节点数、文件数、行数、73 行那组都会随改动变。
脚本里已经写了断言（节点必须是 16 种、硬比较必须是 73 行），源码变了它会直接报错，
照报错信息更新脚本与本文即可。**讲之前重跑一次。**
