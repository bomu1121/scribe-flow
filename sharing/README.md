# 分享会

## 产出在哪

- `out/ScribeFlow-前端技术分享.pptx` —— **18 页，可直接讲**
- `out/slides/slide-01…18.png` —— 逐页导出图（已过几何自检与逐页视觉验收）
- [SPEECH.md](./SPEECH.md) —— 讲演稿：时间分配、逐页要点（含代码出处）、现场演示清单、可能被问到的、删减顺序
- [ROOM.md](./ROOM.md) —— **现场手册**：那天说什么、绝不投什么（含三条"别点"的演示路径）、竞品答法、被问什么
- [QA.md](./QA.md) —— 答辩备查：实际查过的问题（现象 → 怎么定位 → 结论与改法 → 证据强度），含我自己踩的测量坑
- [MODULES.md](./MODULES.md) —— **模块技术细节备查（前端优先）**：第一部分是前端（画布 / 运行态呈现 / 结果页 / 素材交互 / 工程外壳 / 播放器 / 依赖与设计系统 / 工程化现状 / 密钥），每模块给「技术点 → 为什么 → 被问到怎么说 → 局限」；第二部分把后端压成一张「我们用的 / 主流怎么做 / 差在哪」的对照表，不展开实现
- `tools/build-deck.cjs` —— 生成 PPT（改文案后重跑 `node tools/build-deck.cjs`）
- `tools/qa-deck.cjs` —— 生成后的几何自检：解开 pptx 读形状坐标，查越界 / 重叠 / 溢出 / 独字行
- `tools/export-slides.ps1` —— COM 导出 PNG（脚本里刻意不写中文，这台读 .ps1 用 GBK；无真 PowerPoint 时由 WPS 演示承接同一 ProgID）

产出链条：改内容 → build-deck → qa-deck → 导出 PNG → 逐页视觉验收。

## 讲什么

三个段落都是**产品的主体界面**，按一次运行的顺序走：编排 → 运行 → 读结果。

| # | 段落 | 页 |
| --- | --- | --- |
| 01 | 节点编排画布 —— 用了画布库，也不省产品级画布的工作量 | 4–7 |
| 02 | 推送会撒谎，数据库不会 —— 真相通道与四层兜底 | 8–12 |
| 03 | 把 AI 的输出当成会坏的东西 —— 逐条丢弃、不判两次死刑、Markdown 过 DOMPurify | 13–16 |

开场 3 页（含「我为什么做这个」）、收尾 2 页（含「我们没做好的三件事」）。

每条结论都对着实际代码核过，出处写在每页页脚。

## 核过的关键数字

数字都标了来源：**实测**是跑出来的，**结构量**是从代码数出来的（行数会随改动漂，讲之前重跑一次）。

| 数字 | 值 | 来源 |
| --- | --- | --- |
| 节点类型 / 端口类型 | 16 / 4 | 结构量（`NODE_TYPE_LABELS`、`PORT_TYPES`） |
| 画布目录 / 外壳单文件 | 5913 行 / 3028 行（卡片分派 16 段） | 结构量（`wc -l`） |
| 撤销上限 / 重连 / 轮询 / 分段回溯 | 50 步 / 2 秒 / 5 秒 / 12 层 | 结构量 |
| 运行结束多久清掉运行态 | 60 秒 | 结构量（`engine.ts`） |

## 还没做的优化（与 PPT 内容无关，是仓库本身的欠账）

- **ELK 已经进 Worker，但打包体积仍是 1441.14 kB raw / 439.11 kB gzip**（比首屏关键路径的七成还多），
  而项目只用 `layered` 一种算法。候选替代是 `elkjs-native` 或 `d3-dag`，**体积与布局质量都没实测**，动手前先做 spike。
- **Element Plus 样式改按需**：全量 `dist/index.css` 352.79 kB raw / **47.03 kB gzip**；按需只要 25 个文件，
  117.99 kB raw / **22.71 kB gzip** → 可省 **24.32 kB gzip（51.7%）**。
  风险在 `element-theme.css` 的 96 个 `--el-*` 桥接依赖导入顺序，改完必须跑视觉回归。
- **manualChunks 那条结论没落地**：`apps/web/vite.config.ts` 至今没改，因为涉及缓存粒度取舍。
- 其余待做：组件测试（Vitest 4 的 Browser Mode 已转正）、oxlint 补 `no-floating-promises`、
  移除零使用的 Tailwind（preflight 有视觉风险，需回归）。

## 复现

```bash
cd sharing && npm i                # pptxgenjs，独立于 pnpm workspace
node tools/build-deck.cjs          # 生成 pptx
node tools/qa-deck.cjs             # 几何自检，有输出即有问题
powershell -File tools/export-slides.ps1   # 导出 18 张 PNG
```

## 不太确定的地方

- PPT 里所有代码引用（`文件路径:行号`）在写稿当天与代码一致；**改动源码后行号会漂**，讲之前重新核一遍。
- `qa-deck.cjs` 的折行估算与 `build-deck.cjs` 的居中估算用的是同一个字宽模型，所以**它抓不出模型本身错的那类溢出**——它只保证「明显塞不下」能被拦下，不替代逐页看图。
- 首屏体积只测了 gzip，没有测 LCP / FCP。
- **画布没有真实规模的性能基准**：只在合成的 200 节点场景上验证过，那不是实际在用的规模，也没有多轮统计与方差。
