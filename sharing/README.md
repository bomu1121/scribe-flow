# 分享会

## 产出在哪

- `out/ScribeFlow-前端技术分享.pptx` —— **18 页，可直接讲**
- `out/slides/slide-01…18.png` —— 逐页导出图（已过独立视觉验收：第一轮 11 页不合格 → 第二轮剩 2 页 → 第三轮定点复检，**18 页全 pass**）
- [SPEECH.md](./SPEECH.md) —— 讲演稿：时间分配、逐页要点（含代码出处）、现场演示清单、可能被问到的、删减顺序
- [ROOM.md](./ROOM.md) —— **现场手册**：那天说什么、绝不投什么（含三条"别点"的演示路径）、竞品答法、被问什么
- [QA.md](./QA.md) —— 答辩备查：实际查过的问题（现象 → 怎么定位 → 结论与改法 → 证据强度），含我自己踩的测量坑
- `tools/make-bench-graph.mjs` —— 演示道具：一条命令建好 200 节点的演示工程（纯文本链路，不需要密钥/网络）
- `tools/build-deck.cjs` —— 生成 PPT（改文案后重跑 `node tools/build-deck.cjs`）
- `tools/qa-deck.cjs` —— 生成前的几何与结构自检（溢出 / 越界 / 重叠 / 独字行 / 同段重复 pPr）
- `tools/export-slides.ps1` —— PowerPoint COM 导出 PNG（脚本里刻意不写中文，这台读 .ps1 用 GBK）

产出链条：改内容 → build-deck → qa-deck → 导出 PNG → 交独立 judge 验收。

## 讲什么（v2：换成产品主体）

**第一版讲错了方向**：讲的是分块配置、自研 lint、死 CSS —— 那些是项目的边角料，而且用户看不见。
现在三个主题都是**产品的主体界面**：

| # | 主题 | 页 |
| --- | --- | --- |
| 01 | 节点编排画布 —— 用了画布库也不省产品级画布的工作量 | 3–7 |
| 02 | 长任务的实时呈现 —— 有了推送反而更需要轮询 | 8–12 |
| 03 | AI 输出的呈现层 —— 引擎给拼接产物，用户要按段读 | 13–16 |

开场 2 页、收尾 2 页（收尾含「我们没做好的三件事」）。

每条结论都对着实际代码核过，出处写在每页页脚。核过的关键数字：16 种节点类型、画布目录 5687 行、
外壳单文件 2849 行、14 段分派分支、4 种端口类型、撤销上限 50 步、重连 2 秒、轮询 5 秒、分段回溯上限 12 层。

## 还没做的优化（与 PPT 内容无关，是仓库本身的欠账）

- **ELK 自动布局是最大的一块按需浪费**：点一次「自动布局」会下载 `elk.bundled.js` —— 1441.14 kB raw /
  **439.11 kB gzip**（比整个首屏关键路径的七成还多），而项目只用 `layered` 一种算法。候选替代是
  `elkjs-native` 或 `d3-dag`，但**体积与布局质量都没实测**，动手前先做 spike。
- **Element Plus 样式改按需**：全量 `dist/index.css` 352.79 kB raw / **47.03 kB gzip**；按需只要 25 个文件
  （18 个在用组件 + 7 个基础设施），117.99 kB raw / **22.71 kB gzip** → 可省 **24.32 kB gzip（51.7%）**。
  风险在 `element-theme.css` 的 96 个 `--el-*` 桥接依赖导入顺序，改完必须跑视觉回归。
- **manualChunks 那条结论没落地**：`apps/web/vite.config.ts` 至今没改，因为涉及缓存粒度取舍。
- 其余待做：组件测试（Vitest 4 的 Browser Mode 已转正）、oxlint 补 `no-floating-promises`、
  移除零使用的 Tailwind（preflight 有视觉风险，需回归）。

## 不太确定的地方

- PPT 里所有代码引用（`文件路径:行号`）在写稿当天与代码一致；**改动源码后行号会漂**，讲之前重新核一遍。
- 「分块破坏摇树」的机制解释仍是对现象的推断，未读 Rollup 源码；那条结论也仍未落地。
- 首屏体积只测了 gzip，没有测 LCP / FCP。
- **前端性能没有基准测试**：几百个节点会不会卡，没有实测数据（讲稿里如实标了这一点）。
- 技术栈升级建议有时效性（Vue 3.6 仍在 RC 等），讲之前重新确认。
