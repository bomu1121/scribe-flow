## 讲什么

先讲产品形态与差异化（项目介绍该做的），再讲用户在界面上会碰到的两类事。

| # | 段落 | 页 |
| --- | --- | --- |
| 01 | 它是什么，跟现成的差在哪 —— 一张画布三个界面、两类现成产品中间的位置、**技术底座**、承认表、八段只要三段 | 3–7 |
| 02 | 跑的时候 —— 进度停在半路、被记成「你取消了」、换条运行白一下 | 8–11 |
| 03 | 读的时候 —— 八个视频自己找、渲染错类型空了、选字却拖跑节点、粘的是分享文案 | 12–16 |

开场 2 页（含「我为什么做这个」）、收尾 2 页（含「我们没做好的三件事」）。段一里那页「技术底座」是**资历信号**页
（这一类的标配、都是当下一线的版本），只报版本号、不展开，40 秒讲完。

**选题标准（这一版定的）**：每页的主角是**用户身上发生的事**，而且要是屋里人自己也会碰到的事；
代码只作为答案出现，不作为标题。**反面教材**：上一版讲过的 `16 种节点只注册 1 个 nodeType`、
`markRaw`、外壳 3028 行——那些是"我们的架构取舍"，屋里没有人在写同类产品，无人在意，已全部撤掉
（ROOM.md 的备料里留着，被问到才答）。

每条结论都对着实际代码核过（2026-09-29 逐条重量过一遍），出处写在每页页脚。

## 还没做的优化（与 PPT 内容无关，是仓库本身的欠账）

- **ELK 已经进 Worker，但 worker 产物是 1,595,334 B（gzip 466,809 B）**，比首屏关键路径还大，
  而项目只用 `layered` 一种算法。候选替代是 `elkjs-native` 或 `d3-dag`，**体积与布局质量都没实测**，动手前先做 spike。
  （n8n 与 Dify 的自动整理用的是 Dagre，体积小一个量级——这条取舍现在放在 ROOM.md 的备料里，被问到才答。）
- **Element Plus 样式改按需**：当前全量引入的 `element-plus-*.css` 是 360,839 B raw / **47,662 B gzip**；
  「按需只要 25 个文件、117.99 kB raw / 22.71 kB gzip、可省 24.32 kB gzip（51.7%）」是**更早一次实验的记录，
  这次没重跑**（没做按需构建）。风险在 `element-theme.css` 的 96 个 `--el-*` 桥接依赖导入顺序，改完必须跑视觉回归。
- **manualChunks 那条结论没落地**：`apps/web/vite.config.ts` 至今没改，因为涉及缓存粒度取舍。
- 其余待做：组件测试（Vitest 4 的 Browser Mode 已转正）、oxlint 补 `no-floating-promises`、
  移除零使用的 Tailwind（preflight 有视觉风险，需回归）。

## 复现

```bash
cd sharing && npm i                # pptxgenjs，独立于 pnpm workspace
node tools/build-deck.cjs          # 生成 pptx
node tools/qa-deck.cjs             # 几何自检，有输出即有问题
powershell -File tools/export-slides.ps1   # 导出 18 张 PNG
```

`WORKFLOW.md` 里那些数从仓库根目录跑（tsx 在 pnpm 的虚拟目录里）：

```bash
node node_modules/.pnpm/tsx@4.23.12/node_modules/tsx/dist/cli.mjs sharing/tools/node-economics.ts
node node_modules/.pnpm/tsx@4.23.12/node_modules/tsx/dist/cli.mjs sharing/tools/graph-guards.ts
node --no-warnings sharing/tools/run-audit.mjs          # 读运行记录；只在有数据时能跑
```

前两个脚本自带前置断言（节点必须是 16 种、硬比较必须是 73 行、内置链路每段必须类型合法、
26 张内置链路必须全部合法且无环），源码变了会直接报错——
**报错就照信息更新脚本与文档，不要绕过断言。**

## 不太确定的地方

- PPT 里所有代码引用（`文件路径:行号`）在 2026-09-29 逐条重量过；**改动源码后行号会漂**，讲之前重新核一遍。
- **这一轮的视觉验收没有用独立 judge**：`documents:visual-judge` 起不来（provider 不可用），
  改成我自己看图——18 页里直接看过 **12 页**（P1 / P2 / P3 / P5 / P6 / P7 / P9 / P10 / P13 / P15 / P17 / P18），
  覆盖了全部六种版式；没看的是 P4、P8、P11、P12、P14、P16，都是已验过版式的重复形态，
  且 `qa-deck` 几何自检 0 问题。按本仓的规矩这不算数，条件恢复后应补一次。
- **重排期间仓库里的模板被并行改过**（11 条合并成 9 条、名字改成源无关的），投影 P3 那句
  「内置 11 条常用链路」当场过期、已按 `templates.ts` 重核改正。这正好是本仓那条
  「易漂的数字讲前重跑」的现成例子——**上台前一小时再过一遍页脚引用的行号与计数**。
- **有几组数字是转引、不是这次现量的**：结果页切换不闪的「533 次采样 / 100ms / 9ms」、
  设置弹窗的「1.4s → 21ms」与「Obsidian 扫描 280–840ms」，都出自 `CHANGELOG.md` 2026-09-29 那次的记录，
  这次没有重跑复现；PPT 的页脚把它们标成了「作者实测记录，未在本机复现」。
- n8n / Dify 的做法（撤销用命令模式、整理用 Dagre）来自公开文档与 PR，**没有在本机安装它们验证**。
- `qa-deck.cjs` 的折行估算与 `build-deck.cjs` 的居中估算用的是同一个字宽模型，所以**它抓不出模型本身错的那类溢出**——它只保证「明显塞不下」能被拦下，不替代逐页看图。
- 首屏体积只测了 gzip，没有测 LCP / FCP；「前端测试 5 个文件 / 44 个用例」数的是静态 `it(` 声明数，不是实跑数。
- **画布没有真实规模的性能基准**：只在合成的 200 节点场景上验证过，那不是实际在用的规模，也没有多轮统计与方差。
