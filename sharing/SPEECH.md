## 逐页要讲的话

**P1 封面** — 一句话交代产品：把视频/文稿放进画布，用节点编排「转写 → AI 加工 → 合并 → 输出」，跑完得到一份笔记。今天不讲产品，讲它三个主体界面里最难做的部分。

**P2 我为什么做这个** — 不要省。攒了几百个技术视频看不完但丢不掉；市面上的工具是「贴链接、选模板、出摘要」，模板改不了；我想要的是把每一步摊开自己连。这一页同时办掉两件事：说明动机，顺带把「跟已有的有什么不一样」答掉一半。

**P3 今天讲三件事** — 强调这三件都是**用户看得见**的界面，不是工程配置。可以点一句：很多技术分享讲的是构建配置和 lint，那些东西用户永远看不到。

**P4 主题一过场** — 抛出核心判断：用了画布库，也不省产品级画布的工作量。5913 行里真正调库 API 的不到 200 行。

**P5 一个 nodeType** — 讲取舍，不讲实现。外壳共享换来 16 种节点复用；代价是外壳文件 3028 行，卡片分派是一条 16 段的分派链（只有 6 张卡片拆成了独立组件）。**要决策的是边界**：端口、菜单、状态条、只读控制该共享，具体表单该拆。补一句 Vue 的坑：节点组件必须 `markRaw`，否则会被包成响应式代理。

**P6 快照式撤销，和它带来的两个副作用** — 先讲机制（存整图快照、上限 50 步、出图时剥掉运行态、输入框逐字改图但失焦才提交一次历史），再讲两个副作用。**副作用那段是全场最容易共鸣的地方**：用户按 Ctrl+Z 觉得没反应，因为压入了重复快照；撤销顺带把镜头弹回去，因为视角也在快照里。

**P7 浮层坐标系** — 全场技术含量最高、也最容易讲出「原来还有这一层」的一页。顺序：问题（浮层传送到 body，脱离缩放坐标系）→ 解法（provide 一个 zoom，浮层用 CSS zoom 补偿）→ 两个细节（位置不用补、只有尺寸要补）→ 为什么用 zoom 不用 transform。收尾点一句：provide/inject 能穿过 Teleport 是 Vue 的机制红利。

**P8 主题二过场** — 交代场景：转写和 AI 加工可能跑很久，中途断线、切页面、服务重启都是常态。

**P9 有了推送反而更需要轮询** — 本场的核心反直觉点，**一定要讲透**。直觉是有推送就不用轮询，而这里反过来：推送是唯一会静默失效的通道，断线、丢帧、服务重启它都不报错，只是不说话了。所以数据库是真相通道、推送只是加速通道，轮询是它的正确性校正器。四层兜底逐条念。

**P10 放弃增量** — 讲清那条取舍链：增量要求「先收到全部前置事件」→ 于是重连必须做事件重放 → 而这套系统的广播没有重放缓冲 → 路走不通。换成全量覆盖后，重连的正确性问题直接消失。

**P11 建连即补快照** — 讲因果：广播是内存集合、没有重放缓冲（运行结束 60 秒后就没了），所以「连接」这个动作必须自带状态同步。四类节点分别补什么，一句话带过。

**P12 局部重跑是新运行** — 因果链：新 run id → 结果只含本次范围内的节点 → 画布上其它节点退化成未运行（视觉上像删了之前的成果）→ 视图层从历史运行回填。结论那句要念：把复杂度从「前端状态机」挪到了「纯函数式的快照合并」。

**P13 主题三过场** — 交代矛盾：一张卡挂 8 个视频，引擎把它们拼成一份，人却要一个一个读。

**P14 AI 产物坏了是常态** — 四个手法一起讲最有说服力：逐条丢弃但原因必须是人话（丢弃率当质量指标看）、生成期严展示期松（不判两次死刑）、要有降级形态、类型靠嗅探且要互斥。**那个真实 bug 讲出来很加分**：我们曾经把练习题渲染成了一张空的溯源表格。

**P15 Markdown 进 DOM 前必须过一遍** — 全场唯一一条跟安全有关的结论：AI 的产物是外部输入，直接插进页面等于把远端内容当本地内容渲染。统一走 `renderMarkdown`（先 `DOMPurify.sanitize` 再插 DOM）。顺带说降级：解析不出来时给一句人话，不把原始 JSON 摊给用户。

**P16 分段是推导出来的** — 这条是「让派生数据可推导」比「让后端多存一份」更划算的例子：靠运行时记录的「每个输入一行」反推，所以**历史运行不用重跑就能分段**；标题要向上游回溯最多 12 层取视频名。

**P17 三个判断** — 逐条念，可以请大家一起念第一条。

**P18 我们没做好的三件事** — **不要跳过**。三条都是自己在代码里核出来的：提示抛了没人接（3 处 `emit` 零绑定）、同一规则三份实现、状态机比契约小一圈（`queued` 与 `cancelled` 没有视觉表达）。主动讲缺陷会显著提高整场的可信度。

## 大概率会被问到的

> 被问「你们中间遇到什么问题、怎么解决的」时，照 [QA.md](./QA.md) 答——那里按
> 「现象 → 怎么定位 → 结论与改法 → 证据强度」记着实际查过的问题，每条都标了数字是实测还是推断。
>
> 被问「某一块具体怎么实现的」（密钥怎么接、上传怎么收、重试怎么定、备份怎么恢复……）时，照
> [MODULES.md](./MODULES.md) 答——每个模块都有「机制 → 为什么这么选 → 被问到怎么说」三段，
> 最后一栏是能直接念的口语版。

- **「密钥是怎么接的？」** — 用户填在设置页，存本地 SQLite，接口只回「有没有填」不回值；请求由 Node 进程直接发，不走浏览器。不同家鉴权写法不一样（详见 MODULES.md）。
- **「局部重跑为什么不复用旧运行？」** — 复用会破坏「一次运行的审计边界」：这次跑出来的算哪次运行、耗时怎么算。
- **「为什么不直接让后端返回分段数据？」** — 分段是能从既有事实推导出来的，让它可推导比多存一份更划算，而且历史运行也能立刻分段。
- **「AI 返回的 JSON 不合法怎么办？」** — 三层降级：裸 JSON → 去代码围栏 → 截首尾大括号；再不行就逐条丢弃并给出原因，绝不让一条坏数据毁掉整批。
- **「AI 怎么保证它不乱说？」** — 只做结构校验和引文回查，**不做事实校验**，这块是下限。承认。
- **「长文档阅读页你们怎么做的？」** — 现在是一次性渲染，虚拟化还没做，是下一步。承认。
- **「怎么跟 BibiGPT / 通义听悟 / 飞书妙记不一样？」** — 照 [ROOM.md](./ROOM.md) 的 30 秒版答；那里还有一张「已经有人做了的，老实说」的表，别装成都是自己发明的。
- **「有没有做过调研？」** — 别说「我调研过」，说闭环：有产物（`docs/research/r1-desktop-research.md`，20 个产品、原始 HTML 存档、核实状态）、有结论（14 维矩阵 + 4 个 P0）、**落地了**（4 个 P0 代码里全都有）。
- **「三道连线关卡，服务端真会拦吗？」** — 这是准备好被挑刺的那一个。服务端那道只校验端口存在与自连，**不校验类型兼容**。老实答：「第三道是弱的，等于只有两道硬的。」
