# 每个模块怎么讲

这份是**讲的时候照着说**的材料。每个模块四块：**一句话 → 怎么做 → 别人问起来怎么说 → 坑在哪**。
「怎么说」那几段可以直接念，都是口语。

后端的东西我不在这里细讲——它不是这次分享的主角，只需要在被问到的时候答得上来，
所以压在最后一页的表格里，一句话一块。

---

# 一、画布

## 十六种节点，只写一个组件

**一句话**：用户在网格上拖节点、连线、点运行。这个界面里产品级的东西，基本都是我们自己写的。

**怎么做**：底座的 Vue Flow 只给视口、缩放、拖拽、连线的底座。十六种节点我们**只注册一个** nodeType，
真正的业务类型放在节点的 data 里，卡片按类型分派。收益是端口、右键菜单、运行按钮、状态条、悬停预览、
只读控制只写一遍，十六种节点共用同一个外壳；代价是那个外壳文件长到三千多行。

顺便一个 Vue 的坑：节点组件必须 `markRaw`，不然会被包成响应式代理，Vue Flow 比组件引用的时候会出问题。

**别人问起来怎么说**：
> 画布底座是 Vue Flow，但产品级的东西基本自己写。十六种节点只注册**一个**组件，业务类型放 data 里，
> 卡片按类型分派——这样端口、菜单、状态条、只读控制只写一遍。代价是那个文件长到三千行。

**坑**：那个外壳文件是全项目第二大的单文件；十六种节点里只有六张卡片拆成了独立组件，剩下十种还挤在分派链里。

## 连线合不合法，看类型不看界面

**一句话**：两种东西能不能连，由数据类型决定，不是界面上试出来的。

**怎么做**：一共四种口子——音频、转写稿、笔记块、笔记文档。它们之间还有偏序关系：笔记文档既能接笔记块、
也能接笔记文档，其它三种只接同类型。判定就是两个函数的比较，画布只是把结果接进库里。

**别人问起来怎么说**：
> 连线合不合法不看界面看类型系统：四种口子，还有偏序关系——笔记文档能收笔记块也能收笔记文档，
> 其它三种只收同类。这样它就是一条数据上的规矩，测的时候比对一下就行，不用去模拟拖拽。

**坑**：这条规矩现在写在三个地方，其中一处的实现已经不认多类型端口了，只有测试还在用它。
还有——我们说自己有三道关卡（拖的时候判、落线的时候查重、保存时服务端再查一次），
**第三道其实是弱的**：服务端只查了口子存不存在、是不是自连，没查类型兼不兼容。等于只有两道是硬的。
被问到就认，别硬撑。

## 撤销：存整张图，以及它带来的两个怪现象

**一句话**：撤销不是记"你做了啥"，而是每一步存一份整张图的快照。

**怎么做**：上限五十步，存的时候把运行态的信息剥掉，刷新后不会卡在"运行中"。
输入框是另一条路：你在里面打字的时候不记历史，等你点到别处才记一次。

**别人问起来怎么说**：
> 撤销是整图快照、上限五十步。输入框里逐字改但不记历史，失焦才提交一次。

**坑**（这一段很好笑，讲出来有共鸣）：
- 点进输入框什么都没改、再点空白，也会存一份一模一样的快照。用户按 Ctrl+Z 就觉得"没反应"。
- 镜头位置也在快照里，所以撤销会顺手把画面弹回当时的样子。

## 画布缩到 60% 之后，节点里的下拉框为什么也跟着变小

**一句话**：这是全篇技术含量最高的一处，也是最容易讲出"原来还有这一层"的一处。

**怎么做**：节点里的下拉框、右键菜单这些浮层，被传送到了页面最外层，**脱离了画布的缩放**——
画布缩到 60%，浮层还是原来那么大。我们的做法是画布把当前的缩放值传下去，浮层拿到之后自己用 CSS `zoom` 补回来。

两个细节值得讲：**位置不用补**（浮层库按屏幕上的实际位置定位，缩放之后那个位置本来就是对的），**只有尺寸要补**；
以及**为什么用 `zoom` 不用 `transform: scale`**——`zoom` 会参与布局计算，而 `transform` 会干扰浮层库自己算位置。

最麻烦的是模型下拉那一处：屏幕上的宽度要**除以**缩放，才是节点内部的宽度。

**别人问起来怎么说**：
> 节点里的下拉框被传到了页面最外层，就脱离了画布的缩放——画布缩到 60%，它还是原尺寸。
> 我们从画布把缩放值传下去，浮层用 CSS `zoom` 补回来。**位置不用补，只有尺寸要补**。
> 用 `zoom` 而不是 `transform: scale`，因为 transform 会干扰浮层库自己算位置。

**坑**：模型下拉那一处最绕；`provide / inject` 能穿过传送门是 Vue 的机制红利，值得点一句。

## 节点里能填表，还得能拖节点

**一句话**：小坑，但做过编辑器的人会点头。

**怎么做**：把拖拽的把手收到卡片头部，表单区域标成不可拖。不然你在输入框里选字，选着选着就开始拖节点了。

## 连线的曲线也是自己画的

**一句话**：不是用库默认的边。

**怎么做**：基于库的「基础边」加自己的贝塞尔曲线计算，这样才能在边上加运行状态的样式。

## 下拉菜单打开时，背后不许响应

**一句话**：对齐参考产品的手感——任何下拉或右键菜单打开时，页面其它地方不再响应鼠标。

**怎么做**：没有额外画一层遮罩。只是给页面根元素加一个类名，用 CSS 把非浮层的内容设成 `pointer-events: none`。
浮层自己还能点，点外面会落到页面本身，触发各浮层自带的关闭逻辑。覆盖了组件库的下拉、菜单、弹层，
以及我们自己写的几个菜单。

悬停预览那层是**故意排除**在外的——否则鼠标想移到下一个节点的时候会被挡住，反而触发不了关闭。

## 一键整理是怎么算出来的（Vue Flow / ELK / Web Worker 各管什么）

**一句话**：画布库管"能拖能缩能连线"，布局引擎管"排整齐"，Web Worker 管"排的时候别把界面卡住"。
这是三样不同层次的东西，被问到时按这三句拆开答。

**三个名词分别是什么**

| 名字 | 它是什么 | 它**不**负责什么 |
| --- | --- | --- |
| Vue Flow 1.48 | Vue 的图编辑器底座（React Flow 的 Vue 版，MIT）：渲染节点与边、平移缩放、拖拽、连线、缩略图、背景、视口裁剪 | 不知道该把节点摆在哪——你拖到哪就是哪；也不懂业务卡片、撤销、只读锁定 |
| ELK 0.12 | 图布局引擎（Eclipse Layout Kernel 的 JS 版）：你给它"谁连着谁 + 每张卡片多宽多高"，它算回每张卡片的坐标 | 不画界面，只出坐标 |
| Web Worker | 浏览器里的另一条线程：干重活时不占用主线程 | DOM 一律碰不到；数据进出要走一次拷贝，所以**它是"不卡"，不是"更快"** |

**"layered"这个算法在算什么**（我们只用这一种）：① **分层**——按依赖关系把节点分到从左到右的若干列
（`direction: RIGHT`）；② **层内排序**——尽量让连线少交叉；③ **定坐标**——按你给的宽高和间距算出具体 x/y。
所以要先把尺寸告诉它：宽度按节点类型取（`NODE_CARD_WIDTH[type] ?? 224`），高度统一 120；
间距是节点间 40、层间 140。

**跑起来的顺序**（`FlowCanvas.vue:658-712`）：点「自动布局」→ 懒加载 ELK 与它的 worker 脚本 →
把节点和边交出去 → 拿回坐标写回节点 → **压入历史（所以整理完可以撤销）** → 落盘 → `fitView` 把视野套上去。
实例是**懒加载单例**：每次 `new ELK` 都会拉起一个 worker，而 worker 启动本身有成本，所以只建一次。

**为什么必须用 `elk-api` 而不是 `elk.bundled`**：官方限制——自己 bundle 的那份不支持 worker，
必须用 `elk-api` 并把 worker 脚本的地址传进去（这里用 Vite 的 `?url` 拿到地址）。

**代价（与 n8n / Dify 的对照）**：worker 产物 1,595,334 B（压缩后 466,809 B），
对照 `elk-api` 的壳只有 4,935 B。n8n 的 Tidy Up 与 Dify 的「整理节点」都用 Dagre，体积小一个量级。
**这个取舍我们没做 spike**——被问"为什么不用 Dagre"就照实说：选 ELK 是因为它官方支持 Worker，
Dagre 更轻但没量过。

**代价被两件事对冲掉了**：① 它**懒加载**——没点过「一键整理」的用户一个字节都不下载，所以不在首屏关键路径上；
② 它只在点击时跑一次，不是每次改动都重排。

**被问到怎么说**：

> 画布用 Vue Flow，但它只给"能拖能缩能连线"的底座，摆在哪是你自己的事——所以「一键整理」得有个排版的。
> 排版用的是 ELK，算法是 layered，从左到右分层、层内少交叉、再按卡片实际尺寸算坐标。
> 关键是它跑在 Web Worker 里：排版是在大图上会长时间占住主线程的活，挪出去以后界面不卡。
> 注意这不等于更快——同样的计算，只是不占着前台。这份 worker 有一兆多，但它是懒加载的，点了才下。

**诚实清单**：源码注释里那句「合成场景 200 节点实测最长掉帧 526ms」是**合成场景**，不是真实规模
（本项目日常是个位数节点）；挪进 Worker 的收益**没有在真实规模上验证过**；Dagre 那条路**没做 spike**。

# 二、运行中，界面怎么一直说真话

## 长任务的进度与恢复

**一句话**：一次运行可能跑十几分钟，中间断线、切页面、刷新、重启都是常事。

**怎么做**：服务端用 SSE 推事件，一共十种（运行级、节点级、还有多步链的步骤级）。
**没有做到"一个字一个字往外蹦"那种流式**，界面上看到的是节点级的进度。

**别人问起来怎么说**：
> 我们一开始的直觉是：有实时推送了，轮询就是多余的老办法。后来发现**推送是唯一会悄悄失效的通道**——
> 断线、丢帧、服务重启，它都不报错，只是不说话了。所以现在的结构是：数据库是真相，推送只是加速，
> 轮询是它的校对。

## 四层保险

1. **断线两秒重连**。收到"运行结束"就主动断开，并且**不再重连**——不然已经跑完的运行会被反复重放一遍状态。
2. **全局五秒轮询对账**。本地看着还在跑，但全局列表里已经没有"进行中"了，就主动去核对一下、把状态收回来。
3. **运行结束补一次最终状态**。避免推送丢了事件，导致下游节点停在旧状态。
4. **进页面自动恢复**。有正在跑的就接上，没有就把最近一次的状态贴回画布。

还有一条反直觉的：**放弃了"只推变化"，改成每个事件都把字段整体覆盖一遍**。
因为"只推变化"要求"前面的一个都不能少"，而事件一定会丢。

## 接上时先补一份完整状态

**一句话**：内存里那份广播记录不留回放，运行结束六十秒后就没了。

**怎么做**：所以"连上"这个动作必须自带状态同步——服务端先补一份完整快照，再进增量。
补三类：已完成的、失败的、正在跑的。

**一个容易踩的坑**：补快照时会重放一包事件，其中有一个"运行开始"。前端**要主动把它扔掉**，
因为页面自己已经设过状态了，不扔会把刚恢复好的画面又清空一遍。

## 运行中的画布是只读的，而且用的是 getter 不是快照

一句话的点，十秒钟讲完，大家会觉得巧：运行一开始界面立刻变灰，不用刷新页面。

# 三、结果页

## 四个标签页

**一句话**：读报告的地方。结果、练一练、思维导图、节点流水——后两个有产物才出现。

**怎么做**：标签下面那条会滑的横线，是用元素实际位置量出来再算的，窗口变化时重新量；
首次量之前先藏着，不然进场会看到它从零滑一次。
键盘也做全了：左右箭头切换、Home 和 End 跳首尾，焦点只在当前那个标签上。

**为什么不做淡入**：对齐主流设计规范——横向切换用滑动，不用淡入。

## 拼接产物怎么变成能按段读

**一句话**：一张卡挂八个视频，引擎把它们拼成一份，人却要一个一个读。

**怎么做**：引擎跑的时候会把"每个节点实际吃了哪几行输入"记下来，前端拿这个记录**倒着推**出分段。
标题要沿链路往上找，最多找十二层，去拿原始视频的名字。
好处是**几个月前跑的记录，今天打开也能按视频切开读，不用重跑**。

有一个地方代码里特意写了备注：**不能**图省事复用另一个地方的同名定义——那个是给"素材挑选"用的，
这个是给结果页解析自己的产物用的，两者说的不是一件事，混用会让文本工具的段落退回没加工过的原文。

**别人问起来怎么说**：
> 分段不是后端算好存下来的，是前端从运行记录**倒着推**出来的：引擎会把每个节点实际吃了哪几行输入记下来，
> 所以几个月前那条运行，今天打开也能按视频切开读，不用重跑。

**坑**：只往上找十二层，再深就只能显示节点名了；老记录是倒推出来的，音频那条链只认转写节点一种下游。

## AI 的 Markdown 进页面前要洗一遍

**一句话**：全篇唯一一条跟安全有关的结论，也是 AI 前端最容易漏的一处。

**怎么做**：AI 返回的是外部内容，直接插进页面等于把远端的字当自己的字渲染。
我们统一走同一个入口：先过一遍过滤库，再把结果插进页面，不让任何一处绕开。

解析不出来的时候也给一句人话，不要把原始 JSON 摊给用户看。

## 改动前后能逐字对比

**一句话**：AI 校对前后到底改了哪几个字，是能看见的。

**怎么做**：用字符级差异对比算法，在"替换行"上做精确到字的高亮。

# 四、素材

## B站选集：点行是切换，勾选才是合并

**一句话**：一个视频有几十个分 P 的时候，用户要么只留一集，要么把几集合成一个素材。

**怎么做**：拆成两条轨道。**点一行 = 把这一行变成当前来源**（节点回到单链接的样子）；
**打勾 + 底部按钮 = 把勾中的合并成一张多素材卡片**，至少要勾两个才让点，不够的时候按钮下面会写还差几个。

**为什么拆**：以前是一颗按钮按勾了几个走两套逻辑——勾一个会把整个节点**悄悄换成那一集**，
多选卡片跟着消失，界面上完全看不出来。现在把两种意图分开表达。

还有个小设计：点"改选集"只是翻一个本地开关，**已经合并的内容不动**，解析失败或者反悔了东西都还在。

## 你没勾的素材，服务端连下载都不下

**一句话**：这是全篇里"前端一个动作直接省服务器带宽"的一处，前端同事会喜欢。

**怎么做**：每个素材有一个稳定的编号（用的是视频号和分 P 号，**不掺数组下标**，所以你改了选区，
下游也不会认错人）。引擎在跑来源节点之前先问一句"下游有没有人要这一段"，没人要就**连下载都跳过**，
日志里会写"跳过素材 3/8（未被任何下游节点选中）"。

**别人问起来怎么说**：
> 您在画布上没勾的素材，服务端**连下载都不下**。八个视频只放行三段，另外五段根本不下载。

## 扫码登录

**一句话**：扫码登录自己的 B 站账号，然后从收藏夹、合集、稍后再看里挑视频。

**怎么做**：二维码是服务端生成图片的，不依赖任何第三方图床。二维码的密钥**只在内存里**，不写数据库。
登录拿到的 Cookie **只存在服务端，不返回给浏览器**——接口只回用户名和头像。

两个计时器分工：服务端每两秒问一次真状态，前端自己每秒钟走一个倒计时（三分钟有效）。
这样既省请求，也不会因为两边时钟不一样而出现"看着还活着其实早过期了"。

## 上传

**一句话**：本地音视频拖进画布当素材。

**怎么做**：服务端接表单、落盘，三道校验——后缀名、类型、大小（默认上限 2GB）。
不管进来的是 mp4 还是 mkv，送识别之前都会统一转成 16k 单声道 wav。

**坑（被问到要认）**：
- 上传是**先把整个文件读进内存再写盘**的。仓库自己的调研文档把这条列成了已知风险，这次没做流式。
- 有大小和类型校验，但**没有真的去读文件头**确认，看的是浏览器报上来的文件名和类型。
- 上传的文件**没有任何清理机制**，会一直留在硬盘上。

# 五、工程与侧栏

## 自动保存的两个坑

**一句话**：画布改动会自己存，但这件事有两个经典的坑。

**怎么做**：改动之后等半秒再存。两个坑都堵了：
① 把当前工程的编号**先存进闭包里**，避免这半秒里你切了工程、结果旧图存进新工程；
② 切工程之前，先把还没存的那点改动补存掉，避免丢。

## 空画布差点把工程覆盖没——后来加了两道保险

**一句话**：这是真出过的事，讲出来有说服力。

**怎么做**：有一次在异常路径下（热更新换了组件、渲染失败、保存的时机撞上了），
画布把"零个节点"存了回去，而工程只有服务端一份。
之后加了两道互相独立的保险：
① **前端问一句**——上次存的时候有节点、这次要存零个，弹个确认框让你决定；
② **服务端留一份底**——覆盖之前先把上一版写进一个备份目录，每个工程留最近二十份。

有个取舍值得说：**服务端不拒绝空画布**。因为它没法判断"这个空的是用户真想清空，
还是界面出了毛病"——它不知道；留一份底是无条件的，也不依赖前端对不对。

**别人问起来怎么说**：
> 空画布覆盖过工程一次，之后加了两道保险：服务端在覆盖前留一份上一版、保留最近二十份；
> 前端在"上次有节点、这次要写零个"的时候二次确认。服务端不拒绝空画布，因为它判断不了
> 那是用户真想清空还是界面出了毛病。

**坑**：服务端留的那些底**只能人去目录里捞**，界面上没有入口能看到或恢复。

## 工程树的排序和拖拽

**一句话**：侧栏里工程能分文件夹、能拖顺序。

**怎么做**：每个工程有一个序号，拖拽排序的时候把"这一层完整的顺序"提交上去，数组下标就是新序号。
文件夹做了防环（顺着往上走，走一圈就拒绝）和同层重名检查。删文件夹的时候，
**里面的工程移回最外层而不是一起删掉**。

## 文档阅读器

**一句话**：侧栏一个按钮，能把仓库里的文档当文档站直接看。

**怎么做**：只读，两个接口。路径检查是写得最严的一处——强制要求路径以 `docs/` 开头，
从源头就让仓库根目录下的文件够不着，而不是靠后面再判断；用的是相对路径判断而不是简单的字符串前缀比较；
还额外解析了真实路径，防止软链接把读取引到别的地方去。

这个"字符串前缀比较"正是仓库里另外两处读文件的地方用的写法——那两处才是要注意的。

# 六、播放器

**一句话**：结果页里能直接播视频，能拖进度条、倍速、画中画、全屏。

**怎么做**：**没有引播放器库**，就是原生 `<video>` 加自己写的一层控件。
进度条用 Pointer Events 加指针捕获——这样拖出元素范围也还跟着走；缓冲条读的是浏览器报的缓冲进度。
快捷键按常见播放器的习惯配：空格播放、左右五秒（按 Shift 十秒）、上下调音量、M 静音、F 全屏。

两套外观：嵌在页面里的时候是浅色常驻控件条，全屏的时候切暗色、鼠标不动会自己隐藏。

一个交互细节：结果页点第 3 段，视频能跳到第 3 段对应的位置——靠的是播放器对外暴露的跳转方法。

**文件不在了怎么办**：服务端返回的不是一个空的 404，而是带上了这个素材的身份信息，
前端就地在原位渲染一个"重新下载"按钮。**"文件丢了"这个状态也有出口。**

# 七、界面是怎么搭的

## 组件库用了两个，分工是清楚的

- **Element Plus** 管应用外壳：按钮、输入框、对话框、表格、上传、消息这些标准件。
- **一套无样式的组件**（只给行为不给皮肤）只用在**节点里的浮层**：右键菜单、下拉菜单、悬停预览、模型下拉。
  因为这些浮层要跟画布的缩放和传送机制精确对齐，用带皮肤的组件反而对不上。

模型下拉那一处最麻烦（三百多行），要处理画布缩放下的坐标换算。

## 颜色只有一处来源

**一句话**：全项目的颜色写在一张表里，别处不许写死色值。

**怎么做**：一张设计变量表是唯一的颜色来源；Element Plus 也通过变量桥接到同一套色值，
所以页面里不会出现写死的色值，有自研的检查脚本拦着（比如 z-index 也走变量，不写裸数字）。

## 两个可以顺手清掉的东西

- **两套图标库并存**：一套用了三十个文件，另一套只在两个文件里出现——大概是历史遗留。
- **Tailwind 装了一半**：插件挂了、默认样式重置也生效了，但**模板里一个工具类都没用**（项目用的是自己的类名）。
  这事儿的麻烦是：你想删它，得先确认那个"默认样式重置"去掉之后界面有没有变样。

## toast 是我们自己写的（这条要认）

消息提示是自己写的，一对多的队列。这**和仓库自己定的规矩冲突**——规矩说"消息一律用组件库的"。
而且它没有条数上限、也没有去重，所以同一类错误会堆成好几条。被问到就直接认。

顺带一条相关的：画布里有三处会抛提示（两处是节点数量到上限、一处是自动布局失败），
**父组件一个都没绑定**——用户在界面上完全看不到这些反馈。这是"我们没做好的三件事"里的第一条。

# 八、体积和测试（一被追问就会问到这里）

## 打开首页要下载多少

**608.0 KiB**（压缩后，算的是首页直接引用的那几个文件——与仓库门禁 `docs-lint` 的 R9 用的是同一套算法）。
这个项目的自动检查里，620 KiB 是提醒线、650 KiB 是失败线——所以**离提醒线还有 12.0 KiB，离失败线还有 42.0 KiB**。

拆开看：

| 首页要下的东西 | 压缩后 |
| --- | --- |
| Element Plus 的 JS | 322.7 KiB（**占了一半多**） |
| 自己的 JS | 128.5 KiB |
| Vue Flow 的 JS | 69.8 KiB |
| Element Plus 的 CSS | 47.0 KiB |
| 自己的 CSS | 38.6 KiB |

**一半以上是 Element Plus**。仓库自己的注释里也写着："这条检查是拦回归的，不是目标值——根治手段是把它改成按需引入。"
它现在是全量引入的，CSS 有 360,839 B（压缩后 47,662 B），按需引入估算能省一半左右——**这条没做**，
风险在换的时候容易漏掉样式，改完得把界面再对一遍。

## 该按需加载的，确实都按需了

这两块大的都不在首页里：
- 思维导图那个包 681,727 B（压缩后 235,919 B）——**打开思维导图标签页才下载**。
- 算布局的 worker 文件 1,595,334 B（压缩后 466,809 B）——**点"自动布局"才下载**。

反过来说：**首页那 608.0 KiB 是确实要用的**，能动的主要就是 Element Plus 那 322.7 KiB。

## 测试这块我们做得不够（建议主动讲）

- 前端只有 **5 个测试文件、44 个用例**（数的是静态 `it(` 声明），而且**全是纯函数**（运行元信息与提醒、状态合并、分段推导、练一练解析）。
- **组件基本没测**：画布、节点外壳、结果页、推送客户端、播放器，一个都没有。
- 全项目两百多个用例里，绝大多数压在服务端。

这是这次分享最容易被打的一拳，主动说出来比被问出来强：**纯函数测了，组件没测**。
原因是组件测试要搭环境，而这个环境的浏览器模式刚转正，是下一步。

## 两个大文件

结果页那个视图三千四百多行、节点外壳三千行出头。被问到就说"正在拆，画布外壳是最难拆的一块"，
**别主动报数字**。

# 九、密钥（前端要知道的）

**一句话**：用户在设置页填各家密钥，**浏览器永远拿不到密钥本身**。

**怎么做**：
- 接口只回一个"填没填"的布尔值，**从不回密钥**。前端拿这个决定按钮该不该拦、该给什么提示。
- 输入框里还没提交的草稿，只放在会话存储里，**关掉页面就没了**，不写进本地存储。
- 请求是服务端的进程直接发的，浏览器不参与。
- 设置页还能拉一下模型列表，换服务商不用手打模型名。

**别人问起来怎么说**：
> 密钥填在设置页、存在服务端的本地数据库里。前端只拿得到"有没有填"这一个布尔值，拿不到密钥本身；
> 输入框里的草稿只放在会话存储里，关掉页面就没了。请求是服务端直接发的，浏览器不参与。
> 不同家的写法还不一样——有走标准请求头的，有另开一个头的，还有把密钥放请求体里的。

**坑（要认的）**：服务端存的是**明文**，没有加密；而且设置页**没法把密钥清空**（只能改成另一个值）。
另外有三个"测试连接"的接口，会把已经存好的密钥发到请求里给的那个地址去——用在自己机器上没问题，
**但别把这个服务暴露到不可信的网络里**。

# 后端那些，一句话就够

不是这次的主角。被问到，能说出"我们用什么、主流怎么做"就可以了。

| 一块 | 我们用的 | 主流怎么做 | 一句话怎么说 |
| --- | --- | --- | --- |
| 后端框架 | Hono | Express / Nest | 轻，自托管单用户够用 |
| 数据库 | 本地 SQLite 一个文件 | Postgres + 迁移框架 | 不用装数据库；代价是改表只能加列，没有迁移工具 |
| 备份恢复 | 整库备份到坚果云，恢复时不重启进程 | 停机恢复 | 恢复前会自动先备份一次，留后悔药 |
| 跑任务 | 进程内自己跑，节点级并发 | 消息队列 + worker | 单进程够用；代价是重跑等于整节点重跑，没有断点续跑 |
| 语音识别 | 全部走云，没有本地模型 | 对象存储 + 异步任务 | 一句"转写全走云"就行 |
| 视频文件 | 存本地，自己去重 | 对象存储 + CDN | 视频能拖进度条是服务端自己实现的断点传输 |
| 同步 | 自己写的 WebDAV 客户端 | 各家 SDK | 只用到五个方法；一层一层走，宁可报错也不漏文件 |
| 联网核查 | 两个搜索渠道，按来源权威度重排 | 直接用搜索结果顺序 | 实测权威页常常在候选里但排后面，所以问题在排序不在换引擎 |
| 鉴权 | **没有登录鉴权** | 会话 / Token | 定位就是本机自用；**别暴露到外网** |
