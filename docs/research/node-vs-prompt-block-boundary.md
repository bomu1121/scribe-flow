# 新功能该加一张卡片，还是加一个提示词

## 判断就两句

**是不是 AI 在干活？** 不是（查找替换、合并、下载、存文件、要你动手改稿）→ 加卡片。

**是 AI 干的？看料。** 料不变、只是换个处理方式 → 加提示词；料的样子变了（音频变稿子、一份变好几章、
稿子变导图），或者得出门拿/写东西（下载视频、上网查、存进第三方）→ 加卡片。

一句话记法：**卡片是工序，提示词是做法。** 工序要接料出料，料会变形或要出门；做法只是同一份料换个处理方式。
（还有第三种：几道工序的连法固定，那就是流水线——"新建工程"里选的那些。）

顺着这条看现有的东西，答案很直白：

- **溯源**：稿子进、报告出，只是处理方式不同 → 提示词。它要上网查一次，那是给这种做法加一句
  "顺手上网查"的声明，不用开卡片。
- **阴阳师攻略加工**：稿子进稿子出，也该是提示词，现在却占了一张卡片。这是唯一放错的一个。
- **AI 校对**：料也没变，按规则该是提示词；但它每份工程都要、不用挑，留在卡片上也没问题，是产品取舍。
- **思维导图 / 章节切分 / 知识巩固**：一份变导图、一份变好几章、一份变一套题 → 卡片，没错。

再补一条：**如果新能力和已有卡片只差"送到哪儿"**（Notion / 飞书 / 剪贴板），那不是新卡片，
是那张卡里多一个选项。

## 加卡片要付的两笔账

一是用户多学一个概念，而且收不回来——老工程里存下来的卡片，以后改它的行为还得保证它照旧能跑。
二是画布上多一个位置。查过的五家（n8n / Dify / Coze / ComfyUI / LangFlow）没有一家把垂直内容做成节点，
ComfyUI 社区还给这个病起了名字叫 node bloat。

加提示词没有这两笔账：写一段文案、起个名字，用户在「AI 加工」的下拉里就能看到。

## 现在唯一欠的一处

新加一种提示词、而它做出来的东西结果页认不出的时候，现在只能靠"翻正文找字眼"去猜——溯源就是这么被认出来的，
猜错就把报告摊成一张空表。补上这一处（让做法自己报一句"我做出来的是什么"，结果页照着这句话办事），
"加个提示词就能用"才算真正成立。**没做、也没验证。**

## 背后查过什么（需要时再展开）

- 五家产品的官方文档：内容型配方一律不占节点，组合复用一律走子图或子流程；**但没有一家给出成文判据**，
  所以这条只能自己定。
- 两边的代价：独立加一张卡片要动 23–26 个文件、1500–3100 行；加一种做法，代码里只有 2 个文件、
  服务端不用改。
- 我们自己的历史：上线头 15 天卡片从 8 张涨到 16 张，最近 17 天一张没加、提示词一直在加——
  这条分法其实已经在自发发生了。
