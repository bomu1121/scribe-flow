合集选集面板 —— 五套做法对照

同一张 B 站来源节点、同一个真实合集（美国时政 · 109 集 · 共 28.9 小时），只换选集面板的做法。 颜色与圆角引用 tokens.css 的令牌，卡片外壳与现状面板的尺寸照真机计算样式重画。 这是手写原型，不是 Element Plus 真实渲染，落地实现必须用 EP 组件 —— 来源、取舍、数字与诚实清单见 docs/research/collection-picker-research.md。

看哪几套

现状（基线）：常驻勾选框 + 点行切换，永远展开

本仓当前实现 .sf-node-picker。真机实测（probe-picker-geom.mjs，画布 zoom 0.5963）： 卡片 380×588，选集面板 320px（占卡片 54.4%）；列表限高 224px、行高 31.2px、 109 行；一屏只看得见 7.18 行（第 7 行只露 79%，像被切掉），看完要滚 16.15 屏。 当前视频是合集的第 109 集（最后一集），列表默认停在顶部、不定位当前项 —— 所以底部写着「已勾选 1 集」，但屏幕上根本看不见是哪一集。

2. 单轨两模式：浏览态没有勾选框，选中才出动作条（推荐）

依据一：Material 3 Lists 规范「一条列表同一时刻只能有一种选择模式」； 依据二：Material 3 Selection「选择是次要任务时，勾选框只在 hover 该项 或 选中任意一项之后 出现」； 依据三：Android 上下文操作栏 CAB——官方原文「you usually invoke the contextual action mode when … The user selects a checkbox or similar UI component within the view」，示例代码里动作执行完即关闭（mode.finish() // Action picked, so close the CAB.）。 于是：点行 = 切换当前来源、没有常驻勾选框；点「多选」才进选择模式，合并完成自动退出并收起。

5. 海报名片墙：一屏 24 格，专治「有没有值得看的这一集」

依据一：腾讯视频选集面板的实测尺寸 —— .episode-item 高 54px + margin 8px（宽 54px 来自组件内联样式的默认值，可被数据覆盖）， 当前项用「浅底 + 品牌色文字」（background: rgba(0,213,211,.1); color: #00d5d3），并配 isNeedExpand +「收起 / 查看全部」； 依据二：B 站自己的右侧合集会列表就有一支带封面的卡片式变体（.base-video-sections-v1 的 .video-episode-card）； 依据三：Apple TV 的下载流程把「整季 / 单集」并列成两个入口，而不是让人一集集找。 点格子切换当前集，鼠标悬停看标题。
