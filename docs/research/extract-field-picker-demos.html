这些属性会写进笔记头部（列表形式），也是「关联相关笔记」的比较依据；留空就不抽。

方案 A：全部收进下拉（建议 + 创建 + 常用组合） 推荐

参照：GitLab 的定时任务（原话「Select one of the preconfigured intervals, or enter a custom interval in cron notation」——预设与自定义在同一个字段里）＋ Notion 的选项（在列表尾部就地新建一个值）＋ Sentry TimeRangeSelector（输入即生成选项）。形态归类与全部出处见同目录调研文档的 §2。

▾

会写进笔记头部，也是「相关笔记」的比对依据；一个都不选就不抽。

好在哪

  • 一个控件说完全部：建议、创建、常用组合都在下拉里
  • 点开有东西可选——不再是自己选自己
  • 键盘可全程操作（↑↓ 移动、回车选中/创建）

代价

  • 「常用组合」要展开下拉才看见，常驻入口没了
  • 建议列表要有内容才有意义（没有建议就是现状）
  • 一个真缺口：el-select 不会把创建过的值放回候选（ issue #11892 仍 open）， 第二次想选同一个词只能重打——要在 @change 里自己回填。本原型已按回填后的行为做， 所以你能看到「你自己加过的」这一组
  • 落地无阻碍：#footer 插槽自 element-plus 2.4.3 起就有，官方还带一个 「Footer of the dropdown」示例（页脚里放按钮），骨架可直接照抄
  • allow-create 必须同时给 filterable，否则静默失效且不报错
方案 B：属性做成一张小表（每行一个，能写说明）

参照：Notion / Airtable 的字段列表（选项就地新建 + 每个选项有名称与设置）、 VS Code 设置的来源标注与 Reset Setting（值级来源 + 恢复默认的动作）。

空的时候给一组起点，而不是常驻一个「换成：」。

好在哪

  • 每个字段有地方写「这个属性会抽什么」——现在全靠一条公共提示
  • 空列表时可以放引导，不再默认指向历史笔记
  • 以后要给单个属性加开关/类型，有位置放

代价

  • 竖向占位随字段数增长（3 个字段 ≈ 3 行）
  • 「挑一个已有的名字」这件事反而变慢，只能靠输入时的联想
方案 C：模板与结果分两级，手改后自动标「已改」

参照：Notion 数据库模板（套用＝一次性 stamp，之后只是值）、Airtable 单选的 Default option（官方写明「只影响新建记录」）、 Figma 变量模式的规则「显式指定过就锁定，默认/自动才跟随」——「已改」标记用的就是这条。

▾

模板名不再是一个空标签——卡片里直接写清它会抽哪几个字段。

好在哪

  • 「默认指向历史笔记」变成用户自己选的那一格，不再藏在默认值里
  • 手改之后卡片标「已改」，不会像现在这样静默失配

代价

  • 层级最深：模板 + 字段两行，加上开关一共三层
  • 多数人只想要「随便填几个词」，两张卡片是多余的
方案 D：不问字段名，问「你想按什么把笔记串起来」

这一版的出处弱一些：来自 Sentry TimeRangeSelector 的原则——自定义应当是「预设的生成器」， 而不是另一条独立的输入路径（Sentry PR #36624）， 以及 Stripe metadata 这个反面样本：纯自由填写零可发现性，用户不知道业界通用名字叫什么。 但「勾选维度」这个具体控件形态是我构造的，没有可直接对应的成熟设计，见调研文档的诚实清单。

还没选。

好在哪

  • 用户不必先想出一个字段名——那是这个功能最难的一步
  • 默认不再偏向任何一类笔记

代价

  • 看着比前三个都重，勾选项本身也是一份要维护的清单
  • 字段名与勾选项绑死后，「任意名字」的自由度靠自定义那一格兜
