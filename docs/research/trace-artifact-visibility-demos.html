「这枚卡产出的是另一类笔记」怎么让用户看出来

同一枚「AI 加工」节点、同一份文稿：一张选了「观点提炼 · 速览版」，另一张选了「信息溯源 · 上网查证」。 差别不在标题（标题本来就写的是做法名），而在于**产物是两类东西**：一片是普通笔记（`类型: 视频笔记`）， 一片是溯源报告（`类型: 溯源笔记`，会与同源笔记互链）。下面五套做法解决「这件事在画布上看得见吗」。

卡片照真机计算样式重画：320px 宽、标题 13px、描述 11px、运行按钮 24px， 「联网核查」那一行只有声明了需要联网的提示词才有（真机截图里就有）。

现状（基线）：两张卡的说明文字一模一样

两枚卡的描述都是「使用提示词对文稿做 AI 加工」——只有标题里的做法名不同。 用户看不出其中一枚的产物**是另一类笔记**（会带 `类型: 溯源笔记`、会与观点笔记互链）。

量中…

A：把描述行改写成「产出：…」

最省的做法——描述行本来就在那儿，只是现在写的是节点类型（对「AI 加工」来说两枚卡永远同一句）。 改成由**做法**声明产物：一眼看出这是报告，不是笔记。代价：描述行只有 11px 一行，长句子会被挤。

量中…

B：标题旁加产物徽章（dbt 的做法：materialization 用徽章/色条标出来）

产物的**类别**用一个短徽章表达，和做法名并排——扫一眼就知道哪些卡会出报告。 依据：dbt 里同一个「model」概念，`table / view / incremental / ephemeral` 决定了它产出什么， 而 DAG 视图正是用徽章与左侧色条把它标出来的（VS Code 的 dbt Lineage 扩展把配色列成了表）。

量中…

C：下拉里就标（在选择的那一刻告知）

用户是在**选提示词**那一刻做的决定，所以那里是告知的最佳位置：下拉项右侧一个短标（`报告` / `笔记`）。 代价：下拉是通用组件（Element Plus），加后缀要确认能做到、且不挤坏长名字。

量中…

D：把话说到用户真正关心的地方——出口卡上预告「会写出哪几篇」

用户关心的是「库里会出现什么、它们是什么关系」，而不是某张节点内部怎么算。 所以预告放在 **Obsidian 笔记卡**上：一眼看出这次会落两篇、各是什么、且两篇互链。 这一处天然还回答了「保存目录」的问题（两篇会进同一个目录，还是会分头进）。

量中…

E：在连线上标产物（边上写清这条线送的是什么）

产物是**沿着边**流到下游的，所以标在边上也说得通，而且能顺带看出「哪条线送的是报告」。 代价：连线上的标注会随画布缩放变小/变糊，卡多了也容易糊成一片。
