# 设置页说明文字的排版：现状实测与四个候选方案

> 触发：用户看设置页的说明文字，说「用到粗体、符号的时候感觉很拥挤……整体不太协调，很不美观」，
> 并且要求**先调研已有项目的成熟做法，不要凭空捏造**，仍然要「多方案」。
>
> 交付物：同目录的 `settings-text-typography-demos.html` —— 现状照抄 + 4 个候选方案并排，
> 用设置页上的真实文案，宽度按真机的 454px（表单列 460px 减去 6px 余量），可切两个引擎级开关对比。
>
> 测量口径：所有数值都是**在运行中的应用里 `getComputedStyle` / `Range.getBoundingClientRect` 实测**的
> （环境：Chrome 146），不是从源码里读出来的推测。外部依据见 §5，逐条给了出处。

## 1. 现状：不是"感觉拥挤"，是三套尺度并存 + 两类元素没有样式

在设置页上实测到的数值：

| 类名 | 用在多少处 | 字号 | 行高 | 颜色 | 外边距 |
| --- | --- | --- | --- | --- | --- |
| `.sf-field-hint` | 20 | **11px** | 17.6px（1.6） | `--color-text-tertiary` 三级灰 | `2px 0 0` |
| `.sf-settings-hint` | 12 | **14px** | 22.4px（1.6） | `--color-text` 正文黑 | `0` |
| `.sf-settings-desc` | 32 | 13px | 20.8px（1.6） | `--color-text-secondary` 次要色 | `4px 0 18px` |
| `strong`（行内加粗） | — | 继承 | 继承 | 继承 | — |
| `code`（行内代码） | — | 继承 | 继承 | 继承 | — |

两个结构性问题：

1. **`.sf-settings-hint` 这个类名根本没有 CSS。** 它在 `SettingsView.vue` 里用了 12 处，但全仓库
   （`styles/*.css` 与所有组件的 `<style>` 块）没有任何规则匹配它——那 12 段是靠 `body` 的默认值渲染的：
   14px、正文黑。于是同一页里"说明文字"有 11px 三级灰、13px 次要色、14px 正文黑三种样子。
2. **`code` 与 `strong` 也没有任何规则。** 行内 `code` 只拿到浏览器默认的等宽字体，于是字号跟着段落走
   （同页里一会儿 11px、一会儿 14px），且没有背景/内边距/圆角，和正文之间没有任何视觉分隔。
   `strong` 是默认的 **700**——中文没有真粗体，700 靠合成加粗，在 11px 上会糊。

另外两条量出来的边界值：11px 的行高只有 **17.6px**；一行约 **41 个全角字**（454 ÷ 11）。
按 clreq 给的行长参考（正文 17–40 字、横排上限 48 字），**41 字已经贴到上限区**——
这本身也是"字号该往上提一档"的理由：12px 时一行约 38 字、14px 时约 32 字，都更接近舒适区。

## 2. 引擎能给的东西（`text-autospace` / `line-break` / 不要碰 `text-spacing-trim`）

用户说的"符号拥挤"里有一部分**不用改文案、也不用改字号**，可以交给排版引擎。

**`text-autospace`（中西文自动间距）** —— 逐句实测（12px）：

| 文本 | 关 | 开 | 差 |
| --- | --- | --- | --- |
| `AI泡沫` | 34.94 | 36.44 | **+1.5** |
| `话题/AI泡沫` | 63.61 | 65.11 | **+1.5** |
| `中文English混排2026年` | 123.5 | 129.5 | **+6**（四处边界 × 1.5） |
| `UP 主与话题标签是自动加的，`（本来就手打了空格） | 162.27 | 162.27 | **0** |

三条必须知道的前提（缺一条就会白写这行 CSS）：

- **四家引擎的初始值都是 `no-autospace`**，而规范写的是 `normal`——**不显式声明 `text-autospace: normal` 就不生效**。
- 支持面是 **Chrome/Edge 140+、Firefox 145+、Safari 18.4+**（Baseline 2025，2025-11 起 newly available），
  老版本浏览器要留"手打空格"兜底。
- **它只在没打空格的地方补**（0px 那一行就是证据）。所以对现有文案收益接近于零——现有文案基本都手打过空格了。
  它的价值是**兜底**：以后新写的文案忘了加空格时不用人工挑。

插入量本身：clreq 给的参考值是 **¼ 汉字宽**（12px 下 3px），而实测引擎给 **1.5px = 1/8 汉字宽**——
差异是正常的，**CSS 规范与 Unicode 都故意不定义具体数值**，各实现落在 1/6–1/4em 之间。

**`line-break: strict`** —— clreq 的行首行尾禁则要求点号与结束括号不得出现在行首，这一条对应到 CSS 就是它。
**建议常开**（对照页里已经常开）。

**`text-spacing-trim`（全角标点挤压）—— 现在不要上**：MDN 标它 not Baseline / experimental，
而且**字体必须带 `halt` / `chws` OpenType 特性，否则属性直接被忽略**。对照页里留了开关只为看效果。

## 3. 四个候选方案

都在对照页里，内容宽度与真机一致。

| | 做法 | 改动量 | 实测（说明文字 / 行高 / code） |
| --- | --- | --- | --- |
| **现状** | —— | —— | 11–14px 三套 / 1.6 / 12px 无底色 |
| **A 收敛** | 三套合并成一套：全部 **12px / 1.75 / 次要色**；`code` 补底色 + 内边距 + 圆角；`strong` 降到 600 | 几条 CSS | 12px / 21px / 11.4px 有底色 |
| **B 分档**（推荐） | 说明 **12px**、正文 **13px**，行高都 **1.8**；`strong` **600 + 加深到正文色**；`code` 用底色药丸、**不缩字号**、**不用等宽字体** | 同上，文案不动 | 12px / 21.6px / 12px 有底色 |
| **C 不缩字号**（antd 派） | 说明保持 **14px / 行高 22px**，只把颜色降到 45% 黑；`code` 缩到 85% + 1px 边框 + 3px 圆角 | 几条 CSS | 14px / 22px / 10.2–11.9px |
| **D 结构化** | 数值同 B，但把最长的两段拆成「一句话结论 + 要点」 | 要改文案 | 同 B（另加列表） |

几个取舍的理由（每条都能对到 §5 的出处）：

- **为什么不能停在 11px**：11px 的中文笔画已经挤在一起（行高只有 17.6px），而说明文字是要读的。
  12px 有直接的同侪依据：antd 的 `fontSizeSM` = 12/20、Radix 的 size 1 = 12/16、
  飞书的引导语档是 12px、Element Plus 也有 `--el-font-size-small: 13px` 与 `extra-small: 12px`。
- **行高 1.75 / 1.8**：clreq 的原文是「版心之行距多半介於文字尺寸之 **50%–100%** 之間」，
  并补了一句**「當行長較短、或文字尺寸較小時，行距設定也會相對較小」**——我们正是"行短 + 字小"，
  所以取区间偏小的那一侧是符合规范的。另有一道地板：WCAG 2.2 SC 1.4.12 要求
  在用户覆盖到"行高 ≥ 1.5 倍"时内容不能坏，1.75/1.8 在这个地板之上。
- **`strong` 从 700 降到 600**：600 是绝对主流（Tailwind Typography 的 `strong: 600`、antd `fontWeightStrong: 600`、
  GitHub `--base-text-weight-semibold`、shadcn `font-semibold`）；飞书更严格，正文只允许 400/500。
  再加一条**机制性**修正：`font-synthesis-weight: none` 可以禁止浏览器在中文字体缺粗体时"合成"加粗——
  这比只降字重更治本（笔画的糊是合成出来的）。
- **`code` 不缩字号、不用等宽字体**：等宽字体没有中文字形，浏览器会**按字符回退**到另一套字体，
  于是同一段 `code` 里的中文与拉丁字符度量不一致（这是"拥挤/不协调"的机理，出处见 §5）。
  至于缩字号：GitHub 与 antd 都是 **85%**，但那个比例是给 14–16px 正文用的（→ 11.9–13.6px）；
  我们的说明文字只有 12px，照 85% 会掉到 **10.2px**——所以 B/D 取 **1em**，只在 C（14px 那派）里才适合用 85%。
  底色 + 内边距 + 圆角则是主流做法（GitHub 6px 圆角、antd 3px + 1px 边框、shadcn 4px、
  Radix 默认 soft 变体带底色）；只有 Tailwind Typography 不加底色，改用前后各一个反引号。
- **行长**：见 §1 末尾——把字号从 11px 提到 12px，一行字数就会从 41 降到 38，往 clreq 的舒适区靠。

## 4. 推荐

> **实施记录（2026-10-13）**：用户选了方案 B，已落地——`.sf-field-hint` 与 `.sf-settings-hint` 合并成
> `.sf-hint`（32 处），尺寸进令牌（`--text-help-size: 12px` / `--text-body-size: 13px` / `--text-leading: 1.8`），
> 行内 `code` 给底色药丸 + 跟随正文字体 + 不缩字号，全局 `strong/b { font-weight: 600; font-synthesis-weight: none }`，
> `body` 上 `text-autospace: normal` + `line-break: strict`。
> 落地后的实测：帮助文字 12px/21.6px 三级灰、说明段 13px/23.4px 次要色、加粗 600 + 禁用合成 + 正文色、
> code 12px + 4px 圆角 + `no-autospace`；按钮/标签/徽章没有被全局规则挤坏。
> 方案 C（antd 的"不缩字号"）与 `text-spacing-trim` 都**没有采纳**，理由见下。

**B**，落地时一次做完这五件事：

1. **`.sf-settings-hint` 要么补规则、要么与 `.sf-field-hint` 合并成一个类名**（现在两个名字干同一件事，
   其中一个连规则都没有——这是"同一页几套观感"的直接原因）。
2. **字号收敛到两档**并在 `tokens.css` 里命名（如 `--text-help: 12px` / `--text-body: 13px`），
   否则下次加新段落又会各自为政。
3. `strong`：`font-weight: 600` + `font-synthesis-weight: none`。
4. `code`：底色 + `padding: 1px 5px` + `border-radius: 4px`（用仓库的圆角令牌）+ `font-size: 1em`
   + `font-family: inherit`；代码里显式 `text-autospace: no-autospace`（它可继承，代码里自动加空会改变观感）。
5. 全局：`text-autospace: normal`（显式，否则不生效）+ `line-break: strict`。
   **不要**上 `text-spacing-trim`。

C 是另一条路（不缩字号、层级只靠颜色），它的代价是同一个设置页的竖向占位会涨两成以上——
要不要走这条路取决于你更在意"读得舒服"还是"一屏能看更多"。A 是 B 的保守版（只收敛不分档），
D 是 B 的结构版（数值相同、把长段落拆开），两者都能叠在 B 之上。

## 5. 外部依据（逐条给出处）

**W3C《中文排版需求》clreq**（中文编辑草案：https://w3c.github.io/clreq/zh/ ，英文 TR：https://www.w3.org/TR/clreq/ ）

- **行距**：「版心之行距多半介於文字尺寸之 50%–100% 之間，當行長較短、或文字尺寸較小時，行距設定也會相對較小。」
  → `line-height` 1.5–2.0，且小字/短行可取小值。**这是本次行高取值的规范依据。**
- **中西文间距**：「原則上，漢字與西文字母、數字間使用四分之一個漢字寬的字距或空白。但西文出現在行頭或行尾時，則毋須加入空白。」
- **行首行尾禁则**：点号（顿号/逗号/句号/冒号/分号/叹号/问号）与结束引号、结束括号不得出现在一行之首 →
  对应 `line-break: strict`。
- **行长**（clreq issue #608 的讨论邮件，r12a 2024-03）：书籍正文常见 **17–40 字**、最小不宜少于 10 字、
  横排上限 **48 字**。**注意：「每行 30–40 字」这个流行说法我没有找到一手出处**，不采用。
- **段间距**：clreq 的书籍体例是"段首缩进 2 字、段间不加间距"。屏幕 UI 用段间距是**我的判断**（缩进在窄栏、
  卡片、中英混排里会失效），不是规范结论。

**`text-autospace` 的实现现状**：MDN 记 Chrome/Edge 140、Firefox 145、Safari 18.4，四家初始值均为
`no-autospace`（https://developer.mozilla.org/en-US/docs/Web/CSS/text-autospace 与 MDN BCD）；
CSSWG issue #7050 把规范里"1/4em"的措辞改成了不给量（理由是 1/4em 常常太宽、Apple iOS 用 1/6em）；
Unicode UTR #59 也明确不定义具体数值。

**`text-spacing-trim`**：MDN 标 not Baseline / experimental，
且「字体必须带 `halt` 或 `chws` 特性，否则属性被禁用」——所以本次不建议上。

**Tailwind Typography v0.5.16 源码**（https://cdn.jsdelivr.net/npm/@tailwindcss/typography@0.5.16/src/styles.js ）：
body `line-height: 1.75`、段落间距 `1.25em`、行内 code **`font-size: 1em`（不缩）+ 无底色 +
`font-weight: 600` + 不指定等宽字体**、前后各加一个反引号、`strong: 600`。

**其它设计系统的取值**（这一轮抓到的一手材料）：

| 系统 | 说明文字 | 行内 code |
| --- | --- | --- |
| antd v5 | Form `help`/`extra`：**14px / 22px** + 45% 黑（**不缩字号**）；另有 `fontSizeSM` 12/20 档 | 85% + `rgba(150,150,150,.1)` 底 + `0.2em 0.4em` 内边距 + **3px 圆角** + 1px 边框 |
| GitHub（Primer） | 文档正文 16px/1.5，没有小字档 | **85%**（16px→13.6px）+ `#818b981f` 底 + `.2em .4em` 内边距 + **6px 圆角** |
| Radix Themes | size 1 = **12px/16px**（官方指定 UI label 用 1–3 档） | soft 变体带底色，字号 `adjust × 0.95`，**圆角随字号缩放** |
| shadcn | `text-sm` 14px + `text-muted-foreground` | 0.875rem + `bg-muted` + `0.3rem/0.2rem` 内边距 + **4px 圆角** |
| Element Plus 2.14.5（本仓库装的） | **`--el-font-size-small: 13px` / `extra-small: 12px`**，次要色 `#909399` | 没有内联代码组件，需自建 |

**加粗**：600 是主流（Tailwind / antd / GitHub / shadcn）；Radix 用 `highContrast` 而不是加粗，飞书正文只允许 400/500。
`font-synthesis-weight: none` 可禁止合成加粗（MDN，Baseline 2023）。

**等宽字体里为什么中文难看（机理）**：Latin-only 的等宽字体没有 CJK 字形，浏览器**按字符回退**，
该字符的 advance 由回退字体决定，于是同一行里出现两套度量。旁证：UAX #11 说字形宽度由字体决定；
clreq issue #511「Fullwidth is not equivalent to em」；思源等宽的 CJK:Latin advance 是 1000:667（≈3:2）
而不是 2:1（Adobe 官方技术说明）。

## 6. 诚实清单

- **方案 C 的"竖向占位涨两成以上"是估的，不是量的**：我按字号 14/12 与行高 22/21.6 的比例算的，
  没有把四个面板的实际高度逐个测出来对比。
- **段间距用 margin 而不是首行缩进，是我的判断**：clreq 的书籍体例是缩进 + 段间不留白；
  换成段间距属于按媒介换体例，规范本身没有为屏幕 UI 背书。
- **`text-spacing-trim` 的效果我没量**：它对单行宽度为 0（只在行首/行尾生效），我只有"属性被引擎接受"这一个事实；
  加上 MDN 的 not Baseline 与字体特性前提，本次直接不建议上。
- **那些 HTML 片段里的取值是"同侪做法"，不是逐字抄的规范**：3px/6px 圆角、`0.2em 0.4em` 内边距这些
  我按各家公开值照抄，但**没有在真机上逐个复现它们的观感**。
- **四个方案都没有做过用户测试**，判断依据是上面那些实测数值 + 出处 + "同一页只应有一套尺度"这个原则。
- **没有抓到一手 CSS 的**：Stripe、Linear、Vercel 的具体数值（Linear 的第三方来源互相矛盾：14/15/16/17px 都有，
  我判定不可用，因此不引用）。飞书的字号/行高表在官网是图片，只有字色可引。
