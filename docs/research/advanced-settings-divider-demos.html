为什么现在这条线会显得「丑」

不是粗细或颜色的问题，是层级用错了。Material 对分隔线分了两类用途：

官方原文说的是哪一类
"separate larger sections of unrelated content"、"separate interactive areas from non-interactive areas"满宽 线（我们现在这种）
"separate related content within a section"，默认「两侧等距内缩」内缩 线（V6）

我们这条线是满宽、画在同一张卡的表单区中间、两边是同一组设置——按上表它干的是「分隔无关大段落」的活， 所以读起来像「把卡片切断」而不是「这里开始新段落」。Carbon 有句同类的告诫："The divider should not be used to separate every switcher item."

另一条路在系统级文档里更直接：密集设置区用间距 + 小标题分节，不画线—— Windows 11 官方设置页示例里的区块标题就是「Margin="1,30,0,6" + 小标题」，注释写明 "following the correct Windows 11 design specifications for things like spacing, section headers"； GNOME HIG 写「each list can be given a heading」；libadwaita 的 AdwPreferencesGroup 本身就是 title + description、不画线。 这就是 V2。

图怎么来的：往运行中的应用注入一份覆盖样式（组件的样式是 scoped 的，注入时把选择器抬到同等特异性）， 把画布缩放到 3.31 倍，按设计像素裁出「分界线附近」这块；截图前临时隐藏了画布右下角的小地图与缩放控件。
V2 已落地（2026-10-14）：其余五套的样式只存在于那次渲染进程里，仓库里现在跑的是 V2（V1 那张图是改前的样子）。高度与间距是脚本量的（设计像素）， 不是从图上读的。视觉判断由我逐张看图得出：独立 visual-judge 额度冷却中（明天 09:12 恢复），这次没能跑。
