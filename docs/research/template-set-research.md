# 内置链路（模板）调研

**问题**：`packages/shared/src/templates.ts` 里的内置链路该怎么改名、删哪些、加哪些？

调研分两路：① **本机数据**——用户自己有 24 个工程、114 次运行记录，这比任何推测都硬；
② **同类产品对标**——看「音视频 → 笔记」这条赛道上别人把什么当成标配产出。

> 本文只记录调研过程与证据，拍板结论见 [decisions/template-set-and-source-axis.md](../decisions/template-set-and-source-axis.md)。
> 所有本机数字都可在 `apps/server/data/scribe-flow.sqlite` 上用同一条 SQL 复现（见 §1.4 复现方式）。

---

## 1. 本机数据（实测）

数据来源：`apps/server/data/scribe-flow.sqlite`，查询时间 2026-09-29。
口径：`projects` / `runs` / `run_node_results` / `run_node_inputs` 四张表，均为只读查询。

### 1.1 哪些模板真被用过

| 模板（旧名） | 是否有工程在用 | 工程里的实际形状 |
| --- | --- | --- |
| 视频转笔记（单线） | ✅ 4 个工程 | 与模板一致 |
| 视频转思维导图 | ✅ 1 个工程 | 与模板一致（但末尾还挂着「输出」节点，旧版遗留） |
| 视频转 Obsidian 笔记 | ✅ 3 个工程 | 都被用户改过：加第二份来源、加思维导图分支 |
| 文稿转阴阳师攻略笔记（核对版） | ✅ 3 个工程 | 全部用 `source.text` + 攻略加工，没有一次走视频 |
| 视频转练一练 | ⚠️ 未直接用 | 用户自建了一条：`flow.pick + prompt ×2 + drill` |
| 视频多路笔记 / 文稿多路对照 | ❌ 0 | 用户自建了等价物：一份文稿挂 6 个「AI 加工」（对比 5 个不同提示词块） |
| 文稿转笔记 / 文稿转思维导图 / 文稿转 Obsidian 笔记 / 视频转阴阳师攻略笔记 | ❌ 0 | 从未被使用 |

**11 个模板里有 6 个零使用**，而零使用的这 6 个恰好都是「另一份同形状模板换个来源」——
说明「视频版 / 文稿版」成对铺开并没有换来选择，只换来了一张更长的列表。

### 1.2 模板没示范到的节点，用户就不会用

全库 `run_node_results` 里各节点类型出现过的次数：

| 节点 | 出现次数 | 说明 |
| --- | --- | --- |
| `flow.if` 条件分支 | **0** | 模板里从来没示范过它 |
| `process.chapter` 章节切分 | 1 | 用户在一次手工搭的链路里试过一次 |
| `process.text` 文本工具 | 1 | 同上 |
| `process.merge` 合并 | 2 | 其中 1 次是 API 验收脚本 |
| `flow.pick` 素材挑选 | 2 | 自建链路里用过 |
| `source.file` 本地文件 | 1 | 自建链路里用过 |

节点总表里有 16 种节点，模板只覆盖了其中 8 种。**没有模板示范的能力（条件分支、分章、文本工具）
在真实使用里等于不存在**——这跟「面板里有卡片」是两件事。

### 1.3 一次 53 连败暴露的真实需求

有一个工程 53 次运行、**0 次成功**，失败文案集中在一条：

```
52 × process.transcribe  error  没有可转写的音频输入
```

它的画布是这样的（从 `graph_json` 还原）：

```
n_src(source.bili, url 空) ──▶ n_asr(转写) ──▶ n_refine ──▶ n_prompt ──▶ n_obsidian
n_mtmrvar3002(source.bili, url 空)      n_mtmrfyb6001(转写)     ← 这两个节点没有任何连线
```

用户想做的事很清楚：**两个视频 → 各自加工 → 一份笔记**。他加对了节点，却没有连上线——
画布不会提示「这个节点没有连线」，运行也不会因此拒绝，于是 53 次运行全部失败在同一条链路上。

由此得到两条对模板的要求：

1. 「多素材合并成一篇」是真实存在、且用户**自己搭会翻车**的形状 → 该内置。
2. 「孤立节点不报警」是画布交互的问题（不在本次范围），但它解释了为什么模板要尽量给出可直接运行的完整形状。

### 1.4 复现方式

```bash
cd apps/server && node --no-warnings -e "
const {DatabaseSync}=require('node:sqlite');
const db=new DatabaseSync('data/scribe-flow.sqlite',{readOnly:true});
console.table(db.prepare('select node_type,status,count(*) c from run_node_results group by node_type,status').all());
"
```

模板使用情况则是把 `projects.graph_json` 解析后对 `nodes[].type` 做去重统计（未落库为脚本，属一次性查询）。

## 2. 同类产品对标（外部调研）

看的是「别人默认给你什么产出」——因为用户不会提自己没见过的东西。

| 产品 | 默认产出（Studio / 模板） | 对本次的意义 |
| --- | --- | --- |
| 通义听悟 | 章节速览、全文摘要、发言总结、要点回顾、**待办事项**、思维导图、关键词 | 待办/行动项是会议场景标配，我们完全没有 |
| 飞书妙记 | 结构化章节纪要、自动总结、**待办提取（可指派）**、关键词、跳转到对应时间 | 同上；「跳转时间戳」需要 ASR 给时间戳，我们没有（见 §4） |
| NotebookLM | Reports（Briefing Doc / **Study Guide** / FAQ / Timeline）、Mind Map、Flashcards、Quiz、Audio Overview | Study Guide/Quiz 对应我们的「练一练」；**Timeline** 对应我们缺的「时间线」 |
| n8n 模板库（热门） | YouTube 元信息 → 下载音频 → Whisper 转写 → LLM 摘要 → 写 Notion / 本地 Markdown；一个工作流**批量处理多个视频** | 「批量多素材 → 汇总」是热门模板的常见形状 |

| BiliNote 等中文开源工具 | 多种笔记风格（含小红书、会议纪要、学术）、**带时间戳章节**、术语表、行动清单、一键进 Notion/Obsidian | 术语表/行动清单是通用产出；社媒文案偏创作者向 |

两条结论：

1. **「待办 / 行动项清单」和「外语内容中文化」是我们完全空缺、而同类产品当标配的产出**（后者是中文受众看英文字幕视频时的刚需，对标产品里没有直接对应项，属中文场景的推论）。
2. 通用产出的**结构**部分（章节、导图、题目）我们已有节点；**缺口在链路形状**（多素材合并、分章、选段），不在节点数量。

### 2.1 一条逐字核验过的样本

上面 n8n 那一行不是摘要转述，实际打开过页面：
[n8n #11083「Transcribe YouTube Videos & Create GEO Summaries with Whisper and GPT-4o-mini in Notion」](https://n8n.io/workflows/11083-transcribe-youtube-videos-and-create-geo-summaries-with-whisper-and-gpt-4o-mini-in-notion/)。
它的节点顺序是：定时触发 → 取视频元数据 → 下载音频 → Whisper 转写 → **IF 校验（没有转写结果就跳过）**
→ **Merge（把转写与元数据并到一起）** → GPT-4o-mini 出结构化摘要 → 解析 JSON → 写入 Notion。

两个点值得记下来：① 它是一个**批量**工作流（按计划跑、一次多条目），
所以「多素材 → 合并成一篇/一批」在成熟工作流里是默认形状；② 它用到了 IF 与 Merge 这类路由/汇合节点——
我们这两类节点都有，但模板从没示范过（见 §1.2）。

### 2.2 调研局限（诚实清单）

- 除上面那一条外，外部产品部分来自**检索摘要**，没有逐条打开官方文档核验；产品功能可能已变化（检索时间 2026-09-29）。
- 「用户需要什么」这一层，本机数据只能说明**这位用户**的使用习惯（24 个工程、114 次运行），
  样本里还混着 6 个明显是验收/复现用的临时工程；不能当作所有用户的行为。
- 「模板没示范到 → 用户不会用」这条结论，是从节点出现次数反推的，没有做 A/B 对照；
  因果链是合理的推测，不是实测出来的因果。

---

## 3. 结论

1. **模板不该按来源成对铺开**：11 个模板里 6 个零使用，全部是「同形状换个来源」；
   而用户真正需要「换个来源」时，是自己在画布上改来源节点的。
2. **该按「加工路径的形状」组织模板，来源在创建时选**：同一份链路对 B 站视频、本地文件、
   粘贴文稿都成立——因为链路真正开始的节点是「AI 校对 / AI 加工」，不是来源节点。
3. **要补的是形状，不是节点**：多素材合成一篇（用户已用 53 连败证明他需要）、分章、选段。
4. **要补两个产出块**：行动项清单、外语内容转中文——同类产品的标配产出里我们唯一空缺的两类。

具体清单与取舍见 [decisions/template-set-and-source-axis.md](../decisions/template-set-and-source-axis.md)。
