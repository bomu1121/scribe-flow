设置页「说明文字」的排版 —— 现状对照与候选方案

同一个设置页里，说明文字现在有三套尺度和三档颜色。下面用设置页上的真实文案并排比， 宽度按真机的 454px（表单列 460px 减去 6px 余量）。

引擎级开关的实测（12px，量的是文本宽度）： AI泡沫 34.94 → 36.44（+1.5）｜ 中文English混排2026年 123.5 → 129.5（+6，四处边界各 1.5）｜ 话题/AI泡沫 63.61 → 65.11（+1.5）｜ UP 主与话题标签…（本来就手打了空格）162.27 → 162.27（0）。 引擎只在没打空格的中西文边界补 1.5px（= 1/8 汉字宽），已经打过的地方不重复补。
两条必须知道的前提：① 四家引擎的初始值都是 no-autospace（规范写的是 normal）， 不显式声明就不生效；② 支持面是 Chrome/Edge 140+、Firefox 145+、Safari 18.4+ （Baseline 2025），老版本浏览器要留手打空格兜底。
但 text-spacing-trim 现在不建议上：MDN 标它 not Baseline / experimental， 而且字体缺 halt / chws 特性时属性直接失效——这个开关留着看效果， 不要照它写进产品。

现状（照抄真机数值） 三项不一致

真机实测：.sf-field-hint 11px / 行高 17.6px / 三级灰（用了 20 处）、 .sf-settings-hint 14px / 22.4px / 正文黑（用了 12 处，而且这个类没有 CSS）、 .sf-settings-desc 13px / 20.8px / 次要色（用了 32 处）。 行内 code 与 strong 全仓库都没有规则。

改完这个路径会自动检查（只读本地文件、不联网），不用点按钮。

UP 主与话题标签是自动加的，你自己写的标签不会被改。标签只写二级（如 话题/AI泡沫）—— Obsidian 里按一级筛选会自动带上它下面所有二级。标签从哪来看下面的词库。

  • 三套尺度并存：11px / 13px / 14px，颜色也有三级灰 / 次要色 / 正文黑
  • 行内 code 只换了等宽字体，没有背景、没有内边距；字号跟着段落走，于是同一页里 code 一会儿 11px、一会儿 14px
  • strong 用 700 字重压在 11px 的中文上（中文没有真粗体，是合成加粗，小字上会糊）
  • 行高 1.6 → 11px 时只有 17.6px；中文比拉丁文需要更大的行高
  • 一行约 41 个全角字（454 ÷ 11）
方案 A：三套收敛成一套 改动最小

只做"对齐"：所有说明文字统一到 12px / 行高 1.75 / 次要色，给 code 与 strong 补上规则。

方案 B：分两档（说明 12px / 正文 13px）＋ 加粗降重、代码改药丸 推荐

说明文字 12px、正文 13px、行高都 1.8；strong 降到 600 并加深一档颜色（不靠笔画糊出来）， 另加 font-synthesis-weight: none 禁止合成加粗； code 给 背景 + 内边距 + 圆角、字号 1em（不缩）、不用等宽字体 （等宽字体没有中文字形，中文会按字符回退，同一段里出现两套度量）。 为什么不用 GitHub/antd 那个 85%：那个比例是给 14–16px 正文用的，我们这里只有 12px，乘 0.85 会掉到 10.2px。

方案 C：说明文字不缩小，只降对比度（antd 派） 另一流派
