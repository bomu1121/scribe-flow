# 节点手册

## 1. 先读这一节：所有节点共有的语义

### 1.1 端口类型决定能不能连线

`packages/shared/src/port.ts` 只有 4 种端口类型，连线合法性由 `canConnect` 单向判定：

| 目标端口 | 允许的来源端口 | 直白说法 |
| --- | --- | --- |
| `audio` | `audio` | 音轨只能接转写 |
| `transcript` | `transcript` | 文稿只能接文稿 |
| `noteBlock` | `noteBlock` | 笔记块只能接笔记块 |
| `noteDoc` | `noteBlock` 或 `noteDoc` | 笔记块与整篇文档都能接「文档」口 |

注意最后一行是**单向**的：`noteBlock → noteDoc` 可以，`noteDoc → noteBlock` 不行。所以「AI 加工」的产物能直接接输出节点，输出节点的产物接不回合并节点。

`flow.if`、`flow.pick`、`process.text`、`process.mindmap`、`process.obsidian`、`process.drill` 用的是**动态端口**：端口声明里带 `accepts`（可接 `transcript` / `noteBlock` / `noteDoc`），连线时按交集判定（`canConnectSpecs`），运行时按实际输入类型同型透传。总表里这类端口的括号部分就是它的 `accepts`。

### 1.2 多输入怎么合并

一张来源卡可以承载多个视频/分P；多个节点也可以连到同一个下游。汇入时的行为分三类：

- **逐项节点**（转写 / 校对 / AI 加工 / 攻略 / 练一练 / 文本工具 / 素材挑选）：**一个输入一份产物**，逐个处理，各自独立落库。所以「一个校对模块处理了 8 个输入」会得到 8 份结果，而不是一份合并稿。
- **压平节点**（合并 / 输出 / 章节切分 / 思维导图 / 条件分支 / Obsidian）：先把汇入的文本按**连接顺序**以空行合并，再处理成一份产物。
- **转写**特殊一点：它同时是逐项节点，又负责把音频文本化——8 个音频转写后是 8 份文稿产物，摘要形如 `8 个音频 · 12345 字`。

「连接顺序」是 `graph.edges` 里的顺序（即连线被创建的先后），不是画布上的视觉位置。这一条在排查「为什么合并出来的顺序不对」时是关键。

### 1.3 运行状态与产物

引擎实际写入的节点状态只有 5 种：`running` / `done` / `error` / `cancelled` / `skipped`。类型定义与数据库枚举里还有 `queued`，但引擎从不写它。

产物类型 4 种，与端口类型同名（`text` / `noteBlock` / `noteDoc` / `audio`）。产物摘要分两处：

- `preview`：文本类产物截断 320 字，用于画布上的悬停预览。**思维导图、输出、知识巩固三个节点不给 `preview`**（`process.mindmap` / `process.output` / `process.drill`），理由是原始 JSON 或长文档在卡片上是噪音，它们的摘要由 `summary` 承担，完整内容到结果页取。
- `summary`：一定会有一条（兜底为「完成」），如 `12 章 · 3.2 万字`、`条件成立 · 1200 gt 500`。

SSE 重连时补发的快照用的是另一套更短的 preview 口径（120 字单行），所以「刷新后看到的摘要」与「运行中看到的摘要」长度可能不同。

### 1.4 素材挑选（段级分流）

`data.pick` 的类型是 `Record<来源节点 id, 段标识[]>`，段标识由 `packages/shared/src/segment.ts` 生成：

- B 站素材：`bvid:<bvid>:<page>`（有 cid 无 page 时 `bvid:<bvid>:cid<cid>`）；
- 本地文件：`file:<fileId>`，缺 fileId 退到文件名、路径；
- 文本来源：`node:<来源节点 id>`。

**键写的是「来源卡」的节点 id，不是挑选节点的直接上游。** 两边必须同口径：界面按 `collectSegmentOptions` 的 `originNodeId` 写键，引擎在 `resolveInputs` 里用 `originSourceNodeId` 沿「一个输入一份结果」的链路把产物回溯到来源卡再查表。所以 `B站链接 → 转写 → 挑选` 这种中间隔了一层的接法照样生效——若按直接上游查，键必然对不上，而键对不上的语义恰好是「全部选中」，挑选会静默失效。回溯不出唯一来源卡时（多张卡分不清、或产物只带派生位置键）退回直接上游 id 再查一次，让来源卡直连挑选的旧工程配置照旧生效。

判定规则（`passesPick`）只有三条，但每条都是使用者会踩的坑：

1. **键缺失 = 该来源全部选中**（旧工程零迁移的行为）；
2. **空数组 = 全部排除**；
3. **没有段标识的产物一律通过**——合并后的文档、章节切分的每一章、思维导图这类「压平产物」都没有段标识，所以它们不受挑选影响。引擎按产出顺序补的兜底标识（`pos:<产出节点 id>:<序号>`）说的是「第几个产物」而不是「哪段素材」，所以同样按不可筛选处理。

被排除的素材**不会进入下游节点**，而不是「进入后被丢弃」：过滤发生在 `resolveInputs` 里。因此未选中素材的下游如果因此拿不到任何输入，会由下游自己报错（比如转写报「没有可转写的音频输入」），状态是 `error` 而不是 `skipped`。同一节点如果所有输入都被排除，运行前就会被拒绝，提示「素材挑选没有选中任何素材」。

从某个下游节点单独重跑（`scope=fromNode`）时，不在本次运行内的上游产物从最近一次成功运行还原，**段标识一起还原**——否则挑选拿到的是兜底位置键，一个都匹配不上，同样退化成「全选」。

两个附带效果：来源节点对「下游一个都不会消费」的素材**连下载都不做**，摘要显示「未被选中」；运行详情页会列出被排除的段，用来解释「共 8 段、本次只加工 2 段」。

想按段分流，**必须挑在压平节点之前**：段标识能穿过逐项节点（上面那一类），但到压平节点就终止了。

### 1.5 失败重试

只有 8 类节点会自动重试（`RETRYABLE_NODE_TYPES`）：`source.bili` / `process.transcribe` / `process.refine` / `process.prompt` / `process.chapter` / `process.gameguide` / `process.mindmap` / `process.drill`。本地节点（文本、合并、输出、条件分支、文本工具、素材挑选、Obsidian）失败重试没有意义，恒不重试。

次数与退避来自节点数据 `data.retry`：`maxRetries` 默认 2、`backoffMs` 默认 3000，退避是**线性**的（第 N 次等待 `backoffMs × N`）。

是否重试**不看 HTTP 状态码**，而是按错误文案黑名单判定（`isRetryableError`）：取消、未配置密钥、空输入、正则非法、B 站登录失效、断言未通过、JSON 不合法这类属于永久性错误，不重试；超时、网络失败、5xx/429 一律重试。所以「AI 接口 429」会重试，但不会因为 `Retry-After` 而延长等待。

每次尝试都会累加 `attempts` 并写库，结果页在重试过的节点上显示「重试 N 次」。

### 1.6 运行前预检 vs 运行时兜底

启动运行时会先做预检（`apps/server/src/routes/runs.ts` 的 `createRun`），失败直接 400 拒绝，不会跑一半才失败：

- **AI 密钥**：判定范围是本次 scope 内是否存在 `process.refine` / `process.prompt` / `process.mindmap` / `process.drill`；
- **ASR 密钥**：判定是否存在 `process.transcribe`；
- **B 站链接为空**：`source.bili` 既没有 url 也没有 bvid 也没有多选 items；
- **同一工程只允许一个运行中**：已有 `running` 时拒绝再次启动。

**注意 AI 预检没有覆盖 `process.chapter` / `process.gameguide` / `process.obsidian`**：这三个节点缺密钥时不会被预检拦住，而是跑到该节点时才失败（错误文案「未配置 AI 模型密钥，请到设置页填写」，且不重试）。配置齐全时这条差异没有影响；只配了一半密钥时，表现为「运行能启动、但中途卡在某个节点」。

## 3. 来源类

三种来源节点的共同点：**没有输入端口**，只能作为起点；产物都会带上素材段标识，因此可以被下游挑选。

### `source.bili` B站链接

**卡片上能填什么**

| 字段 | 说明 |
| --- | --- |
| 链接（`url`） | 粘贴 B 站链接即解析（含 BV/av 号、`b23.tv` 短链；前端 500ms 防抖）。非 B 站链接会内联报错 |
| 分P / 合集两条轨道 | **点某一行 = 把节点切到那一集/那一P**（当前项用底色标出）；**勾选框 + 底部「合并为一张卡片」= 多选合并**（勾选不足 2 项时按钮禁用并写明原因） |
| 多选卡片（`items`） | 合并后卡片显示「N 项」，可「改选集」回到选集界面重新编辑，且不会清掉已合并的选集 |
| `keepVideo` | 高级设置里的「保留可播放视频」开关，默认关。开启后额外下载并合成可在结果页直接播放的 mp4 |
| `videoQn` | 清晰度档（360P/480P/720P/1080P，默认 1080P），只在开了 `keepVideo` 时有意义 |

**执行语义**：单链接卡下载 1 条音轨；多选卡逐个素材下载，**每个素材一份音频产物**（各自的段标识不同）。音频下载固定走最低码率音轨（`downloadBiliAudio` 固定 `qn=64`），再 FFmpeg 转 16k 单声道 wav 给 ASR——清晰度档只影响「保留可播放视频」的那份文件。

**摘要**：`N 个音轨已就绪`（多选、可选带「另跳过 N 个未选中素材」）或 `音轨已就绪`（单链接）；素材被下游全部排除时是 `未被选中`（此时不做下载）。

### `source.file` 本地文件

上传（或拖拽）音视频，白名单扩展名 `mp4 / m4a / mkv / flv / mov / wav / mp3 / aac / webm / m4v`，单文件上限由 `MAX_UPLOAD_MB` 决定（默认 2048MB）。卡片显示文件名与大小。

**执行语义**：把原件 FFmpeg 转成 16k 单声道 wav；开了 `keepVideo` 时额外准备可播放视频——`.mp4` 且 ffprobe 报告 h264 的**直接引用上传原件（零拷贝）**，其余转码归一化后进媒体库。没上传文件就运行时失败：「请先上传本地音视频」。

### `source.text` 文本

一段多行文本（卡片上显示「已输入长度 / 50000」计数）。**这个 50000 只是前端的输入提示，服务端与 schema 都没有长度上限。**

**执行语义**：直接作为 `transcript` 产物输出，摘要 `N 字`。即便只有一份文稿，也带段标识（`node:<节点 id>`），所以多份文稿连到同一个下游时依然可以挑选。

## 4. 转写

### `process.transcribe` 转写

卡片上只有一个「ASR 引擎」下拉：`MiMo-V2.5`（默认）或 `OpenAI 兼容`。地址与密钥来自设置页的「语音识别」组，节点数据里的 `asrUrl` / `asrKey` 字段存在但没有 UI 入口。

**执行语义**：逐个音频转写（`1/N` 进度），每次结果写回该输入在 `run_node_inputs` 里的文本，以便结果页按段查看。任一音频转写结果为空即整节点失败（「第 N 个音频转写结果为空」）。摘要 `N 个音频 · 总字数`。

**产物**：每个音频一份 `text` 产物——注意是**多份**而不是一份合并稿，合并发生在下游的压平节点里。

## 5. AI 加工

这一组里有 6 个节点，它们的区别只在「用哪套提示词、产物是什么类型」。前四个共用同一个执行分支（`engine.ts` 的 `case "process.gameguide"/"process.refine"/"process.prompt"/"process.drill"`），行为差异由节点数据决定。

### `process.refine` AI 校对

卡片上**没有表单**（也不需要选提示词块），直接用引擎里的校对指令（`engine.ts` 的 `REFINE_DEFAULT_SYSTEM`）：先一句「修正转写文稿中的错别字、重复与语气词，保持原意与信息完整，只输出校对后的文稿」，后面跟两条专有名词规则——**专有名词以原文写法为准，同一名词有多种拼法时按「当前素材信息」里的标题统一，拿不准就保留原文**（不要替换成读音相近的常见词），以及素材信息只用于校订专有名词、不得据此补充文稿中没有的内容。

「当前素材信息」是引擎逐项附在 system 末尾的来源标签（`withSourceMetaHint`，内容即 `describeInputSource` 算出的 `InputSourceMeta.label`，形如 `《视频标题》 P1 · UP：xxx · 链接`）。**它只在节点没有任何自己的提示词时才追加**：填了 `promptOverride`（无 UI 入口，见 §9）或选中了提示词块都不追加，覆盖就是覆盖。理由见 [CHANGELOG.md](../CHANGELOG.md) 里那条「AI 校对节点会把 ASR 没把握的新专有名词统一成错的那个拼法」：校对节点原本只看得到转写稿本身，遇到 ASR 自己都没把握的词只能按多数派猜，而正确拼写往往就写在来源卡标题里。

**产物**：逐项 `text`；摘要 `N 个输入 · 总字数`。

### `process.prompt` AI 加工

| 字段 | 说明 |
| --- | --- |
| `promptBlockId` | 下拉选择提示词块。内置块与自定义块都在这份列表里；列表 label 形如「名称 · 版本 · 配方 · 内置」，并**过滤掉「阴阳师攻略加工」系列**（那一系列由 `process.gameguide` 承担） |
| `promptOverride` | 节点级覆盖提示词。**类型、校验与引擎都支持，但前端没有任何入口**（见 §9） |

**执行语义**：选中的块**带配方**（`recipe`）时走多步链，否则单次调用。配方的判定条件是「节点是 prompt/gameguide/drill 三者之一，且没有填 `promptOverride`」——一旦有覆盖提示词，即便块带配方也退化为单次调用，并记一行日志「自定义提示词覆盖配方，按单步执行」。

**产物**：逐项 `noteBlock`；摘要 `配方 N 步 · M 输入 · K 次调用 · 总字数` 或 `M 个输入 · 总字数`。

### `process.chapter` 章节切分

| 字段 | 取值 | 默认 |
| --- | --- | --- |
| `granularity` | 粗（章节数 ≤12）/ 中（≤20）/ 细（≤30） | `medium` |
| `maxChapters` | 1–50 | 20 |

**执行语义**：先按粒度拼出系统提示词要求 LLM 只输出 `{"chapters":[{"title":…,"content":…}]}`，再做一次结构校验（章节数上限）。文稿短于 200 字直接拒绝：「文稿过短，不适合章节切分」。

**产物**：**每章一份 `noteBlock`**（内容是 `## 标题` + 正文），而不是一份带目录的文档——要目录就用下游的合并节点。摘要 `N 章 · 总字数`。章产物**没有段标识**，是压平型产物。

**注意**：这个节点不在 AI 密钥预检名单里，缺密钥时跑到它才失败。

### `process.gameguide` 阴阳师攻略加工

| 字段 | 取值 |
| --- | --- |
| `mode` | `audited` 「核对版（推荐，稳）」（默认）/ `standard` 「快速版（省时）」 |

**执行语义**：`mode` 决定用哪个内置块——`standard` 用 `builtin.gameguide`（单次调用），`audited` 用 `builtin.gameguide.v2`（4 步配方：攻略要素拆解 → 起草攻略稿 → 回文核对 → 修正成稿）。节点卡片上固定显示产物构成说明：「核心结论表 / 式神速查卡 / 配队 / 避坑 / 术语 / 版本时效」。

**产物**：逐项 `noteBlock`。同样不在 AI 密钥预检名单里。

### `process.mindmap` 思维导图

配置全部在**高级设置**里，卡片正文没有表单：

| 字段 | 取值 | 默认 |
| --- | --- | --- |
| `title` | 导图标题，填了就强制用这个名字 | 空（由 AI 取一个 ≤20 字的中心主题） |
| `branchSize` | 自动（主分支 4–7）/ 精简（3–5）/ 详细（6–9） | `auto` |
| `maxDepth` | 3 / 4 / 5 层（不含中心主题） | 4 |
| `theme` | 纸面 / 演示 / 学术 | `paper` |

**执行语义**：多个输入会被**合并成一份**文稿再交给 AI（压平），要求只输出 `{"title":…,"nodes":[{"text":…,"children":[…]}]}` 的 JSON，随后渲染成 Markmap 可用的 Markdown。画布上的结果预览会渲染真实导图，而不是纯文本。

**产物**：一份 `noteDoc`（导图 Markdown）；摘要 `N 个主分支 · M 个节点 · 总字数`。按 §1.3，它不给 `preview`。

### `process.drill` 知识巩固（练一练）

| 字段 | 取值 | 默认 |
| --- | --- | --- |
| `pointCount` | 考察点数量 3–12 | 6 |
| `kinds` | 题型白名单，取值为单选 / 多选 / 判断 / 填空 | 至少一种（UI 上取消最后一种会回滚） |
| `difficulty` | 基础 / 适中 / 挑战 | 适中 |
| `withExtensions` | 是否输出「再想一步」延伸问题 | 开 |
| `focus` | 考察侧重（≤200 字），如「只考察数据与结论」 | 空 |

**执行语义**：走 `builtin.drill` 的 3 步配方（抽点 → 出题与延伸 → 审题）。节点参数通过 `{{params}}` 注入配方的 system，与原文分离——这是刻意的，因为「引文回查」要以原始输入为比对源。配方产出后还有一道结构层兜底 `buildDrill`：校验题目的引文是否逐字命中原文，**逐条丢弃不合格题目而不是整体失败**（8 题丢 1 题不影响另外 7 题），丢弃明细写进日志与摘要——丢弃率本身就是题目质量的健康指标。一份练习都没通过校验时节点失败：「没有生成可用的练习题，请重跑本节点」。

**产物**：一份练习集 JSON（`noteBlock` 类型），下游的合并/输出节点会在写文件前把它序列化成可读的 Markdown 题目集。摘要由 `buildDrill` 生成（含题量与丢弃情况）。按 §1.3，它不给 `preview`；答题在结果页的「练一练」标签页里做，**判分全在本地**，不联网、也不给开放题做 AI 判分。

## 6. 文本与逻辑

### `flow.if` 条件分支

| 字段 | 取值 |
| --- | --- |
| `condition.field` | 字数（`charCount`）/ 词数（`wordCount`）/ 包含（`contains`） |
| `condition.op` | 包含型：包含 / 不包含；数值型：大于 / 大于等于 / 小于 / 小于等于 / 等于 |
| `condition.value` | 包含型是要匹配的文字；数值型是数字字符串 |

「词数」的口径是 `countWords`：**中文字数 + 英文单词数**（连续字母数字算一个词），不是分词结果。「等于」是精确相等，用它配字数很容易永远不成立。「包含」区分大小写。

**执行语义**：判断结果记在内存里（`active.branches`），**节点本身只产出一份原样透传的产物**；「命中/未命中」体现在**边上**——未命中那一侧的出边在下游取数时被阻断，因此那条支路的下游会因拿不到输入而被标记 `skipped`。分支结果写入摘要：`条件成立 · 1200 gt 500`。

**这点对排查很重要**：条件分支的「分支」不是两份产物，而是边过滤；所以「没走到的那一支」在结果页显示 `skipped`，原因写「条件分支未命中或上游不可用，跳过」。

### `flow.pick` 素材挑选

挑选界面直接在卡片正文里（不需要高级设置）：按上游来源分组，组内可全选/全不选，每项显示序号、标题、分P、时长。两种警告会明确写出来：一段未选（「这个节点将无法运行」）、存在已失效段（「保存后会被忽略」）。**全选时会删掉该来源在 `data.pick` 里的键**，保持工程数据干净。

**执行语义**：到达这个节点时过滤已经发生过了（未选中的素材根本没进来），它的职责只是把选中的原样放行**并保留段标识**，供下游继续挑。摘要 `放行 N/M 段`。一段都没放行时失败：「没有可挑选的内容输入」。

### `process.text` 文本工具

| `operation` | 额外字段 | 行为 |
| --- | --- | --- |
| `findReplace` 查找替换 | `find` / `replace` | 字面量替换（按 `find` 切分再拼），`replace` 留空即删除 |
| `regexReplace` 正则替换 | `pattern` / `flags` / `replace` | `new RegExp(pattern, flags)` |
| `template` 模板渲染 | `template` | `{{input}}` 是正文占位符；模板里没有它时，非空模板会拼在正文前面 |
| `cleanup` 清理 | 无 | 去行尾空格、连续空行压成一个、首尾 trim |

**执行语义**：纯函数，无外部调用，因此**不重试**。逐项处理并保留段标识。摘要 `N 个输入 · 总字数`。

**注意**：`pattern` 与 `flags` 由用户输入直接构造正则，schema 里只有类型校验、**没有长度与 flags 白名单限制**——恶意正则可能导致灾难性回溯（这一条记在 status.md 的安全缺口里）。正常使用不受影响：非法正则会立刻失败，且不重试。

## 7. 组织与输出

### `process.merge` 合并

| 字段 | 说明 |
| --- | --- |
| `title` | 合并后文档的标题，默认「合并笔记」 |

**执行语义**：把汇入的文本按连接顺序以空行拼接，前面加上 `# 标题`。知识巩固的 JSON 产物会先被序列化成可读 Markdown，避免原始 JSON 混进笔记。

**产物**：一份 `noteDoc`，**没有段标识**（压平型）。摘要 `总字数`。

### `process.output` 输出

| 字段 | 说明 |
| --- | --- |
| `fileName` | 输出文件名，默认 `笔记.md` |

**执行语义**：把汇入的文本写到 `<数据目录>/<常规设置里的输出目录>/<运行 id>/<fileName>`（输出目录默认 `outputs`），并记录一行日志「输出文件：…」。文件名会先清洗：路径非法字符替换为下划线，并截断到 80 字符。

**产物**：一份带 `path` 的 `noteDoc`；摘要 `文件名 · 总字数`。按 §1.3，它不给 `preview`——要看内容用画布上「查看完整输出」跳结果页，或直接在结果页下载 Markdown（`GET /api/runs/:id/outputs/:nodeId/download`）。

### `process.obsidian` Obsidian 笔记

| 字段 | 说明 |
| --- | --- |
| `folder` | 保存目录（下拉，可搜索）。空列表提示先到设置页读取目录；占位默认 `00-Inbox` |

**执行语义**：把上游 Markdown 包装成带 frontmatter 的笔记再写盘。写入位置由设置页的「Obsidian」组决定：

- 默认写本地库（`obsidian.vaultPath` + `folder`）；
- 打开设置页坚果云组的「Obsidian 笔记节点直接读写坚果云」后，改为写云端目录 `obsidianRemotePath`。

frontmatter 字段固定为：标题、类型（按来源推断为视频笔记/学习笔记/笔记）、来源、作者、原始链接、创建日期、tags（来自节点 `data.tags`），以及**AI 结构化提取**开关打开时补充的人物/事件/时期。标题缺省取正文第一个 H1，再缺省用「未命名笔记」。保存目录含 `..` 会被拒绝。

**自动关联**：设置页的「写入后自动关联相关笔记」打开时，按人物/事件/时期在库内找相关笔记，在文末追加「## 相关笔记」与 `[[链接]]`；摘要里会显示「关联 N 篇」。本地模式扫描 vault，坚果云模式扫描远端目录。

**产物**：端口声明里**没有输出端口**（画布上不能接下游），但引擎仍会产出一份带路径的 `noteDoc` 供结果页查看。摘要 `已保存到 Obsidian：<目录>/<文件名>`。

**注意**：这个节点也不在 AI 密钥预检名单里；但打开「AI 结构化提取」且缺 AI 密钥时，失败发生在运行到它的时候。

## 8. 配方（节点内多步链）

内置提示词块里有 5 个带**配方**（`recipe`），它们是「单次调用」之上的多步链，图上仍是一个节点：

| 块 id | 名称 | 步骤 |
| --- | --- | --- |
| `builtin.insight.v3` | 观点提炼（配方试点） | 通读拆解 → 分块起草 → 回文核对 → 修正成稿（4 步） |
| `builtin.insight.v4` | 观点提炼（排版版，推荐） | 通读拆解 → 分块起草 → 回文核对 → 修正成稿（4 步） |
| `builtin.trace.v2` | 信息溯源（结构化核对版，推荐） | 通读抽取 → 回文核对 → 结构化成稿（3 步） |
| `builtin.gameguide.v2` | 阴阳师攻略提炼（核对版） | 攻略要素拆解 → 起草攻略稿 → 回文核对 → 修正成稿（4 步） |
| `builtin.drill` | 知识巩固（推荐） | 抽点 → 出题与延伸 → 审题（3 步） |

配方的结构刻意收敛（`packages/shared/src/recipe.ts`）：**只支持顺序步骤 + 确定性断言门**，最多 8 步，不引入任意图或循环。每步可声明 `expects.kind` 与 `asserts` 断言（包含/不包含、长度上下限、JSON 根键、引文逐字命中原文），断言未通过即该步失败——错误文案「断言未通过」在不可重试名单里，不会反复重试。

每个输入会独立跑完整链路，所以调用次数 = 步骤数 × 输入数（摘要里写的「K 次调用」就是这个）。步骤进度按 `node.step.done` / `node.step.error` 事件推给前端，日志带步骤 id。`builtin.trace.v2` 额外支持：配置了外部溯源密钥时，对最终 JSON 做一次联网核查并回填 `external` 字段；核查失败只记日志，保留内部溯源结果。

## 9. 边界与当前不清之处

以下是**已经实现但仍需注意**的边界，不是待办清单（待办见 status.md）：

1. **`promptOverride` 没有前端入口**：类型、schema 与引擎都支持节点级覆盖提示词（填了还会跳过配方改为单步），但界面上没有任何地方能填它。它目前只能通过手工改工程 JSON 使用。
2. **`source.text` 的 50000 字只是前端的计数提示**，服务端与 schema 都不做限制。
   AI 请求自身有 300 秒超时（`apps/server/src/lib/ai.ts` 的 `chatCompletion`），超长文稿更容易撞上它。
3. **`process.chapter` / `process.gameguide` / `process.obsidian` 不在 AI 密钥预检名单里**，缺密钥时表现为「运行能启动、中途失败」而不是「启动就被拒绝」。
4. **`process.obsidian` 声明无输出端口但实际产出 `noteDoc`**：这是有意的（画布上它就该是终点），但读代码时容易误判。
5. **压平节点之前的挑选才有意义**：段标识穿过逐项节点，到合并/章节/导图/条件分支/输出为止。
6. **多输入的先后顺序 = 连线创建顺序**（`graph.edges` 顺序），不是画布上的上下左右位置。
7. **`queued` 状态不产生**：节点结果表与类型里有这个值，引擎从不写它。看到它只可能来自历史数据或手工构造。
