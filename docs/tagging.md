# 标签与合集：怎么用

这套功能只做一件事：**给笔记贴上「谁说的」和「说了什么话题」**。贴完之后，在 Obsidian 里一搜就是合集——
不用在这个工具里再做什么。想按 UP 主看、还是按话题看，取决于你搜哪一个标签。

读这一篇大约 5 分钟，照着做一遍 10 分钟。每个节点能填什么、实现细节看 [nodes.md](./nodes.md)，
其余设置项看 [usage.md](./usage.md)。

## 1. 先看清它能给你什么

| 你想要的 | 怎么做 |
| --- | --- |
| 某个 UP 主说过的全部 | 在 Obsidian 搜 `tag:#UP：某某UP` |
| 某个话题上大家分别怎么说 | 搜 `tag:#话题/平台抽成` |
| 这个 UP 还聊过哪些别的话题 | 打开他任意一篇笔记，看 `tags` 那几行 |
| 一篇笔记属于谁、讲什么 | 打开笔记，看头部 |

**「合集」不是这个工具里的一个页面，就是 Obsidian 的一次搜索。** 原因是：标签搜索零配置、不用装插件、
手机上也能用，而且新入库的笔记立刻就能被搜到——不需要等谁去更新索引。

## 2. 三步走完

1. **建词库**：设置 → Obsidian → 填库路径、建好一级/二级 → **点「保存设置」**。
2. **跑一次**：同一页往下，点「预估」看要动多少篇 → 点「开始重打标」。
3. **去 Obsidian 看**：搜 `tag:#...`，或者把它加进书签。

下面三步逐个说。

## 2.5 笔记库放在哪：推荐放进坚果云同步文件夹

**一句话：把库路径指到坚果云客户端的同步文件夹就够了，不需要配「坚果云」那一组设置。**
同步由客户端负责，ScribeFlow 只当它是个普通本地目录——你少配一套账号与密码，功能反而更全。

| 做法 | 要配什么 | 拿到的能力 |
| --- | --- | --- |
| **推荐：库在客户端同步文件夹里** | 只填一个本地路径 | 全部（见下） |
| 打开坚果云组的「Obsidian 直连云端」 | 账号 + 应用密码 + 远端路径 | **少三项**：重打标看不到云端库、不记指纹（词库一变就把整库重判、白花钱）、重跑会覆盖你手补的标签 |
| 库在本地、手动推拉 | 同上一行 | 全部，但要记得手动按，同步还有单目录 750 项的硬上限 |

也就是说：**「Obsidian 直连云端」只适合跑在没有坚果云客户端的机器上**（Docker、另一台服务器）。
本机装了客户端就把它关掉，库路径填同步文件夹（如 `C:\Users\<你>\Nutstore\1\ScribeFlow\Obsidian`）。

一个已知代价：打标历史按「库路径 + 文件路径」记，所以**换库路径（或换机器）会让它们全部失效**，
下次重打标会做一次全量判定。一次性的事，之后照旧零成本。

## 3. 第一步：建词库（只有这一步需要你动脑）

> **先分清两类标签。** 一类是**自动写的**（来源是裸值 `B站`，UP 主是 `UP：某某`），它们在生成笔记时按元数据就写好了，
> 你只有一个决定权——写不写（设置页两个开关，节点卡片上还能逐篇改）。**另一类才是你要维护的**：
> 下面这个词库，AI 从这里挑话题标签。自动那两类**不进词库**，也不参与「回补旧笔记」。

### 3.1 规则就三条

- **一级是分类，二级是具体标签**，像文件夹套文件夹。
- **笔记上只会写二级**（`话题/平台抽成`），不会写 `话题`。因为 Obsidian 里按一级筛选会自动带上它下面所有二级，
  写两级等于同一个意思记两遍。**但反过来要注意：一级下面一个二级都不填时，这一级自己会被当成标签用**——
  所以别留空的一级。
- **标签里不能有空格**（Obsidian 的硬限制）。填了空格，保存时自动换成 `-`，所以「某个 UP 主」会变成
  `某个-UP-主`，别惊讶。

### 3.2 按你的目标，建议这样建

**关键一句：这一栏填什么，决定了你能按什么找笔记。** 出厂值里的 `类型` / `领域` 是**兜底分类**
（「视频笔记」「AI」这种），跟「某个话题上大家怎么说」没有关系。要用好这套东西，至少要加一个 `话题` 一级：

```
话题                 ← 新建一个一级，专门放你要追踪的议题
  平台抽成
  AI泡沫
  前端被替代
  ...
类型 / 领域          ← 出厂就有的兜底分类，留着也行、删掉也行
```

于是你得到三个维度：

- **谁**——`UP：<名字>`：**自动写的**，不用你维护，也不用填（见上面那个开关）。
- **从哪来**——`B站`、`本地文件`、`文本`：同样是**自动写的**，取值就是笔记里「来源」那一行的值。
  来源与 UP 主这两个标签都**不带一级**（老笔记里的 `来源/B站`、`UP主名称/某某` 是旧写法，重跑一次会换成新的）。
- **什么话题**——`话题/<议题>`：二级就是你想追踪的那些议题，**由你定义**；AI 只负责把每篇笔记对上号。

自动那两个标签**只在生成笔记的那一刻写**：老笔记缺它们，回补**不会**替你补（靠内容猜是不准的），
要改就在 Obsidian 里自己改——手动改过的标签不会被覆盖，除非你把这篇笔记重跑一遍。

> **要不要让 AI 自己加二级？** 默认关。关着时它只能从你列的二级里挑，好处是**同一个话题全库只有一个名字**，
> 搜出来才是完整的合集（要是它今天写「平台抽成」、明天写「平台佣金」，你会发现每张合集都少一半，而且不报错）。
> 想让词库自己长，就在界面上打开那个开关；打开后它只能往已有的一级下面补二级，一级结构永远归你。

### 3.3 三种显示样式：换个看法，一个字段都不改

词库编辑器上方的「显示样式」是三个小图标（左边有「显示样式」四个字标着），
它们只影响**看起来**什么样，不动词库里的任何数据：

| 图标 | 样式 | 长什么样 | 什么时候用 |
| --- | --- | --- | --- |
| 调色板 | 彩色标记 | 一级一个色相（色点 + 淡底），二级继承这一组的色 | 想一眼看出某个标签属于哪一类 |
| 黑白圆 | 单色 | 不上色，靠字重、缩进与留白分层 | **默认**；词库大了以后满屏颜色反而吵 |
| 三行线 | 清单 | 一行一个标签，带用量条 | 标签多、想按「多少篇用过」扫一遍 |

切换立刻生效，刷新、换设备之后还是你选的那个（它跟词库一样存在服务端设置里，不属于任何单个工程）。
鼠标停在某个图标上会显示它是哪一档、以及一句话说明。图标按钮本身给读屏的名字是「彩色标记 / 单色 / 清单」。

### 3.4 建完必须点「保存设置」

服务端读的是**已保存**的词库。没保存时「预估」和「开始重打标」是灰的，界面上会提示你先保存——
这不是 bug，是怕你用旧口径跑一遍全库。

## 4. 第二步：跑一次

### 4.1 为什么分「预估」和「开始」两步

因为「预估」**完全不调用模型、不花钱**。它只扫描你的笔记，告诉你这一轮：

| 预估里的数字 | 意思 |
| --- | --- |
| 需全量判定 | 新笔记，或者内容/标签被你改过——要重新判一遍 |
| 仅判新标签 | 笔记没变，只是词库多了新标签——只判"这些新标签适不适用" |
| 只补写/清理标签 | 不调模型：去掉你已从词库删掉的标签。**自动标签（来源 / UP 主）不在回补范围内**——既不补也不删 |
| 无需处理 | 什么都没动，跳过 |
| 预计调用 | 这一轮大概几次模型调用 |

看了数再决定要不要点「开始重打标」。**你随时可以点「预估」——它不花钱。**

### 4.2 什么时候该重跑

| 情况 | 要不要跑 |
| --- | --- |
| 第一次用（库里有老笔记） | 要，这是最贵的一次 |
| 刚加了一个新话题到词库 | 要，但很便宜——只有正文里出现过那个词的笔记会被判 |
| 在 Obsidian 里改了自己的笔记正文 | 那几篇要（内容变了会被重新判） |
| 改完词库又改回去 | 不用，脚本自己会发现没变化 |
| 什么都没改，只想看看 | 点「预估」就行，预计调用会是 0 |

### 4.3 「深度重扫」是什么

默认只把**正文里出现过标签名**的笔记送去判定，这是省钱的主要来源。代价是换个说法的笔记会漏——
比如标签叫「平台经济」，而笔记里只写了「抽成」，字面不重合就不会被送去。

补法是打开「深度重扫」：不做字面筛选、全库语义匹配，**明显更贵**。建议：平时不开，发现某个新话题
在合集里明显缺人时再开一次。

### 4.4 跑完看什么

报告里有：写入几篇、实际调用几次、输入多少 token、其中多少命中缓存。这些数是**真实的**（来自接口返回，
不是估算）。如果你改了 AI 模型或提示词，成本口径会跟着变，重新跑一次看新数就行。

跑的时候不能同时运行工程——两边都在写同一批文件，工具会拦住你。

## 5. 第三步：在 Obsidian 里看合集

三种方式，从最简到最顺手：

**① 直接搜**：搜索框里输 `tag:#话题/平台抽成`，回车。列出的就是所有讲过这个话题的笔记。

**② 标签面板**：右侧边栏打开「标签」面板，一级一级点下去，效果一样。

**③ 加成书签（推荐）**：把 `tag:#话题/平台抽成` 搜一次，然后**收藏这条搜索**。之后每次点书签直接就到——
这就是你的常驻合集入口。给每个常用话题加一个书签，就相当于一列"专题入口"。

**想让合集好看成一张表**（谁、什么立场、出处，能排序）：Obsidian 1.9 起自带了 Bases，可以基于 `tags`
属性做一个数据库视图。这是可选的——搜索结果已经够用，等你真觉得不够整齐再折腾。

### 小工具：搜索串不用自己拼

设置页 → Obsidian → 标签词库里，**每个一级组头右侧的复制按钮**会把搜索串复制到剪贴板
（一级是 `tag:#话题` 这样的串；二级自己拼也很短：`tag:#话题/平台抽成`）。粘到 Obsidian 搜索框或书签里即可。

自动那两个（来源 / UP 主）不在词库里，所以没有复制按钮——它们的搜索串照这个形状手写就行：
`tag:#B站`、`tag:#UP：某某UP`（冒号是**全角**的，跟写进笔记里的那个一致）。

> 标签名的**单击改成了改名**（键盘 F2），所以复制从"点名字"挪到了那个独立按钮——
> 同一个单击既改名又复制，两件事会打架。

### 新入库的笔记不需要等重打标

「Obsidian 笔记」节点在保存时就顺手打了标签，所以刚跑完的工程立刻能搜到。重打标是给**旧笔记**和
**词库变动**用的。

## 6. 笔记上到底长什么样

一篇讲平台抽成的视频，保存后在 Obsidian 里是这样：

```markdown
---
标题: 平台抽成到底抽多少
类型: 视频笔记
来源: B站
作者: 某某UP
原始链接: https://www.bilibili.com/video/BV1xxxxxxxxx
创建日期: 2026-10-11
tags:
  - B站                # 自动写：跟上面「来源:」那一行同源（裸值，不带一级）
  - UP：某某UP          # 自动写：跟「作者」那一行同源（全角冒号）
  - 话题/平台抽成      # AI 从你的词库里挑的
  - 领域/AI
---

# 平台抽成到底抽多少

（正文……）
```

`tags` 那几行就是全部的秘密。前两行是「谁说的、从哪来」（工具按元数据自动写），后两行是「讲什么」（AI 从你的词库里挑）。

## 7. 常见坑

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 「预估」/「开始重打标」是灰的 | 词库或库路径有未保存的改动 | 先点「保存设置」 |
| 报「Obsidian 库路径不存在或不是目录」 | 路径写错，或库在另一台机器上 | 改成真实存在的目录 |
| 点「预估」显示全库 0 篇 | 库路径不对（这条现在会明确报错），或库里真的没有 `.md` | 检查路径与库内容 |
| 某个话题的合集里人明显不全 | 字面不重合的笔记被预筛漏掉了 | 打开「深度重扫」再跑一次 |
| 标签变成了 `某个-UP-主` 这样 | 空格被自动换成 `-`（Obsidian 标签不能含空格） | 这是正常的；名字不用手填 |
| 我从词库里删了一个标签，笔记上还有 | 还没重跑 | 跑一次重打标，过期标签会被清掉 |
| 关掉「写来源标签」后，笔记里还留着 `B站` 这种 | 来源标签的新写法是裸值，跟人自己写的标签在文件里长得一样，工具分不出来 | 自己删一下；旧写法 `来源/B站` 会被自动清掉，UP 主标签（`UP：某某`）也会 |
| 我自己手写的笔记会被改动吗 | 会扫描，但**只动词库里的标签** | 你自己的标签（不在词库里）一律不碰 |
| 有几篇笔记被列出「跳过」 | front matter 结构坏了（比如开头 `---` 没收尾） | 修好那篇的头部再跑；工具不会去"顺手修复"它 |
| 我改了笔记的提示词 | 内容变了会被重新判定 | 正常，跑一次即可 |
| 想彻底不让 AI 加新标签 | — | 关掉「允许 AI 新增二级标签」 |

## 8. 一句话收尾

**词库是你定义的"想按什么找"，标签是工具替你贴上去的，合集是 Obsidian 的一次搜索。**
你真正要维护的只有词库那一棵树——其余都是自动的。

想细看每个节点的行为与字段，看 [nodes.md](./nodes.md)；设置项逐个的解释看 [usage.md](./usage.md)。
