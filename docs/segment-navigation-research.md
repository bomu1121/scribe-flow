# 多视频结果的分组切换：导航模式调研与改造方案

> 状态：调研完成，方案对照稿见 `docs/samples/segment-nav-options.html`（含 3 个方案的真实数据渲染图）。
> 触发：用户反馈当前「8 个横向胶囊按钮」的方案很低级，要求充分调研后再优化。

## 1. 现在这套为什么不行

当前实现是一个横向滚动的 chip 行：`[全文] [1 标题 字数] [2 标题 字数] … [8 …]`。逐条对照公开的控件规范，它踩了三条硬规则：

| 规则 | 来源 | 我们的现状 |
|---|---|---|
| 分段控件/标签页只适合少量选项：**窄界面 ≤5，宽界面 5–7**；「段太多会难以解析、切换耗时」 | [Apple HIG · Segmented controls](https://developer.apple.com/design/human-interface-guidelines/segmented-controls) | 宽屏 8 段、浮层里同样 8 段（远超声称上限） |
| **标签页是用来分「相关」内容的，不是用来走「顺序」内容的**；顺序阅读应当用排版层级与留白 | [Material Design 3 · Tabs guidelines](https://m3.material.io/components/tabs/guidelines) | 8 个视频是同一条处理链上的**顺序**产物，天然不该用 tab/segment 表达 |
| 选项一多，横排就会退化成**轮播**：被隐藏的选项更难发现，必须用次级控件才能翻出来——「**标签越少越好**」 | [NN/g · Tabs, Used Right](https://www.nngroup.com/articles/tabs-used-right/) | 标题被截断、右侧内容藏在滚动区外，正是「轮播 + 次级操作」 |
| 手风琴擅长**短内容 / 移动端**；标签页适合长内容与复杂布局 | [NN/g · Tabs, Used Right](https://www.nngroup.com/articles/tabs-used-right/) | 每段是 4k–1 万字的长文 → 桌面端应给「列表 + 面板」，而不是折叠块 |

一句话：**我们把「顺序内容的分段导航」做成了「平级标签切换」**，所以它既挤、又藏、又低级。

## 2. 约束（本次设计的边界条件）

来自真实运行 `run_a0bc492d`（8 个视频）：

- **N 会变**：库里既有一个视频的链，也有 2 / 4 / 8 个视频的链；同一节点段数应能撑到 20+（B 站合集/多 P 很常见）。
- **标题长**：中文标题 20–40 字（如「负基础篇—网络通信核心认识终端、IP、端口、域名、DNS，内外网」），横排必然截断；竖排可以两行放全。
- **每段有可比元信息**：字数（4.3k–1.0 万）+ 时长（29:45–1:19:52）+ 状态点；这些是用户「定位」的依据。
- **三种容器宽度**：结果页正文区（约 1000px）、画布浮层（固定 360px）、移动端（<768px 纵向堆叠）。
- **已有两个导航**：左侧「链路输入 / 输出文档」列表、工具条里的「文档目录」（当前段内的标题）。新控件必须和它们划清层级，不能变成第三个抢注意力的列。
- **房子风格**：紧凑行（`.rv-chain-row`：6/8px 内距、6px 圆角、hover/active = `--color-ink-soft`、12px 中黑标题 + 10.5px 三级灰 meta），全站「选一个」用 Element Plus Select，颜色一律走令牌。

## 3. 候选模式与评估

| 模式 | 代表产品 | N 扩展性 | 标题完整度 | 顺序阅读 | 定位效率 | 结论 |
|---|---|---|---|---|---|---|
| A 横向胶囊/标签（现状） | Material Tabs、iOS Segmented | ✗ 8 段即轮播 | ✗ 截断 | ✗ | ✗ | 淘汰 |
| B 右侧「分段大纲」栏 + 底部翻页 | 文档站右侧 On-this-page、笔记应用的目录栏 | ✓ 20+ | ✓ 两行 | ✓ ‹ › / ↑↓ | ✓ 全览 + 可比字数 | **结果页首选** |
| C 阅读器式标题行 + 下拉跳转 | 阅读器/漫画分章、GitHub 文件树选择器 | ✓ | 展开后完整 | ✓ ‹ › | ~ 需展开 | 结果页备选 / **浮层首选** |
| D 左侧栏树内嵌套（输出文档 → 分段） | Obsidian / VS Code 文件树 | ✓ | ✗ 300px 内严重截断 | ~ | ~ | 淘汰（与链路输入抢列、收起即失效） |
| E 手风琴（折叠全部段落） | FAQ、移动端设置页 | ✓ | ✓ | ✗ 仍是一页长文 | ✗ 折叠标题行也要滚动 | 仅移动端兜底 |
| F 缩略图网格 | 视频站分 P | ✓ | ✗ | ✗ | ~ | 不适用（笔记无封面语义） |
| G 全屏目录页/抽屉 | Kindle 目录、PDF 大纲 | ✓ | ✓ | ~ | ✓ | 过重，浮层场景可用 |

补充依据：下拉/选择器是「选项多、只选一个」的标准解，但**隐藏了全局视图**，所以它适合空间受限的容器（360px 浮层），不适合主阅读面；主阅读面要的是「常驻大纲」。

## 4. 结论：分层落地（同一份分段数据，三种容器各用其形态）

| 容器 | 形态 | 理由 |
|---|---|---|
| 结果页（宽） | **方案 B：右侧「分段大纲」栏**（可折叠）+ 栏底「‹ 3/8 ›」翻页 + `↑↓` 键盘切段；顶部保留「全文」入口 | 顺序内容 → 列表而非标签；8–20+ 段不退化；标题两行放全；字数/时长可横向比较；正文滚动与大纲滚动互不干扰 |
| 结果页（≥1280px 才显示大纲） | 窄屏自动降级为方案 C 的标题行（下拉 + 翻页） | 与移动端一致，避免正文被挤到 <640px |
| 画布结果浮层（360px） | **方案 C：单行标题 + 下拉列表**（ElSelect 语汇），或 `‹ 3/8 ›` 紧凑翻页；不铺开 8 个按钮 | 360px 放不下 8 个可读按钮；单行触发器 + 展开列表是这类宽度的标准做法 |
| 移动端 | 标题行下拉 + 手风琴式「上一段/下一段」 | 屏幕小，标签页/分段控件在此彻底失效 |
| 运行日志弹窗 | 维持现有「按输入筛选 + 行内输入标签」 | 日志是检索场景，不是目录导航 |

### 4.1 交互规范（三种容器共用）

- **当前段记忆**：同一节点/运行内记住用户选中的段；SSE 刷新、切回该节点都不丢。
- **深链**：`?focus=<nodeId>&seg=N`；浮层「查看完整输出」带上当前段。
- **滚动**：大纲与正文各自独立滚动；换段时正文回到顶部；大纲当前项自动 `scrollIntoView({ block: "nearest" })`。
- **键盘**：`↑/↓`（或 `j/k`）切段，`Home/End` 到首/末段，焦点在大纲内时 `Enter` 确认；Esc 从大纲回到正文。
- **可访问性**：大纲用 `role="listbox"`/`option` + `aria-selected`（或 `nav` + `aria-current="true"`），当前段同步 `document.title` 后缀；翻页按钮带 `aria-label`（「上一段：<标题>」）。
- **状态**：段状态点（成功/失败/运行中）沿用链路卡片的点语言；失败段在标题下给一行错误摘要。
- **规模**：段数 > 12 时大纲顶部出现筛选框（按标题过滤）；段数 = 1 时整个控件不出现（现状已如此）。
- **空态**：没有分段时保持整篇阅读（不显示空大纲）。
- **性能**：只渲染选中段的 Markdown（已是现状），大纲只渲染文本行；20 段无压力。

## 5. 与现有 UI 的分工

| 控件 | 管什么 | 层级 |
|---|---|---|
| 左栏「链路输入 / 输出文档」 | 管**运行结构**（哪个节点产出了什么） | 全局 |
| 工具条「文档目录」 | 管**当前段内的标题**（H1–H4） | 段内 |
| 新「分段大纲」 | 管**跨段定位**（第几个视频、多长、哪一段） | 段间 |

三者互不重复，符合「结构 → 段间 → 段内」的自然缩放。
