# 使用说明：从零到一份笔记

面向**用这个产品的人**。部署、环境变量与备份目录看 [deploy.md](./deploy.md)；
每个节点能填什么、产出什么看 [nodes.md](./nodes.md)；想改代码先看 [architecture.md](./architecture.md)。

## 1. 先跑起来

本地开发（前端 `:5173`、后端 `:8787`，前端把 `/api` 代理到后端）：

```bash
pnpm install
pnpm dev
```

Windows 上可以双击 `start-dev.cmd`（同一个窗口跑前后端，Ctrl+C 一次停两边）。
只想用现成的部署方式（Docker 单容器、前端静态托管、环境变量、备份目录）→ [deploy.md](./deploy.md)。

打开页面后：**有工程时会自动进入你上次打开的工程**；一个工程都没有时显示欢迎页（打开工程面板 / 新建第一个工程）。

## 2. 第一次使用要配的东西

全部在**设置**里（左栏底部的齿轮按钮）。九组设置里，只有前两组是「不填就跑不动」的：

| 分组 | 什么时候需要 | 要填什么 |
| --- | --- | --- |
| **AI 模型**（默认打开） | 除纯文本节点外的所有加工节点 | 提供商（DeepSeek / OpenAI / 自定义）、接口地址、模型、API Key。DeepSeek 与 OpenAI 会自动带上默认地址与模型，自定义需自己填。**输入/输出单价**是选填的，只用来把 token 折算成估算金额（见 §6.1） |
| **语音识别** | 只有「转写」节点需要 | 引擎（MiMo-V2.5 默认 / OpenAI 兼容）、地址、模型、API Key。**单价（元 / 分钟）**同样是选填的，只影响估算金额 |
| 联网检索 | 用「信息溯源 · 上网查证」并希望联网核查时 | 渠道（智谱 / Tavily）、API Key、每条最多返回结果数 |
| 常规 | 想调并发或输出目录时 | 并发数（1–4，默认 2）、输出目录（默认 `outputs`） |
| 展示范围 | 演示或自用时想收掉某些节点 | 勾上不想出现的节点（如「阴阳师攻略加工」）：节点面板、新建工程的链路列表、快捷新建、提示词库都会一起收起。**只影响新建时能选什么**，已有工程照常显示与运行 |
| Obsidian | 用「Obsidian 笔记」节点、或想按标签归类时 | Obsidian 库路径、默认保存目录；**标签词库**（一级/二级，可增删）、「允许 AI 新增二级标签」、AI 结构化提取与自动关联的开关；以及**全库重打标**（见 §5.4）与**回补相关笔记**（见 §5.5） |
| 坚果云 | 想备份数据库、或让笔记直接写云端时 | 日常只需 **备份目录**（填坚果云同步文件夹里的路径即可，不需要账号密码）；WebDAV 服务器的账号与**应用密码**、Obsidian 云端目录、笔记直连开关等收在同组的「高级：云端口令与直连」里，只给没装客户端的部署用 |
| 提示词库 | 想加自己的提示词时 | 内置提示词按系列归组（「观点提炼」下挂详尽版 / 成文版 / …），列表上不显示版本号；被迭代过的写法自带「历史版本」入口（看历代全文）。自定义提示词的名称与正文；也能和内置提示词逐字对比 |
| 数据与工程 | 想清理运行记录时 | 查看数据目录、运行条数、输出文件数，清理已结束的运行 |

两组密钥各有一个「测试连接」按钮，建议先点它再保存。几条与密钥有关的行为要提前知道：

- 密钥位只显示「已保存 / 未配置」，**服务端不会把密钥回传给浏览器**。
- 密钥**留空表示不修改**，所以「界面无法清除已保存的密钥」——要换就直接填新的覆盖它。
- 保存是整页提交：改完某一组点该组的「保存设置」即可，提交的是整张表单。

**B 站登录**（只有用 B 站来源时才需要）：入口在**画布编辑器右上角的 B 站头像按钮**上（未登录时显示「未登录 B 站」），
点开是二维码，扫码即可。退出登录也在同一个按钮的下拉里，退出会删除服务端保存的 Cookie。

## 3. 一条最短路径（第一次用推荐）

1. 左栏「工程」面板 → 新建工程 → **先选来源**（B站链接 / B站收藏 / 本地文件 / 粘贴文稿），再点一条链路。
   链路只描述加工路径的形状，来源按你选的那个放好，之后也能在画布上换。
   通用链路有「单线笔记」「多路对照」「全提示词对照」「思维导图」「Obsidian 笔记」「分章笔记」「系列综述」「选段加工」（只对音视频来源）；
   垂直链路有「阴阳师攻略」「练一练」。
   **链路只给形状，需要你自己在「AI 加工」节点里选提示词**（打开工程后点节点卡片上的下拉）；
   只有「全提示词对照」例外——它的每条分支已经各绑好一个当前放开的提示词，跑完几版内容一起写进一篇 Obsidian 笔记。
   选「B站收藏」时，点链路会先打开收藏夹选择器（需要先登录 B 站）：勾 1 个视频是普通来源卡片，
   勾多个合成一张多选卡片，取消则什么都不建。可用链路与「B站链接」完全一致——它落到图上也是 B 站来源节点。
2. 打开工程，进入画布。
3. 在「B站链接」节点粘贴链接（会解析出标题、分P 与合集）。
4. 点画布右上角浮条上的**运行**。
5. 运行结束后点「上次结果」进结果页，看输出文档，用右上角的「下载 Markdown」导出。

已经有一条 B 站链接时，用工具栏的「粘贴链接建工程」更快：它把工程名、来源节点、提示词一次配好，回车即建；
勾上「创建后立刻运行」就连运行一起发起，进度直接在那张画布上走。这条链路要调模型（B 站视频还得先转写，
要 ASR 密钥），缺什么服务端会拒绝启动并说明去哪儿配——工程照建，补好设置再手动跑一次即可。

整图运行的进度会就地显示在节点卡片上（状态点、底部摘要），底部浮条会显示「活动任务 N」。

## 4. 画布上怎么操作

**加节点**：左栏「节点」面板 → 点击（加到画布中心）或拖进画布。分组依次是
「来源 / 转写 / AI 加工 / 文本与逻辑 / 组织与输出」。其中「B站收藏」是**动作**而不是节点：
点它会打开收藏夹选择器（需要先登录 B 站），多选确认后直接生成来源节点，不会在画布上多出一个空节点。

**改节点**：所有参数都在节点卡片内填写（没有右侧检查器）。点一下节点会浮出选择条，
「高级设置」里有素材挑选、失败重试，以及来源节点与思维导图节点各自的专属配置。

**连线**：从输出端口拖到输入端口，只有类型相容时才能连上；右键一条连线可以删除它。

**运行**：画布右上角的浮动工具条是「运行 / 上次结果 / 活动任务 N / 停止」。
「更多操作」下拉里有整理画布（自动布局）、适应视图、撤销、重做、复制工程、导出工程、强制结束运行。
只跑一部分时，用节点上的播放按钮（从此节点运行）或节点菜单里的「运行此节点」——
注意这两个的语义不同：前者包含该节点的全部下游，后者只跑这一个节点。

**只跑一部分时，上游不在范围内的节点会沿用上一次的产物**（这正是它能省掉重跑转写的原因）。
如果换过素材（改了 B 站链接卡里的视频/集），启动时服务端会说明「哪个节点的产物是用哪个素材算的」并要求确认：
**按当前文稿继续**（报告与笔记会写文稿**真实的来源**，不会挂到新卡片名下），
或**先去重跑上游**——要让报告对上新素材，得从来源卡的下游第一个节点（转写）开始跑；
改素材那一刻画布上也会提示下游有多少节点需要重跑。文字卡改的是内容、
不是素材身份（它的身份来自节点 id），这一类不会要求确认。

**运行期间画布是只读的**：不能加节点、不能连线、不能改表单——这是刻意的，
避免「改了但本次运行没生效」的困惑。只读期间**运行入口不再置灰**：点它们是**加入排队**
（浮动条「运行」、节点的播放按钮、右键菜单里的两种运行都算），当前运行结束后依次自动开始，
浮动条上出现「排队 N」——点它可以清空排队。同一工程始终只有一个运行在跑（排队不是并发）。
队尾的名字与顺序在提示里写着，点完可以走开；切到别的页面、别的工程，队列照排。
刷新页面会丢掉排队（队列只在内存里），正在跑的那次不受影响。

**停止运行会一并清空排队**：点停止 / 强制结束意味着「都不要跑了」，否则下一条会立刻自己起来。

**快捷键**：`Ctrl/Cmd+Z` 撤销、`Shift+Ctrl+Z` 或 `Ctrl+Y` 重做、`Ctrl+D` 复制选中节点、`Delete` 删除（在输入框里不触发）。
单个工程最多 200 个节点，超过会提示拆分。

**保存**：自动保存，顶栏显示「已保存 HH:mm」。如果画布被清空而上次落盘不是空的，会先弹确认框；
取消就不会写服务端。

## 5. 三个高频操作

### 5.1 选 B 站视频：点行与勾选是两条轨道

在「B站链接」节点的卡片里，分P 列表与合集列表各有两条互不重叠的操作：

- **点某一行 = 把整个节点切到那一集/那一P**（当前项用底色标出），卡片上只留这一个视频；
- **勾选框 + 底部「合并为一张卡片」= 多选合并**（不足 2 项时按钮禁用并写出原因），
  合并后卡片显示「N 项」，可以点「改选集」回到选集界面重新编辑，已合并的选集不会丢。

想从收藏夹 / 我的合集 / 稍后再看 / B站历史里选，用左栏「节点」面板的「B站收藏」动作。

### 5.2 只加工其中几段：素材挑选

一张来源卡可以承载多个视频，一个校对/AI 节点也可以处理多个输入；如果只想让其中几段继续往下走：

- **独立节点**：拖入「素材挑选」节点，在卡片正文里按上游来源分组勾选（组内可全选/全不选）；
- **节点内**：在处理节点的「高级设置 → 素材挑选」里勾选——两处写的是同一份数据。

规则记住了就不会踩：**未选中的素材连同它的下游一起被跳过**；一段都不放行时该节点会拒绝运行；
上游选区变了导致原来的勾选失效时，界面会标出「已失效段」。

### 5.3 选提示词

「AI 加工」节点先在下拉里选一个提示词。下拉**按系列分组**：组标题是你要什么（「观点提炼」），组里是拿到什么
（详尽版 / 成文版 / 速览版……）；单成员系列不分组，直接一项。选完收起时，触发器上会补出系列名
（「观点提炼 · 成文版」）。说明三点：

- 标了**配方**的提示词是「节点内多步链」（比如观点提炼的成文版、信息溯源的上网查证），
  质量通常更好但**调用次数更多、更贵也更慢**；
- 同类内容常有**详版与速读版**两个提示词，产物不同、不要混用：「观点提炼」走"信息不缩水"，
  适合要逐条核对与引用的深度笔记；「观点速读」走"全篇硬上限 800 字"（单次调用、成本最低），
  适合只想一屏读完就做判断的场景——它的"原稿没有回答"一栏会告诉你还缺什么；
- 想写自己的提示词，去设置 → 提示词库新增自定义提示词，然后在节点里选它。

「AI 校对」节点没有这个下拉——它固定用内置的校对指令。

### 5.4 按标签归类：词库与全库重打标

> 第一次用先看 [tagging.md](./tagging.md)——那篇是照着做一遍的上手教程（怎么建词库、怎么看合集、什么时候要重跑）。
> 这一节只交代设置项。

设置 → Obsidian 组里有两块，管的是**笔记的关键词**：

- **标签词库**：一棵两级的树，一级是分类（如 `领域`）、二级是具体标签（如 `AI`）。笔记上只写二级（`领域/AI`）——
  Obsidian 里按一级筛选会自动带上它下面所有二级，所以两级不必都写。**标签不能含空格**（Obsidian 的硬限制），
  填了空格保存时会自动换成 `-`。
- **允许 AI 新增二级标签**（默认关）：关着时模型只能从词库里挑，笔记之间的分类口径不会被模型自己长出来的写法冲散；
  开着时它可以补二级，补进去的会写回词库并在运行日志里留一行。**一级结构始终由你定**。

**全库重打标**（同一组的下方）：给整个库（含你手写的笔记）重新归类。它是两步走的——

1. 点**「预估」**：这一步完全不调模型，只告诉你这一轮要动多少篇（全量判定 / 仅判新标签 / 只清理过期标签 / 无需处理）
   以及大约几次模型调用。**看了数再决定是否发车。**
2. 点**「开始重打标」**：跑起来有进度，结束后给一份报告（写入几篇、实际调用几次、输入多少 token、其中多少命中缓存）。

几条要提前知道的：

- **它只改词库里的标签**。你自己写的标签（不在词库里）一律不碰；只有「从词库里删掉的标签」才会被从笔记里清掉。
- **front matter 读不出结构的文件会被跳过并列出**，内容原样保留，不会被"顺手修复"。
- **默认不做字面筛选之外的语义匹配**：只有正文里出现过标签名的笔记才会被送去判定，这是省钱的主要来源；
  代价是换个说法的笔记会漏（标签叫「平台经济」而笔记只写「抽成」）。补法是打开**「深度重扫」**，它不做字面筛选、
  全库语义匹配，但明显更贵。
- **没变的笔记不花钱**：内容与词库都没动过时，重跑一遍是 0 次调用。所以你随时可以点「预估」看有没有活要干。
- 词库或库路径有未保存改动时按钮会禁用，并提示先「保存设置」——服务端读的是已保存的值。

### 5.5 让旧笔记互相链接：回补相关笔记

「Obsidian 笔记」节点保存时会给新笔记算一段 `## 相关笔记`（文末的 `[[链接]]`），依据是设置页里
**「抽取哪些属性」**那组字段——同一字段的值相同算强相关。这件事只在保存那一刻做一次，
所以在它之前保存的笔记、或者你改了属性字段之后，已经存在的笔记不会自己跟上。

设置 → Obsidian 组里、**开关正下方**那一块干的就是这件事，和全库重打标一样是两步走：

1. 点**「先看要动多少（不花钱）」**：列出全库多少篇、要改多少篇、会写出多少条链接，以及样例里每篇是怎么变的
   （新增 / 更新 / 清掉）。
2. 点**「回补相关笔记」**：原地改写库里的笔记，跑完给一份报告（写入几篇、多少条链接、有没有失败的）。

它和全库重打标的区别只有一点，但很关键——**它不调模型**。判定是纯本地的词法比对，没有"几次调用""多少 token"
这些账，也不花一分钱。由此带来几条要知道的：

- **它只能利用已经抽好的属性**。在本功能之前保存、或当时没开抽取的笔记，front matter 里没有那些字段 →
  没有可比的依据 → 补不出链接（这些篇数会记在「没有属性」里）。想让它们也连上，得先对它们重跑一次属性抽取，
  那是花钱的，这一步不做。
- **它只写"真的会变"的篇**：一模一样的笔记一个字节都不动（不制造无意义的 mtime 抖动与同步风暴），所以随时可以点。
- **它只认自己写的那一段**：`## 相关笔记` 是标题 + 一串 `- [[链接]]` 且延伸到文件末尾，才算它的；
  你自己在正文中间写的同名小标题不会被删掉。归属同一个字段口径变化时，旧链接会被重算或清掉。
- **只支持本地库**：坚果云直连模式下这一步不适用。
- 抽取字段、开关、每篇最多几篇，任一项没保存时按钮会禁用——服务端读的是已保存的值。

**耗时（实测）**：判定是"每篇和全库比一遍"，随篇数平方增长、随正文长度近似线性增长。下面是本机
（Windows / Node 22 / 本地盘 / 脚本生成的合成库）跑出来的：

| 库规模 | 单篇正文 | 跑一遍耗时 |
| --- | --- | --- |
| 200 篇 | 约 1 KB | 约 0.13 s |
| 500 篇 | 约 1 KB | 约 0.54 s |
| 1000 篇 | 约 1 KB | 约 1.8 s |
| 2000 篇 | 约 1 KB | 约 6.8 s |
| 1000 篇 | 约 4.5 KB | 约 4.3 s |
| 2000 篇 | 约 4.5 KB | 约 18.9 s |

「先看要动多少」与「回补」各自算一遍，两步都点就是两份这个时间。**这是本机实测、非估算**，
换机器换盘会变；两三千篇、正文又长时一次要十几秒是正常的，界面上有进度。

## 6. 运行结束后看什么

结果页顶部是「运行结果 #编号」+ 状态 + 耗时，右侧是停止/强制结束（运行中才有）、查看日志、复制、下载 Markdown。
下面最多五个标签页，除「结果」与「节点流水」外都按产物出现：

- **结果**：左侧是「链路输入」面板，按加工阶段（原始素材 → 加工步骤 → 最终输入 → 输出文档）一行一个节点，
  行上是节点名与副标题——**副标题先给素材身份（视频标题或条目数、UP 主、时长）再给运行状态**，
  多个同类来源卡才分得清哪个是哪个。**从某个节点重跑（`scope=fromNode/node`）时，上游那些本次没跑的行
  会在标题右侧标一个「复用」**，表示这一份产物来自更早的运行；本次跑过且成功的行不带任何标记。
  中间是纸面阅读区，**没有别的列**。
  **正在阅读的那一份，它的分段大纲就挂在它自己那一行下面**（「全文（N 段合并）」+ 逐段标题与字数/时长，
  当前段左侧有墨色标记；段数超过 12 时顶部出现筛选框，行右侧有上一段/下一段的翻页）。
  换一份阅读时大纲跟着走，键盘 `↑↓`（或 `j k`）/ `Home` `End` 在大纲内切段。
  **面板收起时阅读区顶部会出现一行「‹ [分段下拉] ›」**，所以收起面板不影响切段——面板只负责展开细节。
  工具条上可以开合链路面板、缩放（75%–200%）、全屏，以及「对比输出」（把当前输入与输出做逐行对比）、
  「编辑文档」。**编辑只用于改一改再复制，不会保存到服务端。**
- **对照**：本次运行有两份以上产物时出现（并行分支的链路一定会有）。左右各选一份，从上到下三层：
  1. **AI 差异分析**：读两份内容后给出「一句话结论 / 只有左边讲到 / 只有右边讲到 / 两边说法不一致 /
     两边都讲到 / 各自更适合什么场景」。**会消耗一次模型调用**（点按钮才跑），结果按内容指纹缓存——
     同一对内容再打开直接读缓存，「重新分析」才重跑；可以「复制分析」把结论贴进笔记。
     单侧超过 1.6 万字时只送头尾，页面会写明哪一侧被截断。
  2. **指标对比**：字数、行数、段落、标题、列表项、表格行、引用、代码块，带差值（机械统计）。
  3. **逐行差异**（默认收起）：删/增行数与重合率写在标题上，展开才看红绿逐行 diff。
  默认比的是链路上最深的一组并行分支（如「AI 加工 A」对「AI 加工 B」）；多素材链路会按段展开，
  默认取同一条素材的两套加工。**结论是 AI 判断，可能不准；指标与逐行差异是机械统计，可作对照。**
- **节点流水**：每个节点的状态、耗时、**用量**、产物摘要或错误；有重试的会显示「重试 N 次」。
  用量列写的是这个节点本次（含重试）真花掉的 token / 音频时长，悬停看输入、输出与缓存命中的拆分。
  失败节点可以直接「重跑」——这会以该节点为起点新建一次运行。
- **练一练**：知识巩固节点的产物。一题一屏作答并判分（判分在本地做，不联网），
  结算后可以「只重做错题」「全部重来」「导出 Markdown」。
- **思维导图**：思维导图节点的产物，用 Markmap 渲染。

另外：运行中会实时刷新；日志浮层支持按节点/步骤/输入段/类型筛选与复制、下载；
运行**中断或失败**的节点，画布卡片底部状态条上会多一个「查看日志」文字链，点击**就地**打开日志浮层并定位到该节点——
中断现场（断在哪一步、当时进度、中间沉默了多久）就写在里面，不用先跳到结果页。
开了「保留可播放视频」的来源，可以在结果页直接播放，文件缺失时 B 站来源能一键重新下载。
结果页支持带参数的直达链接：`?focus=<节点 id>`、`?tab=mindmap|compare`、`?seg=<段号>`。

### 6.1 用量与估算金额

每次调外部接口都会记一笔账，三处能看到：

- **画布节点卡**：底部状态条上一个灰底徽标，写这个节点最近一次运行花掉的 token（转写节点写音频时长）。
  悬停看「调用几次 / 输入多少 / 其中命中缓存多少 / 输出多少 / 其中推理多少」。同一枚卡片上多处调用的会累加到一处。
- **结果页页头**：这一次运行的总用量，后面跟一个金额徽标。
- **结果页「节点流水」**：逐节点的用量列，用来看「这次贵在哪一步」。

**token 是实测，金额要么是账单、要么是估算，三种东西必须分开读。**

实测的部分：token 来自厂商响应的 `usage`（缓存命中的字段名各家不同，我们四种写法都认）；
音频时长优先用厂商报的（MiMo 的 `usage.seconds`、`verbose_json` 的 `duration`），它不报才由本应用从 WAV 头量。

金额有两种来源，界面用两个不同颜色的徽标区分：

- **绿色「账单」**——服务商在响应里**直接报了金额**（目前只有 OpenRouter 这类网关会报）。
  这是对方收的钱，不是我们算的。它的口径是 credits，官方没写明 credits 与美元的换算，所以这里只显示数字。
- **橙色「估算」**——按单价折算出来的。它跟着一行口径说明（按什么价算的），鼠标悬停能看全。

关于估算的几条：

- **没填单价就不显示金额**，界面只写 token——比显示一个按陌生价格算出来的数字实在。
- 单价要你自己填（设置页「AI 模型」的输入/输出/缓存命中单价、「语音识别」的每分钟单价），
  **单位是每百万 token**，与各家官网报价页一致。也可以点「从参考价目填入」：它从一份公开价目表里
  按模型名查一条填进输入框，**你确认后保存才生效**。为什么不直接拿那份表算账：聚合表的价不等于你付的价
  （OpenRouter 是转售价、DeepSeek 分峰谷、智谱与 Moonshot 分缓存 TTL 档）。
- **缓存命中价留 0 就是按输入价算**（不打折），这样估出来偏高而不是偏低。各家折扣不同
  （DeepSeek 约 0.1×、智谱官方写「通常为标准的 50%」），所以不预置倍率。
- **运行记录会存下当时的单价**，之后改设置页不会改写旧账——结果页会写明是「按这次运行时的单价」还是
  「按当前设置的单价」（升级前的旧运行没有快照，只能用后者）。
- 联网检索（智谱 / Tavily）按调用次数计费、不吃 token，所以那些节点上显示的是调用次数。
- 「对照」页的 AI 差异分析也会显示用量：**读缓存时写的是「缓存中那一次用了多少」**，它没有第二次花钱。

设置页「AI 模型」里还有一个**余额对账**：查一次账户余额，跟本地累计估算并排看，就知道我们估得准不准。
余额是**账户级**的粒度，没法分摊到某一次运行——它只能对账，不能当"每次运行的账单"。
有余额接口的是 DeepSeek、Moonshot、OpenRouter 三家；OpenAI / Anthropic 的账单接口要 Admin Key，智谱官方没有接口。

## 7. 工程与运行记录

- **工作台（左栏「工程」）**：文件夹树支持多级、拖拽排序、框选多选、批量移动/删除；
  工具栏是新建工程、新建文件夹、导入工程、刷新、排序方式（手动 / 按名称 / 按最近更新）。
  工程可以复制、导出为 `.scribe-flow.json`、移动到别的文件夹。
  **没有回收站**：删除是即时的（有确认框），文件夹被删时里面的工程会回到根层级而不是被一起删掉。
- **运行记录（左栏「运行记录」）**：按工程查看。每条运行**自带默认名**「第 N 次运行」
  （N 按该工程内的创建顺序；从某个节点重跑时带成「第 2 次运行 · 重跑「AI 校对」」），
  右键或详情页的「重命名」可以改成自己的说法；**把名字清空**这一行就只剩时间。
  右键一行还可以打开详情、打开工程画布、删除运行（运行中不可删，删除会连带清理产物与媒体引用）。
- **设置 → 数据与工程**：看数据目录、运行条数与输出文件数，也可以清理已结束的运行。

## 8. 备份、同步与迁移

- **数据库备份**：备份的是**数据库快照**（含媒体引用与元数据），**不含**视频文件、上传原件与输出文件。
  恢复是整库覆盖，且有保护：正在运行时直接拒绝；恢复前会**先把当前库自动备份一份到「备份目录」**（写不进去就中止，绝不裸覆盖）；
  恢复会校验备份完整性、补齐表结构、清掉残留的「运行中」状态。
  - **「备份目录」填什么，决定备份走哪条路**（没有额外的模式开关）：填**本地文件夹**（如 `D:\我的坚果云\ScribeFlow\backups`）
    → 备份写进坚果云同步文件夹，由客户端上传，**不需要账号密码**；填**云端路径**（以 `/` 开头）
    → 由本应用用 WebDAV 直连上传。设置页会显示当前识别成哪一种。
- **Obsidian 同步**：推送/拉取只处理 `.md`，遇到两边都有改动的文件时**跳过而不覆盖较新的那份**；
  跳过原因会列在「最近操作结果」里。
- **换机器后视频打不开**：这是正常的——媒体文件不在备份范围内。B 站来源可以在结果页一键重新下载，
  本地文件来源需要重新上传再重跑。
- 想连视频一起搬，按 [deploy.md](./deploy.md) 的「备份与迁移」整体拷贝数据目录。

## 9. 常见问题

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 点运行被拒绝：「未配置 AI 模型密钥 / 语音识别密钥」 | 运行前预检 | 去设置页填对应密钥 |
| 运行能启动，但中途某个节点报「未配置 AI 模型密钥」 | 章节切分 / 阴阳师攻略 / Obsidian 三个节点不在预检名单里 | 同上，填好后重跑该节点 |
| 「该工程已有运行正在进行」 | 同一工程只允许一个运行 | 在画布上点运行不会撞到它（运行中点击运行入口 = 加入排队）；只有**另一个标签页或另一台设备**起了运行时才会看到，等那边结束即可 |
| 「素材挑选没有选中任何素材」 | 该节点的输入全被排除 | 至少勾选一段素材 |
| 条件分支没走到的那一支显示「跳过」 | 这是设计行为：未命中的分支由边过滤掉 | 不用处理；要看细节去节点流水与日志 |
| B 站列表报 401 / 提示登录失效 | 扫码登录过期 | 点右上角 B 站头像重新扫码 |
| 结果页视频显示缺失、播不了 | 媒体文件不进坚果云备份 | B 站来源一键重新下载；本地文件重新上传后重跑 |
| 运行卡住、点停止没反应 | 正在进行的调用不响应取消检查点 | 用「更多操作 → 强制结束运行」，然后重跑 |
| 刷新页面后节点不再显示运行进度 | 运行态不写入工程图，靠运行记录恢复 | 重新进入工程会自动恢复订阅；仍不动就用运行记录里的状态判断 |
| 卡片上写着「服务重启，运行已中断」 | 服务进程被重启（常见：改了服务端代码触发 `node --watch` 重启、关掉了终端窗口）把正在跑的运行掐断了 | 点卡片状态条上的「查看日志」看中断现场；服务进程自己的退出/重启原因在 `apps/server/data/logs/service.log` |
| 密钥显示「已保存」，想清空 | 密钥留空＝不修改 | 直接填新值覆盖；要彻底清空需改数据库或从备份恢复 |
| 结果页改完文档，退出就没了 | 编辑不落库（只有复制） | 复制出去，或复制到编辑器里另存 |

## 10. 这套文档在哪看

产品内就有入口：左栏底部的**项目文档**按钮打开只读阅读器，左侧按目录分组（现状 / 决策 / 计划 / 证据 / 调研 / 样例），
右侧显示正文与元信息，相对链接可以在阅读器内跳转。它读的是仓库里的 `docs/` 目录——
如果用 Docker 部署且镜像里没有带 `docs/`，会提示「当前部署未包含文档目录」。

打开时会把全部正文一次性取回，所以**切换文档是即时的**（不再等网络）；本地打开通常快到看不见加载态，
只有真的要等（超过约 0.2 秒）才显示一个小的「正在读取…」。内容还没到时旧正文留在原位并整体变淡，
不会先空白再重排。

要判断「现在有什么、缺什么」看 status.md；要判断「某个节点怎么配置」看 [nodes.md](./nodes.md)；
要判断「代码怎么组织」看 [architecture.md](./architecture.md)。`docs/decisions/` 与 `docs/evidence/` 里的数字
是当时的历史快照，**不代表现状**。
