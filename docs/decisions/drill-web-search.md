# 练一练联网找同类题（联网检索渠道去专有化 + 配方步骤级检索）

> 状态：**已实施**
> 需求原话：「这个能不能不要只服务于溯源模块，比如我的练一练，这个模块最初的期望就是从网上找和知识点比较相关的练习题，他们其实就是可以共用的。现在同时修改我们的知识巩固模块和我们的这个设置项里的描述」
> 上游：知识巩固节点方案（练一练的功能定位）、[信息溯源联网核查](./trace-external-authority.md)（检索渠道与权威度分档）

---

## 0. 一句话

**检索渠道不再叫「外部溯源」：设置页改成「联网检索」，两个模块共用同一份渠道配置；练一练的出题步在落笔前先按知识点上网找同类练习题，但答案与原文依据仍只认原文。**

```
抽点 scan ──▶ 每个知识点带上 1-2 个检索词（queries）
                    │
                    ▼
        联网检索（复用溯源那条渠道）──▶ {{sources}} 注入
                    │
                    ▼
出题与延伸 author ──▶ 借鉴同类题的考察角度与干扰项；答案/引文仍逐字来自原文
                    │          参考了哪条资料 → item.externalRef
                    ▼
审题 audit ──▶ 断言门（引文逐字命中）──▶ 编译期按「本次真检索到的来源」校验 externalRef
```

---

## 1. 改之前是什么样（两条各走各的路）

| | 信息溯源 | 知识巩固（练一练） |
|---|---|---|
| 联网能力 | 有：`PromptBlock.externalCheck` 触发产出后的逐条核查 | **没有** |
| 设置页文案 | 「外部溯源」——写着「信息溯源模块**专用**的搜索服务密钥」 | 与检索零关系 |
| 出题依据 | — | 只有输入原文 + AI 三步配方 |

问题不在功能缺失，而在**能力被一种用法锁死了**：检索这件事被写成了「溯源核查」的同义词，
连设置页的分组名都在替用户做这个判断。练一练最初的设计意图（上网找和知识点相关的练习题）
因此一直没有落点。

---

## 2. 三个决策

### 2.1 检索渠道去专有化：改文案，不动配置键

设置页分组与标题由「外部溯源」改为「联网检索」，说明文字改成「所有需要上网查的模块共用这一份」，
并把两个消费方各自用它做什么写清楚（溯源 → 外部核查；练一练 → 找同类题）。

**配置键一个都没改**（`search.provider` / `search.apiKey` / `search.maxResults`），
所以已填过密钥的安装不需要重填、也不需要迁移——这次改动只涉及界面文案与消费方，不涉及数据。

`每个检索词最多返回结果数` 的口径也一并说清：它是「每个检索词取几条结果」的上限，两个模块都受它约束。

### 2.2 从「块级 externalCheck」抽出「步骤级 search」

溯源的联网是**产出之后逐条核查**（报告里每条待查信息 → 检索 → 判断有没有外部依据）。
练一练的联网是**落笔之前先找参考**（先看同类题怎么考 → 再出题）。
这两件事的时机、入参、产物都不同，硬塞进 `externalCheck` 会得到一个什么都像、什么都不像的实现。

所以新增的是**配方步骤级**声明（`packages/shared/src/recipe.ts`）：

```ts
search: { queriesFrom: "points[].queries[]", maxQueries: 4 }
```

| 决策 | 原因 |
|---|---|
| 声明在**步骤**上，不硬编码步骤 id | 与 `externalCheck` 同一路子：能力由模版自己声明，引擎不认识具体模版名 |
| 检索词取自上一步产物的**路径**（`points[].queries[]`） | 抽点步最清楚每个知识点该搜什么；路径求值复用断言门已有的 `collectFieldStrings` |
| 第 1 步不允许声明 `search` | 检索词来自「上一步产物」，第 1 步没有上一步。写错在 zod 校验期就报错，不必等运行时 |
| `maxQueries` 上限 6，练一练取 4 | **检索请求数就等于它**，是成本与耗时的闸门（见 §4） |
| 结果走独立的 `{{sources}}` 变量，不拼进 `{{input}}` | `input` 是引文回查的比对源。参考资料一旦混进去，「引文必须逐字来自原文」这条保证就废了 |

### 2.3 `{{sources}}` 里必须自带「不可信外部数据」声明

参考资料是公开网页内容，会进模型上下文——这正是提示词注入的入口。所以格式化函数
（`formatReferenceText`）自己带上三层声明：这是不可信外部数据、只用于参考出题角度、禁止当答案依据、
与原文冲突以原文为准。措辞本身是防线的一部分，不要为了简洁去掉。

同理，参考资料**不是**答案来源：题目答案与 `sourceQuote` 仍必须逐字来自原文，
`citationsInOriginal` 断言门一字未放宽。这条是练一练的产品前提（见上游方案 §2.2：
「必须挂原文依据」），联网只提高题目质量，不改变可信来源。

### 2.4 `externalRef` 只保留「本次真检索到过」的链接

出题时会借鉴网上同类题，产物里可以记一条 `externalRef`（标题 + 网址）。但**模型很擅长照着真资料编一个
看起来很像的网址**，而界面上带链接的引用天然显得可信——不校验就等于把幻觉包装成出处。

所以编译期（`buildDrill` → `verifyExternalRefs`）按本次检索到的来源核对，规则两条互补：

| 模型产物里的 `externalRef` | 判定 | 原因 |
|---|---|---|
| 带网址 | **网址必须命中**（忽略协议 / www / 末尾斜杠差异） | 「真标题 + 编造网址」在界面上依然是可点击的假出处，这正是要堵的洞 |
| 不带网址 | 标题必须命中（归一比对） | 智谱渠道相当一部分查询只给标题与正文（见 `traceExternal.ts` 的已知行为），只认网址会让这条通路名存实亡 |

> 这条规则是**被测试逼出来的**：第一版写成「网址或标题命中其一即可」，集成用例
> `drill-web-search.test.ts` 用「同一个真标题 + 只差一个域名的假网址」立刻把它打穿了。
> 所以判定的顺序不是风格问题，是「核对凭据到底以什么为准」的问题。

- 剥掉的条数**不计入题目丢弃数**：题目本身还是可用的，只是「参考自哪里」这句不可信。
- 宁可少留不可错留：模型复述标题时改了措辞（且没给网址），这条参考就会被剥掉。

## 3. 明确不做

| 不做 | 原因 |
|---|---|
| 把网上内容当作答案依据或原文依据 | 会直接推翻练一练的防幻觉设计（引文逐字命中）。联网只影响「怎么问」，不影响「答案是什么」 |
| 每个知识点各搜一轮（12 个点 = 12 次请求） | 请求数与时延随知识点数量线性增长；改为取前 4 个检索词（抽点步按重要性排序），够用且成本封顶 |
| 练一练**必须**联网才能跑 | 检索是增强。没配渠道、取不到检索词、检索失败都只记一条日志然后按「不联网」继续，产物照常产出 |
| 用评测集量化「联网后题目质量提升多少」 | 本次没做（见诚实清单）；摘要里的「N 题参考了网上同类题」是唯一的可见指标 |
| 逐条题目标注「哪句来自网上」 | 答案必须来自原文，网上资料只影响出题角度，做不到也不该做逐句归因 |

---

## 4. 成本与耗时（本次的取舍依据）

| 项 | 值 | 来源 |
|---|---|---|
| 每次运行的检索请求数 | = `maxQueries` = **4**（练一练） | 常量声明；真机日志实测正好 4 条检索词（见 §5） |
| 每个检索词向上游索取的候选条数 | 20（`POOL_SIZE`，未改） | `traceExternal.ts` 既有常量 |
| 注入模型的参考资料条数 | ≤ `maxResults`（设置页，钳制 1-10） | 真机日志实测 10 条（本机设置为 10） |
| 每条参考资料注入的摘要长度 | ≤ 200 字符（`REFERENCE_SNIPPET_MAX`） | 本次新增常量 |
| 多花的 AI 调用次数 | **0** — 检索挂在已有的「出题」步上，不新增步骤 | 真机摘要实测仍是「配方 3 步 · 3 次调用」 |

## 5. 真机验证（本机设置：智谱渠道 + deepseek-flash，本文所有数字都在这一套配置下取得）

| 验的是什么 | 怎么验 | 结果 |
|---|---|---|
| 练一练整条链路 | `pnpm check:api:drill`（API 自检 21 项）× 3 次 | **3/3 通过**（改动前同一脚本 3/3 失败，见下） |
| 联网检索真的发生 | 运行日志 | `已联网检索参考资料：10 条（检索词：论证单元 切章 粒度、视频笔记 切分 方法、按字数切分 弊端、字数切分 上下文 不完整）`——正好 4 条，与 `maxQueries` 一致 |
| 参考资料进了出题提示词 | 读 `ai-request` 日志（step=author） | 含 `【联网检索到的同类参考资料】`，也含 externalRef 规则 |
| 参考链接落到产物里 | 连跑 3 次，统计 `items[].externalRef` | 旧措辞「没有借鉴就不要写」下 **0/2 次**出现；改成「借鉴了就标出处」后 **3/3 次**出现（分别 1 / 2 / 2 条），且全部是真实检索到的 URL（没有触发「剥掉不在检索结果里的参考链接」日志） |
| 链路没被改坏（溯源侧） | 真机跑一次 `builtin.trace.v2` | 3 步通过、0 次断言重问、外部联网核查照常执行 |

> **顺带修掉的两个既有缺陷**（不修就无法验收本功能，详见 CHANGELOG 的「修复」段）：
> ① 练一练的审题步拿不到知识点（出题步产物只有 items/extensions，审题步却要输出 points），
> 模型自造 `{id,name,summary}` 形状导致 `sourceQuote` 全丢——**改动前 3/3 次失败，改动后 3/3 次通过**；
> ② `citationsInOriginal` 的路径把末尾 `[]` 加在字符串字段上（`points[].sourceQuote[]`），
> 收集到 0 条引用＝断言恒过，练一练与溯源 v2/v3 的这道门**一直是空转的**。

## 6. 诚实清单

**没验证的**

- **只测了一个题材、一个模型、一个渠道**：输入是一段「视频切章」的短文稿，模型是 deepseek-flash，渠道是智谱。
  换题材（尤其冷门主题）、换模型（尤其是弱模型）、换 Tavily 渠道时，检索词质量与 externalRef 覆盖率都可能不同——
  §5 的「3/3 次出现参考链接」只对这套配置成立。
- **没有量化题目质量提升**。没有评测集，也没有联网 vs 不联网的人工抽检对比。`externalRef` 的条数说明「资料被用上了」，
  不等于「题目更好了」。
- **未测时延**：4 条检索是串行的（`collectSources` 内顺序请求），实测的每次运行都在 1 分钟内完成（自检的
  `waitRun` 循环没超时），但没有单独测「联网这一步花了多少秒」。

**已知局限**

- 参考资料只覆盖**前 4 个检索词**对应的知识点（抽点步按重要性排序）。真机这次抽了 5 个知识点，
  第 5 个（命中率/覆盖率）大概率没有被检索词覆盖到。
- 提示词里没有告诉模型「资料只覆盖了部分知识点」，模型只知道「上方有参考资料」。
- `externalRef` 未给网址时靠标题比对兜底，模型把标题改写得比较多时会误剥（宁可少留不可错留）。
- `queriesFrom` 是单一路径：模型若整批漏写 `queries`，本次就完全按不联网走（只记一条日志，不报错）。
- 参考资料与具体题目的对应关系是**隐式**的：模型看到的是一个混合候选池，不是「知识点 p1 对应这几条」的分组，
  所以「某题借鉴了某条资料」依赖模型自己判断，本次不做强制。
- 「借鉴了就标出处」这条措辞是**逼出来的**：第一版写成「没有借鉴就不要写」，真机 2 次都没有任何题目带参考标记，
  摘要里那行「N 题参考了网上同类题」自然也不出现——功能做了但看不见。改成默认期望「借鉴就标」后才有 3/3。
  这类提示词措辞对结果的影响，只能靠实跑发现。

**简化**

- 参考资料注入用的是 `collectSources` 的既有语义（多检索词合并成一个池子再按权威度取前 N 条），
  因此**丢掉了「哪条来自哪个检索词」的对应关系**。代价是模型看不到分组，收益是零新增网络逻辑、直接复用已测代码。
