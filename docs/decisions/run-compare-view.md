# 对照视图：差异在结果页看，不在链路里拼

> 现状以源码为准：指标与 diff 计算在 `packages/shared/src/compare.ts`，
> 视图在 `apps/web/src/components/CompareView.vue`，可选项与默认配对在
> `apps/web/src/utils/run-compare.ts`，接入点在 `apps/web/src/views/RunDetailView.vue` 的「对照」标签页。

## 1. 起因

「多路对照」链路原本是：来源 → 转写 → 校对 → **AI 加工 A / AI 加工 B** → **合并**。
用户在一次真实运行里指出问题：**运行详情本来就把两个分支并排列在「链路输入」里，合并这一步只是把两份内容首尾相接，
反而看不出差异**（那次运行里 A 是 9904 字、47 行表格，B 是 6468 字、0 行表格，拼在一起谁也看不出这个差别）。

判断成立：合并节点解决的是「多份素材合成一篇」（合集综述、分章笔记确实需要），
不是「同一素材的两套加工对照」——这是两种不同的需求，之前用同一个节点对付了。

## 2. 决定

1. **「多路对照」链路去掉末端的「合并」节点**（模板改动只影响新建工程；合并节点本身保留，供合集综述 / 分章笔记使用）。
   两条分支各自成为末端，运行收尾会各落一份文件，不再有拼接产物。
2. **结果页新增「对照」标签页**：本次运行有两份以上可比产物时出现，左右各选一份，直接看差异。
   内容三层（从上到下）：
   - **AI 差异分析**（主角）：让模型读两份内容，给出「一句话结论 / 只有左边讲到 / 只有右边讲到 /
     两边说法不一致 / 两边都讲到 / 各自更适合什么场景」，可复制为 Markdown、可「重新分析」；
   - **指标对比**：字数（不含空白）、行数、段落、标题、列表项、表格行、引用、代码块，带差值；
   - **逐行差异**（默认折叠）：公共行 / 仅左 / 仅右 / 重合率 + 字符级高亮的 diff（复用 `DiffViewer`），
     折叠标题上就写着「删 X 行 · 增 Y 行 · 重合率 Z%」。
3. **默认配对＝链路上最深的一组并行分支**（如「AI 加工 A」对「AI 加工 B」）；多素材链路按段展开，
   默认取同一条素材的两套加工（加工 A 第 1 段 vs 加工 B 第 1 段），而不是同一个节点的两段互比。
4. **这是视图，不是节点**。对照不产生新产物、不写盘、不进流水线；
   AI 判读是**阅读时按需点一次**的动作（`POST /api/compare`），不是每个运行都要付的成本。
   依据是本仓自己拍过的判据（[node-vs-prompt-block-boundary](../research/node-vs-prompt-block-boundary.md)）——
   卡片是工序，要接料出料、料会变形；对照只是同一批料换一种看法。

## 2.1 为什么 AI 判读是必须的，而不是锦上添花

第一版只做了机械统计（指标 + 行级 diff），在真实数据上直接暴露了问题：那条真实运行的两份产物
**重叠率只有 11%**，界面上看就是一大片红绿——两份内容主干其实一致，只是措辞与排版不同，
逐行比较把它们全判成了「差异」。噪声淹没了结论。

于是把层次反过来：**结论交给模型，机械统计退到旁证位置**。实测有效——同一条运行，AI 给出的是
「内容主干一致，A 多出事实数据表、论证脉络、金句摘录、情绪基调与行动清单，B 更短，以密集原文引语呈现同一批观点」，
并逐条列出 7 项「只在 A 有」、5 项「只在 B 有」、6 项共同覆盖，以及两侧各自适合的场景。

## 2.2 成本与缓存

- 一次判读＝一次模型调用（实测 12.1 秒 / 两侧约 1.7 万字），所以：**按钮上写明会消耗一次调用**；
- 结果按**内容指纹**（模型 + 两侧标签与正文的 sha256）存进 `compare_reports` 表：
  同一对内容再打开直接读缓存（实测第二次请求 `cached: true`，不再调模型）；
  内容变了自然落到新键上，换模型也要重判；
- 「重新分析」忽略缓存并覆盖同一键的旧结论（键相同，不新增行）；
- 单侧超过 16,000 字时只送头 60% + 尾 40%，中间插「【…此处省略约 N 字…】」标记，
  并在提示词里要求「省略处的差异不许猜」，截断事实由服务端随结果返回（不信模型自述）。

## 3. 边界（先写清楚，免得被当成没用）

- **AI 判读可能有误**：界面上常驻一句「AI 判读，可能不准；下面的指标与逐行差异是机械统计，可作对照」。
  它是判断辅助，不是验收结论。
- **指标是机械统计，不是语义相似度**。两份内容全同但换一套措辞，重合率会很低。UI 上这句话是写死的提示。
- **超过 800 行不做逐行对比**（`DIFF_MAX_LINES`）：只给指标与 AI 判读，并明说「不做逐行对比」。
- **结构化产物不进对照列表**：练一练的练习集、溯源报告都是 JSON，逐行比只有字段噪音（判定在
  `apps/web/src/utils/run-output.ts`，与结果页的阅读器分派共用一份）。
- **不做三方以上同屏对照**：目前是左右两份 + 可切换/交换。
- **不做「谁更好」的打分**：提示词里明确要求「不评好坏、不打分」，只写「各自适合什么场景」，把判断留给用户。

## 5. 怎么验证

- `packages/shared/src/compare.test.ts`：指标逐项（标题/列表/表格/引用/围栏）、行级 diff、重合率边界
  （相同 = 100%、完全不重叠 = 0、两侧都空 = 100%）、超长返回 null。
- `packages/shared/src/compare.analysis.test.ts`：判读结果解析（裸 JSON / ```json 围栏 / 缺字段补空数组 /
  三种失败文案）、Markdown 导出（标签进小标题、空区块不出现）、截断（头 60% + 尾 40% = 上限、标记写明字数）。
- `apps/web/src/utils/run-compare.test.ts`：结构化产物被排除、多素材按段展开、默认配对取相邻同类型节点。
- `apps/server/src/routes/compare.test.ts`（路由级，本地 mock 模型端点）：正常返回、**同一对内容再请求命中缓存
  且不再调模型**、内容变了落新键、`refresh` 覆盖同键、模型返回垃圾时 502 且不写缓存、两侧相同直接拒绝、
  缺密钥给可执行提示、请求体不合法 400、`/ready` 不调模型。
- `pnpm smoke:ui`：结果页出现「对照」标签、渲染出指标表与重合率，且 **AI 分析入口是真实 Element Plus 按钮**
  （漏 import 组件时 `<el-button>` 会被当成未知元素渲染成「有文字、没样式、点了没反应」，肉眼看不出来）。
- 本轮实机核对（2026-09-29）：在用户那条真实运行上真跑了一次判读（12.1 秒、`cached: false`），
  随后从界面再点一次「分析差异」读到 `deepseek-flash · 读取缓存`，页面结构与截图见 [CHANGELOG](../../CHANGELOG.md) 同日条目。
