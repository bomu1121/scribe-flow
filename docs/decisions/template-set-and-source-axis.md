# 内置链路：改成「加工路径 × 来源」

> 调研过程与本机数据证据在 [research/template-set-research.md](../research/template-set-research.md)。
> **现状以源码为准**：链路清单与构建逻辑在 `packages/shared/src/templates.ts`，提示词正文在
> `packages/shared/src/prompt.ts`。本文记的是拍板理由与取舍边界。

## 1. 决定

**模板不再按来源成对铺开，只描述「加工路径的形状」；来源在新建工程时选。**

- 模板 = 三选一的来源（B站链接 / 本地文件 / 粘贴文稿）+ 从文稿开始的加工链。
- 构建时按来源补齐节点：`source.bili` / `source.file` → `process.transcribe` → 加工链；`source.text` 本身就是文稿。
- 因此同一个「思维导图」链路，从视频走也是它、从粘贴文稿走也是它，不再需要两条。

理由（详见调研 §1.1）：11 个旧模板里有 6 个从未被任何工程使用，全部是「同形状换个来源」；
而用户真正要换来源时，是在画布上自己改来源节点的，不是回模板列表里找另一条。

## 2. 链路清单

| # | 链路 | 形状（B站/本地来源） | 分组 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 单线笔记 | 来源 → 转写 → 校对 → AI 加工 | 通用 | 默认链路，快捷新建的默认值 |
| 2 | 多路对照 | 来源 → 转写 → 校对 → 加工 ×2 → 合并 | 通用 | 对照两个提示词块或两个模型 |
| 3 | 思维导图 | 来源 → 转写 → 校对 → 思维导图 | 通用 | |
| 4 | Obsidian 笔记 | 来源 → 转写 → 校对 → 加工 → Obsidian | 通用 | |
| 5 | 分章笔记 | 来源 → 转写 → 校对 → 章节切分 → 合并 | 通用 | **新增**：章节切分首次进模板 |
| 6 | 系列综述 | 来源 → 转写 → 校对 → 加工 → 合并 | 通用 | **新增**：多素材各出一份笔记再合成一篇 |
| 7 | 选段加工 | 来源 → 转写 → 素材挑选 → 校对 → 加工 | 通用 | **新增**：只对 B站/本地来源可用 |
| 8 | 阴阳师攻略 | 来源 → 转写 → 校对 → 攻略加工（核对版） | 垂直 | |
| 9 | 练一练 | 来源 → 转写 → 校对 → 加工 → 知识巩固 | 垂直 | |

旧 → 新对照：

| 旧模板 | 现在怎么来 |
| --- | --- |
| 视频转笔记（单线）/ 文稿转笔记 | 「单线笔记」+ 选来源 |
| 视频多路笔记 / 文稿多路对照 | 「多路对照」+ 选来源（分支从 2/3 条统一成 2 条） |
| 视频转思维导图 / 文稿转思维导图 | 「思维导图」+ 选来源 |
| 视频/文稿转 Obsidian 笔记 | 「Obsidian 笔记」+ 选来源 |
| 文稿/视频转阴阳师攻略笔记（核对版） | 「阴阳师攻略」+ 选来源 |
| 视频转练一练 | 「练一练」+ 选来源（现在文稿来源也能用） |
| —— | 「分章笔记」「系列综述」「选段加工」为新增 |

被删掉的不是能力，是**重复的入口**：选择从 11 项降到 9 项，且每一项都覆盖三种来源。

## 3. 新增链路为什么是这三条

1. **系列综述**：本机有一个工程 53 次运行 0 成功，52 次失败在同一条文案「没有可转写的音频输入」——
   用户想「两个视频 → 各自加工 → 一份笔记」，却把两个来源节点和两个转写节点丢在画布上没连线。
   同类工作流（n8n 热门模板）也是批量多素材再汇总的形状。合并节点一直存在，但没有任何模板示范过。
2. **分章笔记**：章节切分节点在 114 次运行里只出现过 1 次，且从没进过模板；长讲座/长视频先切章再读是通用需求。
3. **选段加工**：多分P 合集里只加工其中几集是 B 站场景的常态；素材挑选节点同样从没进过模板。
   该链路的挑选必须落在**转写之后**（挑选节点的输入不接受音频），这一点在卡片的挑选界面上会写着。

## 4. 新增的两个产出块

同类产品的标配产出里，我们唯一空缺的两类是「待办/行动项」与「外语内容中文化」：

| 块 | id | 补的是什么 |
| --- | --- | --- |
| 行动项清单 | `builtin.action` | 结论与决定、待办、待确认、时间点；字段只写原文真的有的，建议与已决定分开 |
| 外语内容转中文 | `builtin.translate` | 英文等外语转写稿 → 中文结构化笔记；专名与数字保原样，附术语对照表 |

两者都是「单线笔记」链路里的一个提示词块选项，不新增节点类型。

## 5. 明确没做的（含理由）

1. **不加新节点卡片**。调研的结论是缺口在链路形状而不是节点数量：同类产品的标配产出（章节、导图、题目、
   待办、术语）里，前三个已有节点，后两个是提示词层的事。节点总表已经是 16 种，再加会把「选哪个节点」
   这件事变得更难。
2. **不做「带时间戳的章节」**。通义听悟/飞书妙记都有，但前提是 ASR 给时间戳；
   本项目的 ASR 客户端只取纯文本（`apps/server/src/lib/ai.ts` 的 `transcribeAudio`），
   要先改转写产物格式与结果页，属另一个议题。
3. **不给「条件分支」做模板**。`flow.if` 在 114 次运行里出现 0 次，但它是**节点能力**而不是工作流需求：
   「长稿分章、短稿直出」这类形状给一条模板等于替用户预设阈值。先让分章链路本身可被看见。
4. **不在新建工程对话框里选提示词块**。仍然是「模板给形状、块在画布上选」；
   要开箱即用就用快捷新建（粘贴链接建工程）那条路，那里一直可以选块。
5. **不做孤立节点告警**。53 连败的直接原因是画布上两个节点没连线，但画布交互不在本次范围；
   它已记进调研文档，供后续独立处理。

## 7. 怎么验证

- `packages/shared/src/templates.test.ts`：模板 × 来源的完整矩阵——建图合法性、**每条连线两端端口相容**、
  连通性、同排不重叠、未知模板/不支持来源返回 null、实例不污染模板常量。端口那条是这次新增的硬门：
  以前模板的端口写错只有用户连不上时才会发现。
- `pnpm smoke:ui`：新建工程对话框的来源单选（拍板时三个：B站链接 / 本地文件 / 粘贴文稿；后加的
  「B站收藏」是同一个 B 站来源的挑视频入口，排在 B站链接之后）、分组标题，以及「切到粘贴文稿后选段加工消失」。
- 本轮实测：`pnpm test` 403 项通过；`pnpm smoke:ui` **61/61 项通过**（含新增的两条来源轴断言）。
  另外对真实后端做了一次端到端核对：临时建 8 个工程确认同一链路换来源后的实际节点顺序，
  并确认不支持的来源组合退回空图，跑完即删、库内残留 0。细节记在 [CHANGELOG.md](../../CHANGELOG.md) 同日条目。
- 视觉复核发现并改掉两处：链路描述写死了「转写」（粘贴文稿时是错的，步骤改由按来源展开的小字承担）；
  9 条链路会把对话框顶出屏幕（列表改成自带滚动的 `max-height`）。
