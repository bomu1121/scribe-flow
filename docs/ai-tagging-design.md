# ScribeFlow Obsidian 笔记 AI 打标签设计

> 状态：调研完成，方案待评审
> 背景：Obsidian 笔记节点目前只生成 1 个默认标签，用户希望自动生成 5~10 个可用于知识库整理的标签。
> 结论：不应让 AI 自由生成标签，应采用「基础标签规则 + 受控标签体系 + AI 补全」的混合方案。

---

## 1. 问题

当前 Obsidian 输出节点写入 frontmatter 时：

- 标签来自节点 `data.tags`，通常只有 1 个（如“视频笔记”）
- 如果标签不足 5 个，会临时调用 AI 自由生成 5~10 个
- 自由生成会导致：标签碎片化、同义反复、不可控，无法长期用于知识库整理

目标：

1. 每个 Obsidian 笔记自动获得 5~10 个标签
2. 标签覆盖多个维度：来源 / 类型 / 领域 / 概念 / 状态
3. 标签尽量来自用户已有的标签体系，避免污染知识库
4. 用户人工修正后，可回填优化后续打标

---

## 2. 主流方案调研结论

| 方案 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| 关键词抽取（TF-IDF / KeyBERT / RAKE） | 快、便宜、可解释 | 抽不出语义/领域标签 | 预筛词 |
| LLM 自由生成 | 语义理解强 | 标签失控、碎片化 | 不适合直接用于长期知识库 |
| LLM + 受控词表 | 语义强且稳定 | 需要维护词表 | **推荐** |
| 向量/Embedding 分类 | 与已有标签风格一致 | 冷启动难 | 已有大量人工标签后补充 |
| 用户反馈闭环 | 越用越准 | 需要收集修正 | 长期演进 |

结论：采用「基础标签规则 + 受控标签体系 + AI 从词表选择 + 少量新增」方案。

---

## 3. 标签体系设计

### 3.1 标签维度

每篇 Obsidian 笔记建议从以下维度生成标签：

| 维度 | 示例 | 生成方式 |
|---|---|---|
| 来源类型 | `来源/B站`、`来源/文稿`、`来源/本地视频` | 规则自动 |
| 内容类型 | `类型/视频笔记`、`类型/学习笔记` | 规则自动 |
| 领域/主题 | `领域/历史`、`领域/AI`、`领域/效率` | AI 从词表选 |
| 关键概念 | `Obsidian`、`PARA`、`双链`、`RAG` | AI 从词表选/少量新增 |
| 状态 | `状态/未整理`、`状态/已整理` | 规则默认 |

### 3.2 默认标签词表

系统内置一份初始词表，用户可在设置中编辑：

```json
{
  "来源": ["B站", "文稿", "本地视频", "网页", "播客"],
  "类型": ["视频笔记", "学习笔记", "思维导图", "会议纪要"],
  "领域": ["历史", "AI", "编程", "效率", "心理", "知识管理"],
  "概念": ["Obsidian", "PARA", "Zettelkasten", "RAG", "双链", "Templater", "Dataview"],
  "状态": ["未整理", "已整理"]
}
```

### 3.3 标签规范

- 使用层级标签：`领域/历史`、`类型/视频笔记`
- 单篇 5~10 个，不超过 10 个
- 优先从词表选择，AI 最多新增 2~3 个“建议标签”
- 新增标签需要经过简单清洗：去空格、小写化、去重

## 4. 功能设计

### 4.1 设置页：Obsidian 分组新增“标签体系”

- 展示当前受控标签词表
- 支持按维度编辑（来源/类型/领域/概念/状态）
- 提供「从 Obsidian 库读取已有标签」按钮
  - 读取库内 `.md` 文件中的 frontmatter `tags`，合并进词表
- 提供「重置默认词表」

### 4.2 Obsidian 输出节点：不再需要手动填标签

- 移除节点卡片上的标签输入（当前已移除）
- 节点运行流程：
  1. 规则生成基础标签：来源、类型、状态
  2. 若基础标签数量不足 5 个，调用 AI
  3. AI 拿到：正文片段 + 已有基础标签 + 受控词表
  4. AI 输出 JSON 数组：先选词表标签，必要时补少量新标签
  5. 服务端清洗、去重、限制 10 个后写入 frontmatter

### 4.3 AI 提示词模板（草案）

```text
你是知识库打标助手。

请为下面的笔记生成 Obsidian 标签。

要求：
1. 优先从“可用标签”中选择；
2. 如果内容确实需要，最多新增 2~3 个标签；
3. 最终输出 5~10 个标签；
4. 不要解释，只输出 JSON 数组；
5. 标签不能包含空格。

可用标签：
{{tagTaxonomy}}

已有基础标签：
{{baseTags}}

笔记标题：
{{title}}

笔记正文：
{{content}}
```

### 4.4 数据模型

设置项 `app_settings` 新增：

| key | 值 |
|---|---|
| `obsidian.tagTaxonomy` | JSON 字符串，维度 → 标签数组 |
| `obsidian.autoTagEnabled` | `true` / `false` |
| `obsidian.tagMinCount` | 默认 5 |
| `obsidian.tagMaxCount` | 默认 10 |

可选：新增表 `obsidian_tag_feedback` 记录人工修正，用于后续词表学习（本期可不做）。

- `engine.ts` 的 `process.obsidian` 改为走受控打标流程

### 5.3 打标流程实现位置

在 `engine.ts` 内新增：

```ts
private async buildObsidianTags(input: {
  text: string;
  source: string;
  noteType: string;
  explicitTags: string[];
}): Promise<string[]>
```

内部流程：

1. `baseTags = 规则标签`
2. 合并 `explicitTags`
3. 若数量 < min，且 AI key 存在，调用 `chatCompletion`
4. 解析 JSON 数组
5. 优先保留词表中的标签；再保留基础标签；新增标签最多 2~3 个
6. 去重、清洗、截断到 max

## 7. 验收标准

1. 设置页可维护标签词表
2. 可从 Obsidian 库读取已有标签并入词表
3. 运行 Obsidian 笔记节点后，frontmatter 内 tags 为 5~10 个
4. 标签大多来自词表，AI 新增不超过 2~3 个
5. 无 AI key 时降级为基础标签，不报错
6. 标签去重、无空格、层级命名可正常显示
7. 全仓 `pnpm typecheck` 通过

## 8. 自动关联 / 回链设计

目标：当 ScribeFlow 写入一篇新 Obsidian 笔记时，自动发现它与库内已有笔记的相关性，并写入内部链接，让知识库图谱自动生长。

典型场景：

- 今天导入一篇“文天祥生平”
- 下周导入一篇“文天祥诗词”
- 第二篇处理时自动在底部生成：
  ```markdown
  ## 相关笔记
  - [[文天祥生平]]
  ```
- 可选：回写到第一篇，加入：
  ```markdown
  - [[文天祥诗词]]
  ```

### 8.1 触发时机

- 集成在 `process.obsidian` 节点运行流程中
- 写完当前笔记后执行“关联扫描”，不额外增加用户操作

### 8.2 关联依据

| 依据 | 示例 | 来源 |
|---|---|---|
| 共享标签 | `人物/文天祥` | 受控词表 + AI 打标 |
| 核心概念/人物 | “文天祥”“抗元”“过零丁洋” | AI 打标时同时抽取实体 |
| 标题/正文关键词 | 两篇都出现“文天祥” | 本地扫描 |
| AI 相关性判断 | 可选，给两篇笔记让 AI 判断是否相关 | 精确但成本高 |

### 8.3 流程

1. 当前笔记生成完成，获得 `tags` 和核心概念
2. 扫描 vault 内其它 `.md` 文件
3. 对每篇候选笔记计算相关度：
   - 共享标签命中 → 高相关
   - 标题/关键词命中 → 中相关
   - AI 判断 → 可选精排
4. 取 Top N（默认 5）写入新笔记：
   ```markdown
   ## 相关笔记
   - [[已有笔记名]]
   ```
5. 可选：反向回写旧笔记，形成双向链接
   - 默认先做“单向新→旧”，避免批量改动旧文件
   - 设置里提供“双向回链”开关

### 8.4 防误链

- 只对已处理过的知识库笔记做关联，不扫描模板/附件
- 共享标签必须达到阈值（如 ≥1 个受控标签）
- 新笔记和旧笔记标题完全相同/自己除外
- AI 判断结果只作为精排，不单独决定是否链接
- 每篇笔记相关链接数量限制，避免“链接轰炸”

### 8.5 数据与设置

- `app_settings` 增加：
  - `obsidian.autoLinkEnabled`：默认 true
  - `obsidian.autoLinkMax`：默认 5
  - `obsidian.autoLinkBidirectional`：默认 false
- 可选记录 `obsidian_link_log`，便于排查为什么没连/连错
