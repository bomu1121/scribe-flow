# 先看这个：这是「溯源报告导出到 Obsidian」的排版候选库

这六份笔记是**同一次真实运行的溯源报告**（中美社保那条，27 条主张、38 条来源、17 段原文引证），
**内容一字不差，只有排版不同**，用来在 Obsidian 里直接比对。

背景、依据、取舍与实测高度写在仓库的 [`docs/research/trace-export-research.md`](../../docs/research/trace-export-research.md) 里。

## 怎么打开

Obsidian → 左下角「打开其他库」→「打开文件夹作为库」→ 选这个文件夹。
它是个独立的小库，不会碰你真实的库；Obsidian 会在这里建一个 `.obsidian/`（已被 git 忽略）。

## 六份文件

| 文件 | 是什么 |
| --- | --- |
| `0-现状基线.md` | **现在的导出结果**（就是你觉得丑的那份），拿它当对照 |
| `A-主张即标题（详情折叠）.md` | 每条主张升成 `###` 标题（可被 `[[#主张]]` 指向），核查结论与原文依据各自折进一个 callout |
| `B-按核查状态分组（问题优先）.md` | **推荐**：在 A 之上按核查结论分四组（未找到出处 → 仅非权威 → 外部可印证 → 未联网核查），问题在最上面 |
| `C-语法用满（来源用脚注）.md` | 在 B 之上把语法用满：38 条来源收成文末脚注、关键数字 `==高亮==`。用来看「用满」的代价 |
| `D-只改样式（cssclasses）.md` | Markdown 与基线**逐字一致**，只多一行 `cssclasses`，靠 CSS 片段改观感 |
| `E-折叠索引（一条一个块）.md` | 极简版：一条一个折叠 callout、不用标题，整篇折叠态只有 3520px；**代价是没法链到某一条** |

## 建议的对比顺序

1. **`0` vs `B`**：看两处——开头那段速览（现状是「需要留意」13 条平均 242 字的长 bullet，
   B 是四行分组计数）；同一条主张（`0` 是 863px 的扁平 bullet 墙，`B` 默认只占 409px，
   点开 ~900px 看全部）。
2. **`A` vs `B`**：只有一处不同——A 保持原文顺序，B 按核查结论分组。判断「你翻这份报告时，
   是先找问题还是按顺序读」。
3. **`E`**：最短，但正文里没有任何标题，所以**别的笔记没法链接到「第 11 条」**。
4. **`C`**：脚注收来源在阅读视图里最干净，但来源要跳到底部才看得全。
5. **`D`**：先按下一节装好 CSS 片段；它证明「一行 front matter 不改内容」也能改善观感，
   但**一个字符都没省**（整篇高度与基线相同）。

## 方案 D 的 CSS 片段怎么装

1. 把 `snippets/scribeflow-trace.css` 拷进本库的 `.obsidian/snippets/`（没有这个目录就新建）。
2. 设置 → 外观 → CSS 片段 → 点「刷新」→ 打开 `scribeflow-trace` 这一项。
3. 只有 front matter 里写了 `cssclasses: [scribeflow-trace]` 的笔记会变（也就是 `D` 这一份）。

## 诚实清单

- 六份都是**从真实报告的 JSON 生成**的（`tools/build-candidates.mts`，内容一字未改），
  但**不是线上真实导出**：真要落地还要跑一次看分组名与条数。
- 折叠（`> [!x]-`）在**阅读视图**下默认是折起来的；**编辑视图**里看到的是源码（`> ` 前缀），
  那是编辑态本来的样子，不是排版问题。
- 库里的图标、颜色、行距取决于你的 Obsidian 版本与主题（默认主题、无插件）。
- 这里看到的是 Obsidian 自己的渲染，和我做对比页时的近似预览不是一回事；两边的差别写在调研文档的诚实清单里。
