# 先看这个：这是「笔记排版方案」的对比库

这 5 份笔记是同一条视频笔记（中美社保那条），**内容一模一样，只有排版不同**，用来在 Obsidian 里直接对比。
方案的来由、依据与取舍写在仓库的 `docs/research/obsidian-note-typography.md` 里。

## 怎么打开

Obsidian → 左下角「打开其他库」→「打开文件夹作为库」→ 选这个文件夹。
它是个独立的小库，不会碰你真实的库；Obsidian 会在这里建一个 `.obsidian/`（已被 git 忽略）。

## 五份文件

| 文件 | 是什么 |
| --- | --- |
| `0-现状基线.md` | 现在的导出结果（就是你觉得丑的那份），拿它当对照 |
| `A-纯Markdown骨架.md` | 不用任何 Obsidian 特有语法：删掉 `## 正文` 空壳、正文小节升到 `##`、`---` 分隔、速查按类别分组 |
| `B-Callout容器.md` | **推荐**：速览用 `> [!summary] 速览` 装起来、正文保持裸标题、速查用折叠的 `> [!example]- 速查` 并按类别分组 |
| `B2-真实产物（改版后真跑）.md` | 方案 B **真正落地后**用同一份样本文稿跑出来的产物（front matter 与 `# 标题` 由我按引擎的写法补上，正文一个字没改）。想确认「真实产物长什么样」看这一份，别只看手写的 demo |
| `C-Obsidian语法上限.md` | 在 B 上把语法用满：原话用 `> [!quote]`、关键数字 `==高亮==`、速查按类别拆成 6 个折叠 callout |
| `D-只改样式（cssclasses）.md` | Markdown 与基线**完全一致**，只多一行 `cssclasses: [scribeflow]`，靠 CSS 片段改观感 |

## 建议的对比顺序

1. **`0` vs `B` vs `B2`**：看三处——速览区有没有容器；正文里 `## 正文` 那个空壳标题还在不在；
   文末的「速查」是不是折成一行（点开看分组）。`B2` 是真实产物，形状可能与手写的 `B` 略有出入
   （组名、条目数每次运行都会变），以它为准判断「用起来顺不顺眼」。
2. **`D`**：先按下一节装好 CSS 片段，它证明"一行 frontmatter 不改内容"也能改善观感。
3. **`A` / `C`**：两端的选项。A 换到别的 Markdown 工具也长这样，C 只在 Obsidian 里最好看。

## 方案 D 的 CSS 片段怎么装

1. 把 `snippets/scribeflow.css` 拷进本库的 `.obsidian/snippets/`（没有这个目录就新建）。
2. 设置 → 外观 → CSS 片段 → 点「刷新」→ 打开 `scribeflow` 这一项的开关。
3. 只有 frontmatter 里写了 `cssclasses: [scribeflow]` 的笔记会变（也就是 `D` 这一份）。
